# 第 6 章 参数绑定与查询取值

## 本章目标

- 掌握三种占位符写法与五种 `sqlite3_bind_*` 函数的用法；
- 理解 `SQLITE_STATIC` 与 `SQLITE_TRANSIENT` 的区别，不再纠结该传哪个；
- 会用 `sqlite3_column_*` 取值，会用 `sqlite3_column_type` 处理动态类型与 NULL；
- 理解参数绑定为什么能防 SQL 注入。

本章是全书最实用的一章——生产代码里 90% 的数据库调用就是"绑定 + 取值"这两组函数的组合。

## 6.1 三种占位符

```sql
-- ① 匿名问号（本书默认）：下标从 1 开始，按出现顺序编号
INSERT INTO contacts(name, phone) VALUES(?, ?);

-- ② 带编号问号：显式编号，可复用同一参数
UPDATE contacts SET name = ?2 WHERE id = ?1;

-- ③ 命名参数：可读性最好，SQL 较长时推荐
INSERT INTO contacts(name, phone) VALUES(:name, :phone);
```

三种写法对应不同的绑定函数：

```c
sqlite3_bind_text (stmt, 1,  "张三", -1, SQLITE_TRANSIENT);        /* 对应 ?     */
sqlite3_bind_text (stmt, 2,  "13800000001", -1, SQLITE_TRANSIENT); /* 对应 ?2    */
sqlite3_bind_text (stmt,
    sqlite3_bind_parameter_index(stmt, ":name"),  /* 先把名字换成下标 */
    "张三", -1, SQLITE_TRANSIENT);                                  /* 对应 :name */
```

`sqlite3_bind_parameter_index(stmt, ":name")` 查出命名参数的下标；`sqlite3_bind_parameter_count(stmt)` 与 `sqlite3_bind_parameter_name(stmt, i)` 用于调试时枚举参数。

## 6.2 五个 bind 函数与类型

| 函数 | C 类型 | 对应存储类型 |
| --- | --- | --- |
| `sqlite3_bind_int64` | `sqlite3_int64`（也覆盖 `int`） | INTEGER |
| `sqlite3_bind_double` | `double` | REAL |
| `sqlite3_bind_text` | `const char*` + 长度 | TEXT |
| `sqlite3_bind_blob` | `const void*` + 长度 | BLOB（二进制） |
| `sqlite3_bind_null` | 无值 | NULL |

（`bind_int` 是 `bind_int64` 的 32 位便捷版本。）

### 手把手：一个安全的插入函数

```c
int add_contact(sqlite3 *db, const char *name, const char *phone)
{
    const char *sql = "INSERT INTO contacts(name, phone) VALUES(?, ?)";
    sqlite3_stmt *stmt = NULL;
    int rc = sqlite3_prepare_v2(db, sql, -1, &stmt, NULL);
    if (rc != SQLITE_OK) return rc;

    sqlite3_bind_text(stmt, 1, name,  -1, SQLITE_TRANSIENT);
    sqlite3_bind_text(stmt, 2, phone, -1, SQLITE_TRANSIENT);

    rc = sqlite3_step(stmt);          /* 期待 SQLITE_DONE */
    if (rc != SQLITE_DONE)
        fprintf(stderr, "插入失败: %s\n", sqlite3_errmsg(db));

    sqlite3_finalize(stmt);
    return rc;
}
```

无论 `name` 是 `O'Brien`、含引号还是含中文，都原样入库——**参数从不经过 SQL 解析器**。

### 关于 SQLITE_TRANSIENT

`bind_text/bind_blob` 的最后一个参数是"SQLite 拿到这块内存后怎么处理"的约定：

- `SQLITE_TRANSIENT`：SQLite 立即**拷贝一份**，你传的指针随后怎么变都无所谓——**拿不准就传它**；
- `SQLITE_STATIC`：你保证该内存在 finalize 之前**一直有效且不变**，SQLite 直接引用零拷贝——典型场景是字符串字面量、生命周期明确的全局/成员缓冲区。

传错 `SQLITE_STATIC`（内存提前失效）会产生偶发崩溃，非常难查。建议：字面量传 `SQLITE_STATIC`，其余一律 `SQLITE_TRANSIENT`。

### 未绑定参数的默认值

只绑了部分占位符就 step？未绑定的参数自动按 **NULL** 处理，插入 NOT NULL 列时会失败并报 `NOT NULL constraint failed`——看到这个错先检查是不是漏绑定/漏 reset 之后的重新绑定。

## 6.3 查询取值：column 系列

```c
int          sqlite3_column_int    (sqlite3_stmt*, int iCol);
sqlite3_int64 sqlite3_column_int64 (sqlite3_stmt*, int iCol);
double        sqlite3_column_double(sqlite3_stmt*, int iCol);
const unsigned char *sqlite3_column_text (sqlite3_stmt*, int iCol);
const void          *sqlite3_column_blob (sqlite3_stmt*, int iCol);
int          sqlite3_column_bytes (sqlite3_stmt*, int iCol);   /* text/blob 的字节长度 */
int          sqlite3_column_count (sqlite3_stmt*);             /* 结果列数 */
const char  *sqlite3_column_name  (sqlite3_stmt*, int iCol);   /* 列名 */
int          sqlite3_column_type  (sqlite3_stmt*, int iCol);   /* 当前行该列实际类型 */
```

### 手把手：类型感知的取值循环

```c
const char *sql = "SELECT id, name, phone, group_name FROM contacts WHERE group_name = ?";
sqlite3_stmt *stmt;
sqlite3_prepare_v2(db, sql, -1, &stmt, NULL);
sqlite3_bind_text(stmt, 1, "同事", -1, SQLITE_TRANSIENT);

int ncols = sqlite3_column_count(stmt);
while (sqlite3_step(stmt) == SQLITE_ROW) {
    for (int i = 0; i < ncols; i++) {
        const char *cname = sqlite3_column_name(stmt, i);
        switch (sqlite3_column_type(stmt, i)) {
        case SQLITE_INTEGER: printf("%s=%lld\n", cname, sqlite3_column_int64(stmt, i)); break;
        case SQLITE_FLOAT:   printf("%s=%g\n",   cname, sqlite3_column_double(stmt, i)); break;
        case SQLITE_TEXT:    printf("%s=%s\n",   cname, sqlite3_column_text(stmt, i));  break;
        case SQLITE_BLOB:    printf("%s=<BLOB %d字节>\n", cname, sqlite3_column_bytes(stmt, i)); break;
        case SQLITE_NULL:    printf("%s=NULL\n", cname); break;
        }
    }
    printf("----\n");
}
sqlite3_finalize(stmt);
```

要点：

- `column_type` 报告**当前行**该列的实际存储类型（动态类型，行与行可能不同）；
- NULL 列上调用 `column_text` 返回 NULL 指针、`column_int` 返回 0——**无法区分"存了 0"和"存了 NULL"**，需要区分时必须先看 `column_type`；
- 取 BLOB：`column_blob` 拿指针 + `column_bytes` 拿长度，两者要在**同一次调用时机**取齐，指针同样只在本行有效；
- 中文按 UTF-8 传输，Windows 控制台显示乱码是显示层问题（`chcp 65001`），数据本身无损。

## 6.4 绑定为什么防注入：正反对比

**反面（拼接，危险）：**

```c
char sql[512];
/* 用户输入 name = "x'); DROP TABLE contacts; --" 时灾难发生 */
sprintf(sql, "INSERT INTO contacts(name, phone) VALUES('%s', '%s')", name, phone);
sqlite3_exec(db, sql, NULL, NULL, &errmsg);
```

拼接文本会先被 SQL 解析器当成 SQL 语法分析，攻击者构造的引号能改变语句结构——这就是 SQL 注入。哪怕转义手写正确也很容易漏，何况 SQLite 的转义规则与 MySQL 并不相同。

**正面（绑定，安全）：**

```c
sqlite3_prepare_v2(db, "INSERT INTO contacts(name, phone) VALUES(?, ?)", -1, &stmt, NULL);
sqlite3_bind_text(stmt, 1, name, -1, SQLITE_TRANSIENT);
sqlite3_bind_text(stmt, 2, phone, -1, SQLITE_TRANSIENT);
sqlite3_step(stmt);
sqlite3_finalize(stmt);
```

绑定值通过 API 通道直接进入存储引擎，**绕过了 SQL 解析器**，`x'); DROP TABLE contacts; --` 只是普通文本，会被老老实实存成一列数据。规则一句话：**凡是来自程序外部的文本（用户输入、文件内容、网络数据），一律走绑定，绝不拼接。**

4. 实验：绑定语句中故意只绑第 1 个参数就 step，观察错误信息。

<details>
<summary>参考答案（练习 3）</summary>

```c
int search_by_name(sqlite3 *db, const char *kw)
{
    char pattern[128];
    snprintf(pattern, sizeof pattern, "%%%s%%", kw);   /* %kw% */
    sqlite3_stmt *stmt;
    sqlite3_prepare_v2(db, "SELECT id,name FROM contacts WHERE name LIKE ?", -1, &stmt, NULL);
    sqlite3_bind_text(stmt, 1, pattern, -1, SQLITE_TRANSIENT);
    while (sqlite3_step(stmt) == SQLITE_ROW)
        printf("[%lld] %s\n", sqlite3_column_int64(stmt, 0), sqlite3_column_text(stmt, 1));
    sqlite3_finalize(stmt);
    return 0;
}
```

为什么这里的拼接安全：`pattern` 里的 `%` 只是 LIKE 的通配符，整个字符串作为**参数值**经绑定通道传入，不参与 SQL 解析；即使 `kw` 里含有引号、分号，也只影响匹配结果，不可能改变语句结构。安全边界在于"数据是否进入 SQL 解析器"，而不在于"代码里是否出现了字符串拼接"——但为避免误用，实践中仍应尽量把通配符逻辑集中在这一处封装函数里。

## 本章小结

- 占位符三兄弟：`?`（按序）、`?N`（显式编号）、`:name`（命名，配 `bind_parameter_index`）；
- 五个 bind 覆盖 INTEGER/REAL/TEXT/BLOB/NULL；字符串内存拿不准就 `SQLITE_TRANSIENT`，字面量才 `SQLITE_STATIC`；
- 取值四件套：`column_count` / `column_name` / `column_type` / `column_*`；NULL 判断必须靠 `column_type`；
- 绑定值绕过 SQL 解析器，这是防注入的全部原理；LIKE 模式串拼在参数值里是安全的。
