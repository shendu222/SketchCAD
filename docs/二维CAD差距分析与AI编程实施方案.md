# 二维 CAD 产品差距分析与 AI 编程实施方案

> 分析对象：自研二维 CAD 内核 **SketchCAD**（`sketch-cad-cpp/`，C++17 / Qt 6.10.1 / MinGW / CMake+Ninja）
> 对标产品：**AutoCAD 2025**、**ZWCAD（中望 CAD）2025**、**CAXA 电子图板 2023**
> 结论形式：每项给出 **差距等级（高/中/低）+ 代码证据 + 具体表现 + 影响范围**，避免定性空谈
> 证据基线日期：2026-09-26（代码事实均取自当前工作副本，行号可复核）

**已有优势（差距分析中的"正资产"，重构时不得破坏）**
1. **国标化深度**：GB/T 14665 线宽五组 + 9 种线型 + 重合图线优先级、GB/T 4457.5 剖面（19 材料 + PAT）、GB/T 131 粗糙度、GB/T 17452 剖切符号、GB/T 14689 图框、GB/T 4458.4 标注（12 类 + 公差注写）。主流 CAD 是"通用工具 + 用户自配"，本产品是"开箱即国标"。
2. **参数化制图模板**：飞机三面图 / 法兰盘 / 轴承座 / 箱体 / 法兰盘轮毂 / 户型平面图（建筑装修）6 套。
3. **引用式块模型 + 动态块 + 属性块 + 外部参照（Xref）**：与 AutoCAD 语义对齐，附加/分离已落地（68+18 断言）。
4. **测试密度高**：测试代码 / 实现代码 ≈ 1:2.5，38 个独立可执行回归 —— 这是"敢用 AI 大改"的前提条件，也是多数商业 CAD 不具备的。

## 1. 七维度差距清单

### 1.1 绘图与编辑命令完备度　【总评：中，承接外部图纸场景为"高"】

| # | 子项 | 本产品现状（证据） | 主流水平 | 等级 | 具体表现与影响范围 |
|---|---|---|---|---|---|
| 1.1.1 | 基础绘图 | line/circle/circle3p/arc/rect/poly/spline/ellipse_/polyline/freehand 齐全 | 同 | **低** | 可用；缺构造线 XLINE/RAY（低影响） |
| 1.1.2 | 修剪/延伸 | 有 `trim`，**无 `extend`** | TRIM+EXTEND 成对 | **中** | 承接外部图纸最常用组合动作缺失一半，用户被迫"先画辅助线再修剪" |
| 1.1.3 | 倒角/圆角 | 有 `fillet`；仅矩形自带 `rect_chamfer`，**无通用 `chamfer`** | FILLET+CHAMFER | **中** | 机械图倒角标注场景不可用 |
| 1.1.4 | 多段线编辑 | 有 `PolylineEditTool` 交互，**无命令行 PEDIT**（拟合/样条化/宽度/闭合/合并/反转） | PEDIT 全套 | **中** | 外来的 LWPOLYLINE 无法程序化修复，交互编辑能力弱 |
| 1.1.5 | 合并/连接 | 无 `join` | JOIN | **中** | 导入后离散线段无法复原为多段线，影响后续偏移/填充 |
| 1.1.6 | 打断/分割 | 有 `break_at`、`divide` | BREAK/SPLIT/DIVIDE/MEASURE | **低** | MEASURE（定距等分）缺失，影响低 |
| 1.1.7 | 边界/面域 | **无 BOUNDARY/BPOLY/REGION** | 有 | **中** | 剖面填充依赖内置边界追踪，无法让用户交互指定边界；复杂腔体填充需人工描边 |
| 1.1.8 | 填充编辑 | 有填充生成与参数对话框，**无 HATCHEDIT 命令行 / 无边界再编辑 / 无渐变填充** | HATCH+HATCHEDIT+渐变 | **中** | 填充边界随图形变更后无法更新 → 出图错误风险 |
| 1.1.9 | 阵列 | **仅 UI**（`arrayRectangular` / `arrayPolar`），无命令行 `array`；无路径阵列 ARRAYPATH | ARRAYRECT/POLAR/PATH | **中** | 不可脚本化/不可批量；路径阵列缺失影响法兰孔沿曲线分布 |
| 1.1.10 | 复制粘贴 | 无剪贴板命令族（COPYCLIP/PASTECLIP/PASTEBLOCK/COPYBASE） | 有 | **中** | 图间搬运依赖文件导入导出，效率低 |
| 1.1.11 | 特性匹配 | 无 `matchprop`（属性刷） | MA/ MATCHPROP | **低** | 手感缺失，影响低 |
| 1.1.12 | 查询测量 | 仅 `list`；无 DIST / AREA / MASSPROP / ID / LIST 增强 | 全套 | **中** | 校核图纸（算面积、查坐标）需外部手段 |
| 1.1.13 | 图形清理 | 无 `purge`（清理未用块/图层/线型）、无 `audit` | PURGE/AUDIT/OVERKILL | **中** | 长期编辑后文件膨胀、不可见垃圾累积；无 OVERKILL 导致重复图元 |
| 1.1.14 | 文字体系 | 单行 Text；**无 MTEXT 多行文字、无 STYLE 文字样式管理器、无字段 FIELD** | MTEXT/STYLE/FIELD | **中** | 技术要求、多行注释排版能力弱；字体/字高无法统一治理 |
| 1.1.15 | 表格/明细栏 | 有 BOM 面板与标题栏表单，**无 TABLE 图元** | TABLE | **中** | 明细表无法作为图元参与打印/导出 |
| 1.1.16 | 编组与选择过滤 | 有 10 条 `select_*` 命令；**无 GROUP 编组、无 QSELECT 快速选择、无 FILTER 过滤器** | GROUP/QSELECT/FILTER | **中** | 大图上按属性批量筛选不可用 |
| 1.1.17 | 单位与图形界限 | 无 `units` / `limits` 设置面板 | UNITS/LIMITS/INSUNITS | **低** | 跨单位图纸交换时精度与比例语义不明 |

**影响范围总述**：自绘新图场景覆盖良好（≈ 80% 日常动作可用）；**"修改/修复外来图纸"场景覆盖不足（≈ 40%）**，正是企业用户最高频的场景，因此对外竞争力上该维度应按 **高** 计。

### 1.2 捕捉与约束求解　【总评：高】

| # | 子项 | 现状（证据） | 主流水平 | 等级 | 具体表现与影响范围 |
|---|---|---|---|---|---|
| 1.2.1 | 对象捕捉种类 | **5 种**：Endpoint / Center / Intersection / Tangent / Midpoint（`Snap.h:18`） | ≥ 14 种 | **中** | 缺象限点、垂足、插入点、节点、最近点、外观交点、平行、延伸、两点间中点；画垂线/公切/象限连接需手算 |
| 1.2.2 | 捕捉模式管理 | 无"临时捕捉覆盖（Shift+右键菜单）"、无捕捉开关面板 | 有 | **中** | 捕捉冲突时只能全局切换，效率低 |
| 1.2.3 | 极轴/对象追踪 | **无极轴追踪 POLAR、无对象捕捉追踪、无临时追踪点（TK）** | 有 | **高** | 这是 AutoCAD 系"画线不用辅助线"的核心手感，缺失直接导致画线效率量级差异 |
| 1.2.4 | 正交/栅格 | 有 `grid` 命令与栅格显示；正交模式未形成统一开关体系 | ORTHO/SNAP/DYN | **低** | 影响可控 |
| 1.2.5 | 约束类型 | 声明 8 类：Coincident / Parallel / Perpendicular / Equal / Tangent / Horizontal / Vertical / Fixed | ≥ 20 类（含同心、共线、对称、等半径、点在线上） | **中** | 常用同心/共线/对称缺失 |
| 1.2.6 | 约束求解器 | **非求解器**：`ConstraintSolver` 只实现 Tangent/Perpendicular/Parallel 的"改后修复"，其余靠拓扑联动；无方程组、无迭代、无自由度分析 | 尺寸驱动 + 几何约束联合求解（DOF 分析、欠/过约束诊断） | **高** | 无法做参数化改图（改一个尺寸全图联动）；系列化产品设计能力缺失 |
| 1.2.7 | 尺寸驱动约束 | 无（标注只是图形，不驱动几何） | 有（Dimensional Constraint） | **高** | 与设计端（参数化建模）无法打通 |
| 1.2.8 | 约束诊断与可视化 | 无约束图标显示、无约束栏、无"过约束"提示 | 有 | **中** | 约束冲突时静默失败，用户不知为何图形不跟随 |

**影响范围**：草图驱动 / 参数化改图 / 系列化设计**全线不可用**；日常手工绘图受影响中等。

### 1.4 DWG / DXF 文件格式兼容性与数据保真　【总评：高 —— 最硬的短板】

| # | 子项 | 现状（证据） | 主流水平 | 等级 | 具体表现与影响范围 |
|---|---|---|---|---|---|
| 1.4.1 | DXF 导入实体覆盖 | **7 类**：LINE/CIRCLE/ARC/LWPOLYLINE/POLYLINE/TEXT/MTEXT（`CadFormats.cpp:1019-1080`） | ≥ 30 类 | **高** | **不支持 INSERT（块引用）、ELLIPSE、SPLINE、DIMENSION、HATCH、SOLID、POINT、LEADER/MLEADER、ATTRIB、XLINE/RAY、MLINE、TABLE、VIEWPORT、三维实体、代理对象** |
| 1.4.2 | 块定义导入 | **不读 BLOCKS 段** | 完整块表 | **高** | 外来图纸的块被整体丢弃或炸开，可编辑性与文件体积双损失 |
| 1.4.3 | 标注导入 | 不读 DIMENSION | 完整 | **高** | 图纸尺寸信息全部丢失 → 无法二次编辑，只能当底图 |
| 1.4.4 | 填充导入 | 不读 HATCH（本产品自身填充能力强，但读不进来） | 完整 | **高** | 剖面区域变成空白，机械图几乎不可用 |
| 1.4.5 | 表段导入 | 不读 LTYPE / DIMSTYLE / UCS / VIEW / VPORT | 完整 | **中** | 线型与标注样式语义丢失 |
| 1.4.6 | DXF 导出保真 | 椭圆→96 段折线、样条→16×离散、标注→炸开成 LINE+SOLID+TEXT、块引用→展开；**不导出 HATCH 实体** | 原生实体 | **高** | 本产品画的图交出去后被"打散"，对方无法编辑标注/填充；来回交换逐步劣化 |
| 1.4.7 | DXF 版本 | R12 | R12 / 2000 / 2004 / 2007 / 2010 / 2013 / 2018 | **中** | R12 兼容性最好但缺真彩色/Unicode/图层线型等；与新版软件交换建议靠 R12+DXF 双轨 |
| 1.4.8 | DWG 版本 | **仅 R12（AC1009）** | R2000~R2018 主流 | **高** | **近 25 年的主流 DWG 文件读不了**，这是进入企业客户现场的第一道门槛 |
| 1.4.9 | 编码与中文 | UTF-8 写文本（R12 严格为代码页）；DWG 亦为 R12 | GBK/ANSI + Unicode 双轨 | **中** | 与老版 AutoCAD 中文交换可能乱码（手册已标注该限制） |
| 1.4.10 | 颜色与真彩色 | R12 仅 ACI 近似 | ACI + TrueColor | **低** | 视觉差异，影响可控 |

**量化表述**：以"图元类型加权保真率"计，导入一张典型机械零件图（含块、标注、剖面线、样条、椭圆）的几何保真率估计 **40%~60%**；语义保真（能否继续编辑）接近 **20%**。

### 1.5 大图性能与渲染　【总评：高】

| # | 子项 | 现状（证据） | 主流水平 | 等级 | 具体表现与影响范围 |
|---|---|---|---|---|---|
| 1.5.1 | 场景更新粒度 | `onModelChanged()` 与 `onSelectionChanged()` **都直接 `rebuild()` → `scene_->clear()` + 重建全部 Item**（`GraphicsView.cpp:939-958`） | 增量/脏矩形更新 | **高** | 改一个图元、甚至**只是选中一个图元**，都要销毁并重建全部 Item 与 BSP 索引 → 复杂度 O(N) |
| 1.5.2 | 渲染对象模型 | 一图元一 `QGraphicsItem`（含大量 `new`/`delete`、样式计算） | 批量绘制 / 顶点缓冲 | **高** | 10 万图元时 Item 开销与内存不可接受 |
| 1.5.3 | 命中测试 | `hitTest()` 线性扫描全部图元（`GraphicsView.cpp:1317`） | 空间索引（网格/RTree/BVH） | **高** | 鼠标移动即 O(N)，大图上移动鼠标卡顿 |
| 1.5.4 | 撤销内存 | Memento 全量快照 × 200 步（`SketchModel.h:351`、`SketchModel.cpp:33`） | 差量/命令模式（command pattern） | **中~高** | 5 万图元 × 200 步 ≈ 10^7 图元副本，内存与复制耗时都是灾难 |
| 1.5.5 | 重绘范围 | 全视口 `update()`，无脏矩形 | 脏矩形 | **中** | 局部修改也全屏重绘 |
| 1.5.6 | 昂贵几何的缓存 | 样条采样、剖面线生成、PAT 铺线在绘制期实时计算（未见缓存层） | 几何缓存 / 显示列表 | **中** | 填充密集区平移掉帧 |
| 1.5.7 | 加载与序列化 | JSON 存档逐图元解析，未见分块/延迟加载 | 惰性加载 / 二进制存档 | **中** | 打开大文件慢 |
| 1.5.8 | 多线程渲染 | 无 | 部分产品有 | **低** | 可作为 P3 优化 |

**当前可承受规模估计**：约 **1~2 万图元**仍可交互；**5 万图元以上编辑响应明显退化；10 万级基本不可用**。主流 CAD 在 10 万~50 万图元仍可平移缩放。

### 1.6 二次开发接口与生态　【总评：高 —— 生态为零】

> **`docs/AI提示词驱动的CAD能力持续改进方案.md`（V2）** 取代 —— 改为**以提示词设定为核心的改进步骤库**

> 本节的 **§2.1 优先级排序**（即任务池排序）与 **§2.4 人工门禁 G1~G8**、**§2.5 验收 L1~L6** 仍然有效，

### 2.1 优先级排序原则与结果

排序公式：**优先级得分 = 阻塞度(1-5) × 需求刚性(1-5) × AI 适配度(1-5) ÷ 人工不可替代度(1-5)**

| 候选项 | 阻塞度 | 刚性 | AI 适配度 | 人工不可替代度 | 得分 | 归入阶段 |
|---|---|---|---|---|---|---|
| DXF 导入/导出实体扩展（块/标注/填充/椭圆/样条） | 5 | 5 | 5 | 3 | 41.7 | **P0** |
| 打印与布局最小闭环（页面设置 + PDF + 实体打印） | 5 | 5 | 4 | 3 | 33.3 | **P0** |
| 渲染与编辑性能（增量重建 + 空间索引 + 差量撤销） | 5 | 4 | 3 | 4 | 15.0 | **P0** |
| 命令补全（EXTEND/JOIN/CHAMFER/PEDIT/BOUNDARY/HATCHEDIT/MA/PURGE/AUDIT/DIST） | 4 | 4 | 5 | 2 | 40.0 | **P1** |
| 捕捉补全 + 极轴/对象追踪 + 夹点编辑 | 4 | 4 | 4 | 3 | 21.3 | **P1** |
| 图层体系补全（线型/冻结/打印开关/状态管理器/隔离/匹配） | 3 | 4 | 5 | 2 | 30.0 | **P1** |
| 约束求解器（几何+尺寸驱动、DOF 诊断） | 4 | 3 | 2 | 5 | 4.8 | **P2** |
| MTEXT / TABLE / MLEADER / 形位公差 | 3 | 3 | 5 | 2 | 22.5 | **P2** |
| 二次开发接口（C ABI + 脚本宿主 + SDK） | 5 | 3 | 4 | 3 | 20.0 | **P2** |
| 命令别名 pgp / 动态输入 / 快捷特性 | 2 | 3 | 5 | 1 | 30.0 | **P2** |
| DWG R2000+ 读写 | 5 | 5 | 2 | 5 | 10.0 | **P3（且需先过合规评审）** |
| LISP 兼容层 / 行业生态 / 多线程渲染 | 3 | 3 | 3 | 4 | 6.8 | **P3** |

> **排序结论**：先补"能接图、能出图、能开大图"（P0），再补"常用工具与手感"（P1），再做"参数化与开放"（P2），DWG R2000+ 与生态放 P3 且必须先解决合规路径。

### 2.3 AI 编程可承担的任务清单（含做法与边界）

| 任务类型 | 具体做法（提示词工程 / 上下文注入） | 产出形态 | 边界约束 |
|---|---|---|---|
| **① 命令实现（样板化）** | 向 AI 注入"最小完整样例"：既有 `OffsetCommand`（命令类 + `registerExact` + 菜单项 + CMake target + 测试文件），要求"照此结构实现 EXTEND" | 命令类 + 注册 + 菜单 + 测试 target | **只允许调用 `Modify.h`/`Geometry.h`/`Trim.h` 既有 API，禁止自造几何算法**；几何语义由人工复核 |
| **② 格式解析器生成** | 注入 DXF 组码表片段 + 目标结构体 + 既有 `fromDxf` 代码风格；要求表驱动（"未知实体跳过并记录计数"） | `DxfEntityReader` 各类 parse 函数 + 单元测试 | 数学部分（椭圆参数化、NURBS、 hatch 岛）人工写；AI 只做字段搬运与错误恢复 |
| **③ 测试用例生成** | 三类：<br>a) 黄金样本差分（导入→导出→几何比对）<br>b) 属性测试（随机几何 + 不变量断言，如"镜像两次回到原位"）<br>c) 退化用例（零长、重合点、自交、极小角、1e6 坐标） | 测试 target + CMake 注册 | **禁止 AI 写"恒真断言"**；用变异测试验证（故意改坏源码，测试必须失败） |
| **④ 遗留代码迁移/重构** | 大文件拆分（`GraphicsView.cpp` 3440 行 → 按职责分文件）、接口抽取（渲染后端抽象 `IRenderBackend`）、重复代码合并、命名规范统一 | 逐文件 diff + 全量测试绿 | 必须"行为等价"；拆分为多 PR（每个 ≤ 300 行）；禁止同批混入功能改动 |
| **⑤ 文档与手册同步** | 注入命令表/菜单表 → 生成用户手册章节、命令速查表、Changelog | Markdown | 事实须可由代码复核，禁止臆造快捷键 |
| **⑥ 回归基建** | 生成 CI 脚本、基准采集脚本、测试清单、覆盖率报告 | 脚本 + 配置 | 阈值由人工设定 |
| **⑦ 数据/资源整理** | PAT 图案库整理、GB 标准参数表结构化（线宽组、剖面材料、粗糙度） | 数据文件 + 校验脚本 | 标准条文以国标原文为准，AI 不得改写数值 |

**AI 提效的经验值（按本项目实测调整）**：样板化命令/解析器/测试：提效 3~5×；重构迁移：提效 2~3×（受 review 速度限制）；几何算法：提效 < 1.5×（且风险为负）。

### 2.5 验收标准与回归验证方式

**分层验证金字塔**

| 层 | 名称 | 内容 | 门槛 |
|---|---|---|---|
| L1 | **单元/断言测试** | 每个新模块一个 CMake 测试 target；现有 38 个 exe / 42 测试文件 / 12,236 行 | 新模块 ≥ 8~20 断言；全量 38 exe exit 0（现已是基线） |
| L2 | **黄金样本差分** | `tests/golden/`：① 自绘图纸 ② 真实客户图纸（脱敏）③ 公版 DXF/DWG 样本；流程：导入 → 重导出 → 再导入 → 比对（图元计数、点集、长度、面积、包围盒、图层、块表） | 几何差 ≤ 1e-6（图纸 mm）；类型保真率按 §2.2 各模块指标 |
| L3 | **属性/模糊测试** | 随机几何 + 不变量（镜像两次=原位、偏移后等距、撤销 N 次=初始）；模糊输入（畸形 DXF 不得崩溃，须报错并跳过） | 1e5 随机例无失败；畸形输入零崩溃 |
| L4 | **性能基准** | 打开 / 平移 / 缩放 / 单选 / 保存 / 撤销内存；1 万 / 10 万 / 50 万三档 | 10 万：打开 ≤ 3 s、平移缩放 ≥ 30 FPS、单选 ≤ 16 ms、撤销内存 ≤ 图元内存 20%；回归 > 5% 阻断 |
| L5 | **人工抽检清单** | 打印样张比对、AutoCAD/ZWCAD 打开验证（标注/填充可编辑）、GB 符合性（线宽组/字高/剖面）、交互手感（夹点/捕捉） | 每阶段签核清单，逐项签字 |
| L6 | **全量构建回归** | `ninja -j 1` 全量 + 38 个 exe 全绿（本项目已验证：1201/1201 通过） | 每个合并请求前执行一次 |

**各阶段 Definition of Done（节选）**
- **P0 完成判定**：真实客户图纸保真 ≥ 95%；A4/A3 PDF 与样张一致；10 万图元性能达标；CI 一键全绿。
- **P1 完成判定**：命令数 66 → ≥ 110（对标 AutoCAD 常用 150 条，覆盖 ≥ 70%）；捕捉 5 → 14 种；夹点 5 类热操作可用；图层体系对齐主流。
- **P2 完成判定**：约束求解器通过 20 个基准草图（含诊断）；SDK 可写出外部插件；脚本 API 覆盖 ≥ 200 个模型操作。
- **P3 完成判定**：DWG R2000+ 在合规授权下读写通过 L2；布局/视口可用。

**CI 流水线（建议）**：PR → 编译（多 target）→ L1 → L2 差分 → L3 抽样 → L4 阈值 → 生成报告 → 人工 review → 合并。任一红色环节阻断。

## 附录 A：建议立即建立的"AI 编程工作契约"（写入 CONTRIBUTING）

1. **上下文注入三件套**：① 同类既有实现的最小完整样例；② 目标模块的头文件与 API 清单；③ 既有同类型测试文件。
2. **禁写清单**：几何算法内核、容差常量、枚举顺序、存档字段语义、公共 ABI —— 只能由人工改动。
3. **提交形态**：一个 PR = 一个模块 = ≤ 300 行 + 测试 + CMake 注册 + 手册同步；描述中必须写"验证方式"。
4. **AI 自审门槛**：提交前必须本地编译通过 + 所属测试 target 全绿 + 无新增编译警告。
5. **复核抽查**：每个 AI 生成的几何相关 PR，人工必须至少手动验算 1 个数值例。
