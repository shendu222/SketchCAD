# 户型平面图参数化绘制 —— 算法与参数说明

> 面向对象：`sketch-cad-cpp`（C++17 / Qt 6 / namespace `SketchCAD`）
> 新增模块：`src/core/FloorPlanViews.{h,cpp}`、`src/ui/FloorPlanViewsDialog.{h,cpp}`、`tests/floor_plan_views_test.cpp`
> 依据附图：C 户型 101M² 三房两厅两卫装饰平面图（总开间 9200 / 总进深 11460）

## 1. 附图特征分析

附图是一张**建筑装修专业平面图**，与程序既有的机械制图要素（法兰盘、箱体、轴承座、法兰盘轮毂）属于完全不同的图种。逐项拆解其构成要素：

| # | 附图要素 | 表达方式 |

| 2 | 剪力墙 / 承重墙 | **实心涂黑**的墙段（区别于内部双线隔墙） |
| 3 | 内隔墙 | 双线（两条平行线，中间留空） |
| 4 | 门 | 门扇线 + **90° 开启弧**；阳台为推拉门（双错位滑扇） |
| 5 | 窗 | 洞口内三条平行细线 |
| 6 | 家具图块 | 双人床（含枕头）、沙发、茶几、电视柜、餐桌 + 四椅、厨房操作台 + 水盆 + 灶、坐便器、洗手盆、淋浴房、洗衣机、衣柜 |
| 7 | 房间名标注 | 客厅 / 餐厅 / 厨房 / 主卧 / 次卧 / 书房 / 卫生间 ×2 / 景观阳台 / 生活阳台 / 玄关 |

## 2. 程序能力缺口（修改前的缺失项清单）

审查既有代码后，确认以下**绘图接口、数据预处理、图形元素与样式渲染**四类能力缺失：

### 2.1 绘图接口缺口

| 缺口 | 说明 | 既有能力 | 补充方式 |
|---|---|---|---|
| **G1 实心涂黑填充** | 剪力墙需整块涂黑 | `Hatch` 图元已支持 `SectionExempt::SmallAreaSolid`，渲染层走 `HatchDraw::SolidFill` 通道，用图元自身 `color` 填充 | 直接复用：构造 `Hatch` + 置 `sectionExempt = SmallAreaSolid` + `color = 墨色` |
| **G2 建筑斜短线起止符号** | 尺寸链端点是 45° 短粗斜线，非箭头/圆点 | 原 `Dimension` 体系只有箭头/圆点终端，且 `arrowForm` 由**全局标准**决定（`DimensionStandardConfig`），**不可逐元素覆盖** | **绕开 Dimension 体系**：尺寸链以「直线 + 文字 + 斜短线图元」组合绘制（`ChainBuilder`） |
| **G3 开启弧** | 门的 90° 门扇摆动弧 | `ElementType::Arc` + `ElementFactory::createArc` | 复用；注意弧半径须按比例换算 |
| **G4 洞口切墙** | 门窗洞口要自动把墙断开并封口 | 无 | 新增 `OpeningSpec` / `WallSpec` 数据模型 + `WallBuilder::run()` 切段算法 |
| **G5 通高图签** | 右侧通高装饰图签（11 行栏目） | 原 `sheet_frame` 标题栏为机械图格式 | 新增 `buildTitleBlock()` |
| **G6 房间文字** | 中文房间名 | `ElementType::Text` + `createText` | 复用 |

### 2.2 数据预处理缺口

- 附图给的是**建筑拓扑**（墙体走向、洞口位置、家具布置），程序里没有任何建筑布局描述结构。
- 补充 `defaultLayout(const FloorPlanParams&)`：用**比例坐标（0~1，相对 outerW/outerH）**描述 C 户型拓扑，使整套布局可随总尺寸参数整体缩放。
- 洞口以**沿墙轴线的绝对模型坐标**给出，由 `WallBuilder::run()` 换算为沿墙起点偏移。

### 2.3 图形元素 / 样式渲染缺口

- 家庭图块（床/沙发/桌椅/洁具）缺失 → 新增 `FurnBuilder`（由直线/圆/椭圆/矩形组合）。
- 建筑图层体系缺失 → 新增 6 个图层前缀（见 §5.1）。
- 建筑配色缺失 → 新增墨色 / 家具灰 / 标注灰三色。

## 3. 坐标体系与坐标变换（**全模块最容易出错的一环**）

```
模型坐标系：单位 mm，原点在户型外框左下角，Y 轴向上，X 向右
            └─ outerW × outerH 即外框尺寸（默认 9200 × 11460）

图纸坐标系：单位 mm，原点在图纸左下角，Y 轴向上
            └─ sheetW × sheetH 即幅面尺寸（默认 A3 横放 420 × 297）
```

变换关系（`struct Transform`）：

```cpp
struct Transform {
    double s = 0.02, ox = 0, oy = 0;
    double X(double x) const { return ox + x * s; }   // 纸面 X = 模型 X × s + ox
    double Y(double y) const { return oy + y * s; }   // 纸面 Y = 模型 Y × s + oy
};
```

> ⚠️ **铁律：所有进入 `Element` 的 `pts` / `radius` / 文字字高，必须是「图纸 mm」。**
> 本模块曾因 3 处违反此律产生严重几何错位（见 §9 调试记录）。

参数化的两个比例坐标辅助 lambda（家具/标注用）：

```cpp
auto fxp = [tf, W](double v) { return tf.X(v * W); };   // 比例坐标 0~1 → 纸面 X
auto fyp = [tf, H](double v) { return tf.Y(v * H); };   // 比例坐标 0~1 → 纸面 Y
auto rw  = [&](double mm) { return mm * tf.s; };        // 模型长度 mm → 纸面长度 mm
```

## 4. 绘制算法总览

`buildFloorPlanViews(p, model)` 是一条固定流水线，共 8 步：

```
① 参数收敛 makeValid()  ──→  ② 比例选取（标准比例表 + 图签避让）
                                      ↓
                              ③ 排版（可用区内居中）
                                      ↓
   ┌──────────────────────────────┴──────────────────────────────┐
   ↓                    ↓                       ↓                 ↓
④ 墙体（洞口切段、剪力墙涂黑）  ⑤ 家具图块  ⑥ 房间名标注  ⑦ 四周两级尺寸链
   └──────────────────────────────┬──────────────────────────────┘
                                  ↓
                     ⑧ 内容包围盒 + 落框检查（fits）
                                  ↓
                     ⑨ 图框 + 幅面线 + 装饰图签（不计入包围盒）
```

### 步骤 ① 参数收敛

`FloorPlanParams::makeValid()` 用 `std::clamp` 把每个参数压回可行域（总尺寸 1000~100000、墙厚 50~600、门宽 600~2000、字高 1.2~10、边距 5~40、图签宽 60~sheetW/2 等）。`validate()` 做不变式检查，返回空串表示合法。

### 步骤 ② 比例选取（建筑标准比例表）

```cpp
const double availW = sheetW - 2*margin - titleBlockW;   // 扣除右侧通高图签
const double availH = sheetH - 2*margin;
const double sMax = min((availW - 2*dimBand) / outerW,   // 再扣四周尺寸链带
                        (availH - 2*dimBand) / outerH);
// 自动：取标准表中第一个 ≥ 1/sMax 的分母
const double kArchScales[] = {50, 100, 150, 200, 250, 500, 1000};
```

- `autoScale = true`：从上表选**最小的可用分母**（即最大的可用比例）。
- `autoScale = false`：直接用 `manualScale` 作分母。
- 默认 A3 横放（420×297，边距 10，图签宽 115，尺寸链带宽 22）→ **自动得 1:50**。

### 步骤 ③ 排版

```cpp
R.planW = outerW * s;   R.planH = outerH * s;
tf.ox = margin + (availW - planW) * 0.5;   // 在「扣除图签后的可用区」内水平居中
tf.oy = margin + (availH - planH) * 0.5;   // 垂直居中
R.planX0 = tf.ox;  R.planY0 = tf.oy;       // 户型外框左下角纸面坐标
```

### 步骤 ④ 墙体（`WallBuilder`）

对每条 `WallSpec` 执行 `run(wall, tf)`：

1. **判向**：`wallIsHorizontal(w)` → `(y1-y0) <= (x1-x0)`。
2. **求沿墙参数**：`startM = horiz ? wall.x0 : wall.y0`（墙起点模型坐标）、`lenM = 墙长（模型）`。
3. **洞口排序 + 去重叠**：按 `offset` 升序；若 `ops[i].offset < ops[i-1].offset + ops[i-1].width` 则把 `ops[i].offset` 推到前一个洞口右缘（**非法输入保底收敛**）。
4. **沿墙游标切段**：`cursor` 从 0 走；对每个洞口 `o0 = clamp(op.offset - startM, 0, lenM)`、`o1 = clamp(o0 + op.width, 0, lenM)`：
   - `emitPiece(cursor, o0, nullptr)` → **实墙段**
   - `emitPiece(o0, o1, &op)` → **洞口**
   - `cursor = o1`
   末尾 `emitPiece(cursor, lenM, nullptr)` 收尾。
5. **洞口宽换算**：`opP.width = op->width * tf.s`（模型 mm → 纸面 mm）后再分派给 `windowPiece` / `doorPiece` / `slidePiece`。

各段绘制规则：

| 段类型 | 绘制内容 | 线宽(px) |
|---|---|---|
| 实墙段（剪力墙 `solid=true`） | `Hatch` 涂黑多边形（SolidFill） + 双线轮廓 | 1.4 / 1.6 |
| 实墙段（内隔墙） | 仅双线轮廓 | 1.6 |
| 窗 | 洞口两条边线 + 两条中间分格线（`t/6` 内缩） + 两端封口线 | 1.0 |
| 平开门 | 两端封口线 + **门扇线**（长度 = 洞口宽） + **90° 开启弧**（半径 = 洞口宽） | 1.0 / 1.2 / 0.6 |
| 推拉门 | 两端封口线 + 两片错位滑扇 | 1.0 / 1.2 |

**门扇/开启弧的方向**由两个参数决定：
- `hinge`（0 = 铰位在洞口起点侧，1 = 终点侧）
- `swing`（+1 / −1 = 开启方向，墙体局部坐标的法向）

二者组合出 4 个象限，映射到 `Arc` 的 `startAngle / endAngle`（`a0/a1`），例如水平墙 + `hinge=0` + `swing≥0` → `a0=0°, a1=90°`。

### 步骤 ⑤ 家具（`FurnBuilder`）

`FurnBuilder` 提供 `rect / line / circle / ellipse / bed / toilet / basin` 原语，**所有入参一律为纸面 mm**，图块内部零件尺寸（模型 mm）经 `sm(mm) = mm * s` 换算：

- `bed(x0,y0,bw,bh)`：床身矩形 + 两个枕头 + 被沿折线。
- `toilet(cx,cy,dirX)`：水箱矩形 + 坐圈椭圆。
- `basin(cx,cy)`：台面矩形 + 盆椭圆。

`buildFurniture()` 用比例坐标布置 11 组图块（厨房操作台/水盆/灶、餐桌+4 椅、沙发/茶几/电视柜、主次卧床+衣柜、客卫主卫洁具、淋浴房、洗衣机）。

### 步骤 ⑥ 房间名标注（`buildLabels`）

11 处固定房间名，锚点 = `(tf.X(fx*W), tf.Y(fy*H))`，字高 = `p.labelTextH`（纸面 mm）。

### 步骤 ⑦ 四周两级尺寸链（`ChainBuilder`）

用「直线 + 文字 + 45° 斜短线」手工构造，规避 `Dimension` 体系的全局 `arrowForm` 限制：

- `tick(x,y)`：以 `(x,y)` 为中心的 45° 短粗线（半长 0.8mm，线宽 2.0px）——即建筑制图的斜短线起止符号。
- `hChain(nodes, tf, sheetY, extY0)`：水平链。`nodes` 为模型 X 值序列；`sx = tf.X(nodes)`；逐节点画**界线**（从 `extY0` 到 `sheetY+2`）+ **斜短线**；再画尺寸线；最后在每个分格中点上方写分格数字（值 = 相邻节点模型差，四舍五入到整数 mm）。
- `vChain(nodes, tf, sheetX, extX0, textDir)`：竖直链，另带 **`textDir`** 参数：
  - `+1` → 数字写在尺寸线**右侧**（用于平面图**左**侧的链，文字向内生长）
  - `−1` → 数字写在尺寸线**左侧**（用于平面图**右**侧的链）
  - 目的：保证文字**不越出 ±dimBand 尺寸链带**（否则 `fits` 会失败）。

8 条链的布置：

| 位置 | 尺寸线纸面偏移 | 节点（比例坐标） |
|---|---|---|
| 下（分格） | `y0 - 8` | 0, .36, .50, .58, .66, .82, 1 |
| 下（总尺寸） | `y0 - 18` | 0, 1 |
| 上（分格） | `y1 + 8` | 0, .28, .50, .55, .70, 1 |
| 上（总尺寸） | `y1 + 18` | 0, 1 |
| 左（分格） | `x0 - 8`（`textDir=+1`） | 0, .17, .30, .49, .61, .83, 1 |
| 左（总尺寸） | `x0 - 18`（`textDir=+1`） | 0, 1 |
| 右（分格） | `x1 + 8`（`textDir=−1`） | 0, .28, .49, .66, .83, 1 |
| 右（总尺寸） | `x1 + 18`（`textDir=−1`） | 0, 1 |

### 步骤 ⑧ 包围盒与落框检查

**在图框/图签之前**遍历 `R.elems`（即只覆盖平面图内容），累加包围盒：

- `Text` 按 `QRectF(a.x, a.y - th*0.3, text.size() * th, th)` 估算（CJK ≈ 1em/字）；
- 其余图元按全部 `pts` 取 min/max。

```cpp
R.fits = bounds.left()   >= margin - 1e-6
      && bounds.right()  <= sheetW - margin + 1e-6
      && bounds.top()    >= margin - 1e-6
      && bounds.bottom() <= sheetH - margin + 1e-6;
```

### 步骤 ⑨ 图框 + 图签

- 幅面线：`(0,0)-(sheetW,sheetH)`，线宽 1.0。
- 图框：`(margin,margin)-(sheetW-margin,sheetH-margin)`，线宽 2.0。
- 装饰图签 `buildTitleBlock()`：右侧通高，宽 `titleBlockW`；11 行栏目按图签净高的比例分配行高，含设计单位（logo 方块 + 公司名）、建设单位、工程名称、工程编号、审核/校对/设计/工程负责（签字格 + 日期格）、图纸名称、专业/图号/比例、备注。

### 5.2 内部数据结构

```cpp
enum OpenType { OT_Window = 0, OT_Door = 1, OT_Slide = 2 };

struct OpeningSpec {
    double offset = 0;    // 沿墙轴线的绝对模型坐标（mm）
    double width  = 0;    // 洞口宽（模型 mm）
    int    type   = OT_Window;
    int    hinge  = 0;    // 门：0=铰位在起点侧，1=终点侧
    int    swing  = 1;    // 门：开启侧（墙局部法向 +1/-1）
};

struct WallSpec {
    double x0 = 0, y0 = 0, x1 = 0, y1 = 0;  // 墙矩形（模型 mm，厚度已含）
    bool   solid = false;                    // true = 剪力墙（涂黑）
    std::vector<OpeningSpec> openings;       // 沿墙起点 → 终点排序
};
```

## 6. 参数完整说明

`FloorPlanParams`（默认值即附图 C 户型配置）：

## 7. 使用方式

### 7.1 界面入口

主菜单 **【绘图(&D) → 制图模板 → 户型平面图…】** → 弹出参数对话框（21 项）→ 确定后图元经 `SketchModel::beginEdit` / `addElementsQuiet` 落入当前图纸。

### 7.2 代码调用

```cpp
#include "core/FloorPlanViews.h"

SketchCAD::FloorPlanParams p;          // 默认 = C 户型 101M²
p.outerW = 11200.0;                    // 改总开间
p.showFurniture = false;               // 不画家具
const auto R = SketchCAD::buildFloorPlanViews(p, model);
model->beginEdit(QStringLiteral("绘制户型平面图"));
model->addElementsQuiet(R.elems);
// R.scaleLabel == "1:50"、R.fits == true、R.elems.size() == 438（默认参数）
```

### 7.3 参数预设建议

| 场景 | 关键参数 |
|---|---|
| 标准出图 | 默认（A3 横放，1:50，全要素） |
| 大户型 | 加大 `outerW` / `outerH`（自动降比例到 1:100） |
| 纯结构图 | `showFurniture = false`、`showLabels = false` |
| 平面布置图 | 关 `showDims`，保留家具与标注 |
| 小幅面 | `sheetW/sheetH` 改 A4/A5，自动降比例 |

## 9. 调试记录：四类真实缺陷与根因

开发过程中出现 6 项断言失败，最终定位为 4 个独立缺陷。记录于此，供后续模板复用。

### 缺陷 1 —— `Transform` 定义在使用点之后

`WallBuilder::run(WallSpec&, const Transform&)` 定义在文件前部，而 `struct Transform` 定义在文件后部（§坐标变换段）。编译器报 `request for member 'X' in 'tf', which is of non-class type 'const int'`。

**修复**：把 `Transform` 定义上移到 `WallBuilder` 之前，并删除原处定义。

### 缺陷 2 —— 洞口模型偏移缺 `startM`

`op.offset` 是**沿墙轴线的绝对模型坐标**，而 `piecePaper()` 期望的是**沿墙起点偏移**。缺少 `startM` 换算会导致内墙上的洞口被错误 clamp 到墙端（第二扇门直接消失）。

**修复**：`run()` 内补 `const double startM = horiz ? wall.x0 : wall.y0;`，切段时用 `op.offset - startM`。

### 缺陷 3 —— 开启弧半径 / 门扇长度未乘比例 ★ 最隐蔽

`OpeningSpec::width` 是**模型 mm**（如 900），而门扇端点 `leafEnd` 与开启弧 `createArc(center, w, ...)` 的圆心已由 `tf.X/Y` 换算为**纸面坐标**。半径却仍传 900 → 弧跨度远超图纸。

**症状**：`bounds = (-787, -0.6, 1855.2 × 2626663.8)` —— 高度 262 万 mm。
**修复**：在 `emitPiece()` 内构造纸面副本 `OpeningSpec opP = *op; opP.width = op->width * tf.s;` 再分派。

### 缺陷 4 —— 家具内部偏移未乘比例 + `fyp(H - 0.001)` 二次缩放

两个子问题：

1. `FurnBuilder::toilet/basin/bed` 内部零件尺寸（100/420/190/240/250/180/60…）是**模型 mm**，却直接用在了纸面坐标上 → 图块放大 50 倍。
2. 厨房操作台写作 `fyp(H - 0.001)`，而 `fyp(v) = tf.Y(v * H)` 期望**比例坐标 0~1** → 实际传入 `11460` → `11460 × 11460 × 0.02 ≈ 2 626 663`。**这正是缺陷 3 中那个 262 万 mm 的真正来源**（缺陷 3 与 4 叠加）。

**修复**：
- `FurnBuilder` 增加成员 `double s` 与 `double sm(double mm) const { return mm * s; }`，所有零件尺寸经 `sm()`；
- 厨房上边改用 `const double yTop = tf.Y(H);`。

### 缺陷 5 —— 尺寸链文字越出尺寸链带

右侧竖直尺寸链的文字原本一律向 `+x` 延伸，`"11460"` 5 字 × 2.5mm = 12.5mm，使包围盒宽 = `planW + 50.3`，超出测试容差上界 `planW + 40`。

**修复**：`vChain()` 增加 `textDir` 参数，右侧链条文字向左（向内）排布，保证内容不越出 ±`dimBand` 带。
