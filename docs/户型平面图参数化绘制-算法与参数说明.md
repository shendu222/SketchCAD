## 2. 程序能力缺口（修改前的缺失项清单）

审查既有代码后，确认以下**绘图接口、数据预处理、图形元素与样式渲染**四类能力缺失：

### 2.1 绘图接口缺口

| 缺口 | 说明 | 既有能力 | 补充方式 |
|---|---|---|---|
| **G1 实心涂黑填充** | 剪力墙需整块涂黑 | `Hatch` 图元已支持 `SectionExempt::SmallAreaSolid`，渲染层走 `HatchDraw::SolidFill` 通道，用图元自身 `color` 填充 | 直接复用：构造 `Hatch` + 置 `sectionExempt = SmallAreaSolid` + `color = 墨色` |
| **G2 建筑斜短线起止符号** | 尺寸链端点是 45° 短粗斜线，非箭头/圆点 | 原 `Dimension` 体系只有箭头/圆点终端，且 `arrowForm` 由**全局标准**决定（`DimensionStandardConfig`），**不可逐元素覆盖** | **绕开 Dimension 体系**：尺寸链以「直线 + 文字 + 斜短线图元」组合绘制（`ChainBuilder`，三级链） |
| **G3 开启弧** | 门的 90° 门扇摆动弧 | `ElementType::Arc` + `ElementFactory::createArc` | 复用；注意弧半径须按比例换算 |
| **G4 洞口切墙** | 门窗洞口要自动把墙断开并封口 | 无 | 新增 `OpeningSpec` / `WallSpec` 数据模型 + `WallBuilder::run()` 切段算法 |
| **G5 通高图签** | 右侧通高装饰图签（18 行栏目） | 原 `sheet_frame` 标题栏为机械图格式 | 新增 `buildTitleBlock()` |
| **G6 房间文字** | 中文房间名 | `ElementType::Text` + `createText` | 复用 |
| **G7 引线标注** | 箭头 + 折线 + 多行文字 | 无 | 新增 `addLeader()` |

### 2.2 数据预处理缺口

- 附图给的是**建筑拓扑**（墙体走向、洞口位置、家具布置），程序里没有任何建筑布局描述结构。
- 补充 `defaultLayoutImpl(const FloorPlanParams&)`：用**基准模型坐标（9200×11756）**描述 C 户型拓扑，随 `outerW/outerH` 整体等比缩放（见 `kx = outerW/9200`、`ky = outerH/11756`）。
- 洞口以**相对本墙起点的模型偏移（mm）**给出，由 `WallBuilder::run()` 直接作为沿墙起点偏移使用。

### 2.3 图形元素 / 样式渲染缺口

- 家庭图块（床/沙发/桌椅/洁具）缺失 → 新增 `FurnBuilder`（由直线/圆/椭圆/矩形组合）。
- 建筑图层体系缺失 → 新增 6 个图层前缀（见 §5.1）。
- 建筑配色缺失 → 新增墨色 / 家具灰 / 标注灰三色。

## 3. 坐标体系与坐标变换（**全模块最容易出错的一环**）

```
模型坐标系：单位 mm，原点在户型外框左下角，Y 轴向上，X 向右
            └─ outerW × outerH 即外框尺寸（默认 9200 × 11756，含多功能间抬高）

图纸坐标系：单位 mm，原点在图纸左下角，Y 轴向上
            └─ sheetW × sheetH 即幅面尺寸（默认 A3 横放 420 × 297）
```

变换关系（`struct Transform`）：

```cpp
struct Transform {
    double s = 0.02, ox = 0, oy = 0;
    double X(double x) const { return ox + x * s; }   // 纸面 X = 模型 X × s + ox
    double Y(double y) const { return oy + y * s; }   // 纸面 Y = 模型 Y × s + oy
};
```

> ⚠️ **铁律：所有进入 `Element` 的 `pts` / `radius` / 文字字高，必须是「图纸 mm」。**
> 本模块曾因多处违反此律产生严重几何错位（见 §9 调试记录）。

参数化的两个比例坐标辅助 lambda（家具/标注用）：

```cpp
auto PX = [tf, kx](double v) { return tf.X(v * kx); };   // 基准模型坐标 → 纸面 X
auto PY = [tf, ky](double v) { return tf.Y(v * ky); };   // 基准模型坐标 → 纸面 Y
auto rw = [&](double mm)      { return mm * tf.s; };     // 模型长度 mm → 纸面长度 mm
```

## 4. 绘制算法总览

`buildFloorPlanViews(p, model)` 是一条固定流水线，共 9 步：

```
① 参数收敛 makeValid()  ──→  ② 比例选取（标准比例表 + 图签避让）
                                      ↓
                              ③ 排版（可用区内居中）
                                      ↓
   ┌──────────────────────────────┴──────────────────────────────┐
   ↓                    ↓                       ↓                 ↓
④ 墙体（洞口切段、剪力墙涂黑）  ⑤ 家具图块  ⑥ 房间名标注  ⑦ 引线标注（降板说明）
   └──────────────────────────────┬──────────────────────────────┘
                                  ↓
                      ⑧ 四周三级尺寸链（分格→分间→总尺寸）
                                  ↓
                     ⑨ 内容包围盒 + 落框检查（fits）
                                  ↓
                     ⑩ 图框 + 幅面线 + 装饰图签（不计入包围盒）
```

### 步骤 ① 参数收敛

`FloorPlanParams::makeValid()` 用 `std::clamp` 把每个参数压回可行域（总尺寸 1000~100000、墙厚 50~600、门宽 600~2000、字高 1.2~10、边距 5~40、图签宽 60~sheetW/2 等）。`validate()` 做不变式检查，返回空串表示合法。

### 步骤 ② 比例选取（建筑标准比例表）

```cpp
const double availW = sheetW - 2*margin - titleBlockW;   // 扣除右侧通高图签
const double availH = sheetH - 2*margin;
const double sMax = min((availW - 2*dimBand) / outerW,   // 再扣四周三级尺寸链带
                        (availH - 2*dimBand) / outerH);
// 自动：取标准表中第一个 ≥ 1/sMax 的分母
const double kArchScales[] = {50, 100, 150, 200, 250, 500, 1000};
```

- `autoScale = true`：从上表选**最小的可用分母**（即最大的可用比例）。
- `autoScale = false`：直接用 `manualScale` 作分母。
- 默认 A3 横放（420×297，边距 10，图签宽 75，尺寸链带宽 19）→ **自动得 1:50**。

### 步骤 ③ 排版

```cpp
R.planW = outerW * s;   R.planH = outerH * s;
tf.ox = margin + (availW - planW) * 0.5;   // 在「扣除图签后的可用区」内水平居中
tf.oy = margin + (availH - planH) * 0.5;   // 垂直居中
R.planX0 = tf.ox;  R.planY0 = tf.oy;       // 户型外框左下角纸面坐标
```

### 步骤 ④ 墙体（`WallBuilder`）

对每条 `WallSpec` 执行 `run(wall, tf)`：

1. **判向**：`wallIsHorizontal(w)` → `(y1-y0) <= (x1-x0)`。
2. **求沿墙长度**：`lenM = 墙长（模型 mm）`。**注意 `OpeningSpec::offset` 已是相对本墙起点的模型偏移（mm）**，不再减墙起点。
3. **洞口排序 + 去重叠**：按 `offset` 升序；若 `ops[i].offset < ops[i-1].offset + ops[i-1].width` 则把 `ops[i].offset` 推到前一个洞口右缘（**非法输入保底收敛**）。
4. **沿墙游标切段**：`cursor` 从 0 走；对每个洞口 `o0 = clamp(op.offset, 0, lenM)`、`o1 = clamp(o0 + op.width, 0, lenM)`：
   - `emitPiece(cursor, o0, nullptr)` → **实墙段**
   - `emitPiece(o0, o1, &op)` → **洞口**
   - `cursor = o1`
   末尾 `emitPiece(cursor, lenM, nullptr)` 收尾。
5. **洞口宽换算**：`opP.width = op->width * tf.s`（模型 mm → 纸面 mm）后再分派给 `windowPiece` / `doorPiece` / `slidePiece`。

各段绘制规则：

| 段类型 | 绘制内容 | 线宽(px) |
|---|---|---|
| 实墙段（剪力墙 `solid=true`） | `Hatch` 涂黑多边形（SolidFill） + 双线轮廓 | 1.4 / 1.6 |
| 实墙段（内隔墙） | 仅双线轮廓 | 1.6 |
| 窗 | 洞口两条边线 + 两条中间分格线（`t/6` 内缩） + 两端封口线 | 1.0 |
| 平开门 | 两端封口线 + **门扇线**（长度 = 洞口宽） + **90° 开启弧**（半径 = 洞口宽） | 1.0 / 1.2 / 0.6 |
| 推拉门 | 两端封口线 + 两片错位滑扇 | 1.0 / 1.2 |

**门扇/开启弧的方向**由两个参数决定：
- `hinge`（0 = 铰位在洞口起点侧，1 = 终点侧）
- `swing`（+1 / −1 = 开启方向，墙体局部坐标的法向）

二者组合出 4 个象限，映射到 `Arc` 的 `startAngle / endAngle`（`a0/a1`），例如水平墙 + `hinge=0` + `swing≥0` → `a0=0°, a1=90°`。

**布局规模**：共 **31 条墙**（17 条外围**不规则轮廓**剪力墙 + 14 条内隔墙，逐个房间闭合、消除中间墙体缺口），切分后剪力墙实墙段涂黑 → **28 个涂黑区（pocheCount=28）**；内隔墙双线贯穿，各房间（次卧 / 玄关 / 厨房 / 餐厅 / 客厅 / 走廊 / 主卧 / 主卫 / 客卫 / 家政间 / 阳台 / 生活阳台 / 多功能间）均形成封闭回路。

### 步骤 ⑤ 家具（`FurnBuilder`）

`FurnBuilder` 提供 `rect / line / circle / ellipse / bed / toilet / basin` 原语，**所有入参一律为纸面 mm**，图块内部零件尺寸（模型 mm）经 `sm(mm) = mm * s` 换算：

- `bed(x0,y0,bw,bh)`：床身矩形 + 两个枕头 + 被沿折线。
- `toilet(cx,cy,dirX)`：水箱矩形 + 坐圈椭圆。
- `basin(cx,cy)`：台面矩形 + 盆椭圆。
- `WD(a,b,c,d)`：衣柜 / 储物柜矩形 + 对角线交叉（附图对衣柜的画法）。

`buildFurniture()` 用基准模型坐标布置 **12+ 组图块**（厨房操作台/水盆/灶/冰箱、多功能间到顶衣柜 ×2、餐桌 + 4 椅、沙发/茶几/电视柜、主次卧床 + 衣柜、客卫主卫洁具、淋浴房、洗衣机、玄关通高储物柜），位置随 `kx/ky` 缩放。

### 步骤 ⑥ 房间名标注（`buildLabels`）

11 处固定房间名，锚点 = `(tf.X(L.x * kx), tf.Y(L.y * ky))`，字高 = `p.labelTextH`（纸面 mm）。

### 步骤 ⑦ 引线标注（`addLeader`）

附图左下「降板构造」说明：箭头（双翼 ±25°）指向尖端（模型 `(4300*kx, 900*ky)`）→ 斜段（纸面偏移 `-11.5,-6.5`）→ 水平尾线（向左 11mm）→ 尾线下方多行右对齐文字（「降板构造详见图集」「结构降板 -0.050」）。引线受 `showLabels` 开关控制。

### 步骤 ⑧ 四周三级尺寸链（`ChainBuilder`）

用「直线 + 文字 + 45° 斜短线」手工构造，规避 `Dimension` 体系的全局 `arrowForm` 限制：

- `setOffsets(band)`：设三级偏移 `o1 = (band-4)/3`、`o2 = 2(band-4)/3`、`o3 = max(6, band-4)`（默认 band=19 → `o1=5, o2=10, o3=15`）。
- `tick(x,y)`：以 `(x,y)` 为中心的 45° 短粗线（半长 0.8mm，线宽 2.0px）——即建筑制图的斜短线起止符号。
- **三级链**：每边画 3 条链——
  - **分格**（最内）：节点取自墙角 / 洞口棱线（密集分格，对齐附图）；
  - **分间**（中间）：节点取自功能块划分（如 0/4400/7600/9200）；
  - **总尺寸**（最外）：节点仅外框两端（0 / 总开间或总进深）。
- 每条链：逐节点画**界线**（自 `tf.Y(extFrom[i])` / `tf.X(extFrom[i])` 贯通至 `edge ± (o3+2)`，即最外级链外 2mm，对应附图通长界线风格）+ **斜短线**；再画尺寸线；最后在每个分格中点写**水平数字**（横链居中于线上方、竖链居中于线上，值 = 相邻节点模型差，四舍五入到整数 mm）。
- 数字水平书写保证三级链间距（5/10/15mm）大于字高，互不侵占。

12 处链调用（顶 / 底 / 左 / 右 各 3 条），每条链 3 级 → **`dimChainCount = 36`**；分格逐级累计 → **`dimCount = 165`**。

| 上 | 分格 | 0, 2700, 3700, 4400, 4900, 6300, 7600, 8100, 8900, 9200（台阶棱角 4400/7600 起界 11756） |
| 上 | 分间 | 0, 4400, 7600, 9200 |

| 下 | 分间 | 0, 2200, 3300, 5600, 9200 |

### 步骤 ⑨ 包围盒与落框检查

**在图框/图签之前**遍历 `R.elems`（即只覆盖平面图内容），累加包围盒：

- `Text` 按 `QRectF(a.x, a.y - th*0.3, text.size() * th, th)` 估算（CJK ≈ 1em/字）；
- 其余图元按全部 `pts` 取 min/max。

```cpp
R.fits = bounds.left()   >= margin - 1e-6
      && bounds.right()  <= sheetW - margin + 1e-6
      && bounds.top()    >= margin - 1e-6
      && bounds.bottom() <= sheetH - margin + 1e-6;
```

> 实测内容包围盒比平面图每侧宽出约 21mm（三级链外伸 `o3+2=17` + 5 位数字尺寸文本半宽 ≈ 4mm），竖直方向每侧约 17mm。

### 步骤 ⑩ 图框 + 图签

- 幅面线：`(0,0)-(sheetW,sheetH)`，线宽 1.0。
- 图框：`(margin,margin)-(sheetW-margin,sheetH-margin)`，线宽 2.0。
- 装饰图签 `buildTitleBlock()`：右侧通高，宽 `titleBlockW`；**18 行栏目**（字段计数 32）按图签净高比例分配行高，行序对齐附图：
  `R_Logo`(设计单位标识 + logo 方块) → 4×`R_Field`(设计单位全称 / 工程地址 / 工程名称 / 项目名称) → 6×`R_Sign`(审核~图名六行签字栏，含签名格+日期格) → `R_DwgName`(图纸名称大字) → 2×`R_TwoCol`(专业\|设计阶段、图号\|比例) → 3×`R_Full`(平面方案 / 快速搜索 / 出版图签) → `R_Note`(本图纸尺寸以现场放线为准)。

## 5. 核心数据结构与函数

| `LY_FURN` | `户型-家具` | 家具图块 |
| `LY_DIM` | `户型-标注` | 尺寸链线、斜短线、引线 |

| `LY_TITLE` | `户型-图签` | 幅面线、图框、图签 |

| 颜色 | RGB | 用途 |
|---|---|---|

### 5.2 内部数据结构

```cpp
enum OpenType { OT_Window = 0, OT_Door = 1, OT_Slide = 2 };

struct OpeningSpec {
    double offset = 0;    // 相对本墙起点的模型偏移（mm），沿墙起点 → 终点
    double width  = 0;    // 洞口宽（模型 mm）
    int    type   = OT_Window;
    int    hinge  = 0;    // 门：0=铰位在起点侧，1=终点侧
    int    swing  = 1;    // 门：开启侧（墙局部法向 +1/-1）
};

struct WallSpec {
    double x0 = 0, y0 = 0, x1 = 0, y1 = 0;  // 墙矩形（模型 mm，厚度已含）
    bool   solid = false;                    // true = 剪力墙（涂黑）
    std::vector<OpeningSpec> openings;       // 沿墙起点 → 终点排序
};
```

## 7. 使用方式

### 7.1 界面入口

主菜单 **【绘图(&D) → 制图模板 → 户型平面图…】** → 弹出参数对话框（23 项，含新增的「设计单位全称」「工程地址」）→ 确定后图元经 `SketchModel::beginEdit` / `addElementsQuiet` 落入当前图纸。

### 7.2 代码调用

```cpp
#include "core/FloorPlanViews.h"

SketchCAD::FloorPlanParams p;          // 默认 = C 户型 101M²
p.outerW = 11200.0;                    // 改总开间
p.showFurniture = false;               // 不画家具
const auto R = SketchCAD::buildFloorPlanViews(p, model);
model->beginEdit(QStringLiteral("绘制户型平面图"));
model->addElementsQuiet(R.elems);
// R.scaleLabel == "1:50"、R.fits == true、R.elems.size() == 918（默认参数）
```

| 场景 | 关键参数 |

| 小幅面 | `sheetW/sheetH` 改 A4/A5，自动降比例 |

## 9. 调试记录：真实缺陷与根因

开发与对齐附图过程中定位并修复了多个缺陷，记录于此供后续模板复用。

### 缺陷 1 —— `Transform` 定义在使用点之后

`WallBuilder::run(WallSpec&, const Transform&)` 定义在文件前部，而 `struct Transform` 定义在文件后部。`run` 依赖 `tf.X/Y`。

**修复**：把 `Transform` 定义上移到 `WallBuilder` 之前。

### 缺陷 2 —— 洞口偏移语义：相对墙起点 vs 绝对坐标 ★ 易反复

`OpeningSpec::offset` 的语义历经两次反转：

- **第一版**：按「绝对模型坐标」理解，在 `run()` 内做 `op.offset - startM`（墙起点）换算。对起点恰在全局原点的墙（南墙/西墙）无影响。
- **对齐附图修订版**：所有开口偏移统一为**相对本墙起点**的模型 mm（更直观、且与布局描述一致）。因此 `run()` 必须**直接使用** `op.offset`，**不可再减 `startM`**；`startM` 变量已移除。

> ⚠️ **回归教训（缺陷 6）**：若误加回 `op.offset - startM`，会让所有"墙起点 ≠ 全局原点"的墙（多功能间北墙、北墙右段、多功能间底部结构带）的开口被 `clamp` 到墙左端、第一实墙段长度归零被跳过，**涂黑区从 28 掉到**更低值、且开口画在墙角（几何错误）。校验 `pocheCount==28` 正是为此设的护栏。

### 缺陷 3 —— 开启弧半径 / 门扇长度未乘比例 ★ 最隐蔽

`OpeningSpec::width` 是**模型 mm**（如 900），而门扇端点 `leafEnd` 与开启弧 `createArc(center, w, ...)` 的圆心已由 `tf.X/Y` 换算为**纸面坐标**。半径却仍传 900 → 弧跨度远超图纸。

**症状**：包围盒高度达百万 mm 级。
**修复**：在 `emitPiece()` 内构造纸面副本 `OpeningSpec opP = *op; opP.width = op->width * tf.s;` 再分派。

### 缺陷 4 —— 家具内部偏移未乘比例 + 二次缩放

两个子问题：

1. `FurnBuilder::toilet/basin/bed` 内部零件尺寸是**模型 mm**，却直接用在了纸面坐标上 → 图块放大 50 倍。
2. 厨房操作台曾写作 `fyp(H - 0.001)`，而 `fyp(v) = tf.Y(v * H)` 期望**比例坐标 0~1** → 实际传入 `11460` → 二次缩放放大百万倍。

**修复**：`FurnBuilder` 增加成员 `double s` 与 `double sm(double mm) const { return mm * s; }`，所有零件尺寸经 `sm()`；厨房上边改用 `const double yTop = tf.Y(H);`。

### 缺陷 5 —— 尺寸链文字越出尺寸链带

右侧竖直尺寸链的文字原本一律向 `+x` 延伸，`"11460"` 5 字 × 2.5mm 使包围盒宽超出容差。

**修复**：三级链数字**水平书写**，横链居中于线上方、竖链居中于线上，保证文字不越出三级链间距（> 字高）。

### 缺陷 6 —— 误减 `startM` 致多功能间开口塌陷（本次对齐附图期间修复）

**现象**：`pocheCount` 实测 19（预期 22），多功能间北墙/北墙右段/底部结构带的开口被画在墙角。

**根因**：`run()` 用 `o0 = clamp(op.offset - startM, ...)` 把"相对墙起点偏移"误当成"绝对坐标"再减墙起点；非原点墙的 `op.offset(≈500) - startM(≈4400*kx)` 为负 → `clamp` 到 0 → 开口落在墙左端、首实墙段长度 < 1.0 被 `emitPiece` 跳过。

**修复**：`run()` 改为 `o0 = clamp(op.offset, 0, lenM)`（offset 已是相对墙起点），移除 `startM`；同步更新本说明 §5.2 / §4 步骤④ 的语义描述。

### 缺陷 7 —— 轮廓被简化为规则长方形、中间墙未闭合（本次按附图整改）

**现象**：原实现把户型外框画成 9200×11756 的规则矩形，且内隔墙存在缺口，与附图中"次卧/内卫/主卧向外凸出的不规则轮廓 + 各房间闭合"不符。

**根因**：`defaultLayoutImpl()` 的外围剪力墙按 `x[0,9200]×y[0,10856]` 整框 + 右上多功能间抬高块绘制，未表达西/南/东侧凸角；内隔墙分段未形成完整房间回路。

**修复**（不规则轮廓 + 闭合）：

1. **西凸角**：次卧西墙画到 `X=0`（Y[1100,5930]），其上方的玄关/厨房西墙内退至 `X=2550`（Y[5930,10656]），两段之间以水平接墙 `X[0,2750]×Y[5730,5930]` 连接 → 次卧向西凸出。
2. **南凸角（阳台/生活阳台）**：阳台西墙 `X[2900,3100]×Y[0,1300]`、南墙 `X[2900,6430]×Y[0,200]`、东墙 `X[6300,6500]×Y[0,1300]` 向南凸出至 `Y=0`，而次卧/主卧底在 `Y=1100` → 南侧中部凸出。
3. **东阶梯凸角**：主卧/主卫东墙在 `X=9200`（Y[1100,7755]），客卫东墙内退至 `X=8950`（Y[7755,9350]），以两段水平接墙连接 → 东侧阶梯状凸角（主卧、内卫向外突出）。
4. **闭合**：14 条内隔墙（次卧东、玄关东、厨房东/南、餐厅东、客厅东、餐厅底/客厅顶、客厅南推拉门、主卧北、主卫西、客卫西、家政间南/西）将各房间围成封闭回路，消除中间墙体缺口。

> ⚠️ **坐标来源说明**：本环境无法读取附图像素，凸角坐标按既有会话中的附图描述与可推断结构量取，**误差约 ±250mm**；若与原始附图存在偏差，请以附图真实角点坐标替换 `defaultLayoutImpl()` 中对应墙段的 `x0/y0/x1/y1` 即可，无需改动其余管线。
