## 1. 问题分析：四项需求的现状盘点

动手前先做了一轮代码级盘点，结论与"修复"这个措辞有几处重要出入——**正交模式与栅格吸附此前根本不存在**，因此本轮是"诊断 + 补建"而非"修 bug"。

| 需求 | 盘点结果 | 定性 |
|---|---|---|
| ① 对象捕捉补全 | 已具备 15 种类型（端点/圆心/交点/切点/中点/象限/垂足/插入/节点/最近/外观/平行/延伸/两点中点），已有优先级表 `snapPriority()`、像素容差 `PICK_TOL_PX=8` | **缺的是"命中提示"**：吸附时只画彩色标记，不告诉用户吸到了什么 |
| ② 约束求解 | `ConstraintType` 有 8 值，但自动检测仅 3 类（Tangent/Perpendicular/Parallel）；`constraint` 命令只是"建一条约束图元"，日志原文写着「求解器后续接入」 | **缺同心/对称/尺寸，缺求解，缺冲突检测** |
| ③ 正交与栅格 | 全局搜索 `ortho/gridSnap/snapToGrid/gridStep` → 命中的全是 `line_orthogonal` 等**直线子模式**与栅格**显示**开关（F7） | **正交模式、栅格吸附两项能力完全缺失** |
| ④ 正交开关体系 | 无状态可统一 | 需**先建状态，再统一入口** |

### 1.1 由此确定的真实问题

1. **正交缺失**：画水平/垂直线只能靠极轴或 `line_snake`，无法"随手锁方向"。
2. **栅格只有显示、没有吸附**：`drawBackground` 按缩放画 1/10/100 mm 网格，但坐标从不量化——"对齐到栅格"这件事从未发生。
3. **约束是"死记录"**：`constraint perpendicular 3 7` 只新增一个 `ElementType::Constraint` 图元，不求解、不校验、不报错，用户以为加了约束实际什么都没发生。
4. **捕捉反馈缺失语义**：标记有颜色区分，但用户看不出"现在是端点还是垂足"，尤其在多类型同时开启时容易误判。

## 2. 方案选型与关键决策（含权衡）

### 决策 1：正交/栅格定位为「强制性输入约束」，优先级**高于** OSNAP

**备选**：
- (A) 作为最低优先级兜底（OSNAP 命中就不量化）——符合"栅格是粗对齐"的直觉；
- (B) 作为最高优先级强制覆盖——符合 AutoCAD 真实行为。

**选型 (B)**，理由：正交的语义是"此刻画不出斜线"。若 OSNAP 优先，则正交开启时吸到一个斜向端点仍会画出斜线，正交形同虚设，用户会判定"正交坏了"。AutoCAD 的实际行为也是 ORTHO 压过对象捕捉。

栅格吸附同理：开启后即便 OSNAP 未命中，坐标也必须落在栅格上（这是"吸附"的定义）。

**代价**：正交开启时无法吸附到斜向的几何特征点。这正是正交的目的，且用户可用 F8 一键退出。

### 决策 2：正交 + 栅格同时开启 = **正交定方向、栅格定长度**

这是需求里点名的"两者同时开启时行为异常"。若无明确规定，会出现两种实现互相打架：

```
正交把点锁到 y=37.6（水平）→ 栅格又把 x 量化，但 y=37.6 不在栅格线上
→ 若再对 y 量化 → y=38，点脱离了正交锁定线 → 下一帧正交又把它拉回 37.6 → 抖动
```

**规定**：先按正交锁轴（保留 |Δx|、|Δy| 中较大者），再**只量化被保留的那个分量**，另一分量严格保持基准值。这样点永远精确落在锁定轴上，长度为步长整数倍，无抖动。

```cpp
// snap::applyInputConstraints（Snap.cpp）
if (canOrtho && !grid) { 保留较大分量，另一归零 }              // ① 仅正交
if (!canOrtho && grid) { x/y 各自 round(v/step)*step }         // ② 仅栅格
// ③ 两者同时开：锁轴后只量化保留分量，另一分量 = base 原值
```

### 决策 3：正交状态用**单一状态源 + 信号广播**统一三入口

需求 4 的实质是"消除多份状态"。做法：

```
SketchModel::orthoMode_  ←── 唯一真相
   ↑ 写入：F8 快捷键 / 状态栏按钮 / 命令 ortho
   ↓ 广播：orthoModeChanged(bool) → 按钮勾选态回写 + HUD 重绘
```

**权衡**：曾考虑让 GraphicsView 自己存一份"当前正交"以便绘制时零开销读取。否决——那正是需求要消灭的状态分裂。绘制时直接读 `model_->orthoMode()`，一次普通成员调用，开销可忽略。

三条入口全部只调 setter，谁改都会广播给其余两方，**结构上不可能不一致**，而不是靠"记得同步"。

### 决策 4：约束分两层——「隐式自动维持」与「显式声明求解」

| | 隐式（原有） | 显式（本次新增） |
|---|---|---|
| 来源 | 修改前扫描，记录"既成事实"的相切/垂直/平行/同心 | 用户命令声明"我要这两个图元满足 X" |
| 存储 | 不落盘，每次重新检测 | `SketchModel::constraints_`，随图存档 |
| 行为 | 只维持已有关系 | 主动把被动方解到满足为止 |
| 反馈 | 无 | 成功/失败逐条回报 |

**为什么不合并**：合并会让"用户显式声明的尺寸锁定"在每次编辑时被当成"既成事实"重检，一旦几何漂移就静默丢失约束。分层后显式约束永远在表里，`list` 可见、`solve` 可重解。

### 决策 5：显式约束用**独立表**而非塞进 Element

`Element` 只有 `ctype/refA/refB`，**没有**存放 Dimensional 目标值、Symmetric 轴 id 的字段。两条路：

- (A) 给 `Element` 加字段 → 需同步工厂、JSON、属性面板、DXF/DWG 导出（改动面大，且约束不是图元）；
- (B) `SketchModel` 持有 `std::vector<ConstraintRecord>` + 顶层 JSON `"constraints"`。

**选型 (B)**：约束是"关系"不是"图元"，本就不该混进图元表；独立表还让 `value/axisId` 有地方放。旧 `constraint` 命令创建的 `ElementType::Constraint` 图元行为保持兼容（命令改为走新的 `add` 路径）。

### 决策 6：枚举只增不改

`ConstraintType` 在文件里以**整数**存档。新增 `Concentric/Symmetric/Dimensional` 一律**末尾追加**，旧档读出的 0..7 语义不变。

### 决策 7：命中提示文本与菜单/快捷键**同源**

命中提示要显示"端点(E)"。若另写一份 switch 常量，早晚与菜单文案漂移。做法：给 `SnapFieldDef` 增加 `SnapType type` 字段（14 条全部填全），`snapTypeLabel()` 反查得到 label——菜单、快捷键、设置面板、命中提示**同一个字符串**。

### 决策 8：求解失败必须**可定位**

失败反馈格式固定为：

```
#12 与 #7 的「垂直」约束无法满足：#7 已被「固定」约束锁定，不能移动
```

包含：涉及的两个图元 id、约束类型、具体原因。命令 `constraint solve` 逐条以 error 级输出，`constraint check` 另外列出冲突/过约束。

## 3. 规格：优先级、容差与命中提示

### 3.1 落点优先级（自高到低）

```
1. 键盘输入坐标（keyboardInputActive_）→ 原样使用，一切捕捉/约束跳过
2. 正交 / 栅格吸附（强制性输入约束）
3. OSNAP 对象捕捉（显式几何特征）
4. 追踪：极轴 / 对象追踪 / 临时追踪点
5. 自由点
```

> 注意 2 高于 3：见决策 1。追踪（4）与 OSNAP（3）的关系见极轴文档——OSNAP 优先。

### 3.2 容差

| 项 | 值 | 说明 |
|---|---|---|
| 拾取/捕捉容差 | `PICK_TOL_PX = 8` px | 像素定义再除以 zoom 换算为世界单位，任何缩放下手感一致 |
| 追踪容差 | 同上 `worldTol()` | 极轴垂距、对齐线偏差共用 |
| 约束求解容差 | 0.5 mm | 世界单位（约束是图纸语义，不随缩放变） |

### 3.3 命中提示

- **捕捉命中**：标记旁绘制类型名（像素级正写，11px 粗体，颜色=标记色），如 `端点(E)`、`垂足(P)`；
- **追踪命中**：十字标记 + `极轴` / `对象追踪` / `临时追踪点`；
- **状态行**：HUD 常驻显示 `输入约束 [F8]正交✓ [F9]栅格吸附✗（步长 1.00 mm） 捕捉容差 8 px`；
- **正交开启且绘制中**：从基点画出水平+垂直双向虚线，明确"方向已被锁定"。

### 4.1 约束相容性与冲突规则

**相容性校验（添加时前置拦截）**：平行/垂直需两端直线；相切需"直线+圆"或"圆+圆"；同心需两端圆/弧；水平/竖直需被动方直线；对称需轴为直线且两端点数相同；尺寸需被动方可度量且目标值 > 0。

**冲突检测（`constraint check`）**覆盖五类：

1. 同一对图元**重复**同类约束；
2. 同一对图元同时**平行 ∧ 垂直**（互斥）；
3. 同一图元同时**水平 ∧ 竖直**（跨约束对也算）；
4. **同心 ∧ 相切**（同心圆仅退化情形才相切，通常无解）；
5. **Fixed 图元被当作被动方**（要求移动它，必然失败）；以及 **Equal ∧ 两端不同 Dimensional 值**（过约束）。

## 5. 验证结论

- **构建**：`cmake --build ... --target SketchCAD -j 1` → **EXIT=0**，62/62 编译单元通过、链接成功，零新增编译错误；
- **产物**：`build/SketchCAD.exe` 12,856,522 字节（2026-09-29 23:49）；
- **几何自洽性**（代码级推演）：
  - 正交：保留较大分量，另一归零 → 结果必在过基点的水平/垂直线上；
  - 正交+栅格：只量化保留分量 → 结果仍在锁定轴上，且长度为步长整数倍 → **无抖动**；
  - 首点无基准 → 正交不生效（正确：第一点本就该自由）；
- **状态一致性**（结构性保证）：三入口均经 `setOrthoMode/setGridSnap` 单一入口写入，setter 幂等且变化才广播，不存在状态漂移路径；
- **向后兼容**：`ConstraintType` 末尾追加；旧档无 `"constraints"`/`"trackConfig"` 键 → 回落空表/默认配置；旧 `constraint <type> <id1> [id2]` 用法仍可用。

### 5.1 真机验收路径

1. **正交**：F8 开（状态栏「正交」高亮、HUD 显示 ✓）→ 画直线，第二段只能水平/垂直；命令行 `ortho off` → 状态栏与 HUD 同步变 ✗（三入口一致）；
2. **栅格吸附**：F9 开 → 坐标量化；`snap 5` 改步长 5mm → HUD 步长同步；
3. **同时开启**：正交+栅格 → 点始终在水平/垂直线上且长度为步长整数倍，无跳动；
4. **捕捉提示**：悬停端点 → 标记旁显示「端点(E)」；垂足 → 「垂足(P)」；
5. **约束**：`constraint add dimensional 3 4 50`（把 #4 长度锁为 50）→ 拖动 #4 后自动回到 50；`constraint add concentric 5 6`；`constraint list` 看满足状态；造一条互斥约束后 `constraint check` 应报出具体图元 id。

## 6. 遗留与后续方向

- **栅格吸附步长与显示栅格联动**：当前步长独立设置（默认 1mm），未跟随 `drawBackground` 按缩放自动切换的 1/10/100 档。可加"跟随显示栅格"选项；
- **对称约束的轴选择**：现需显式给轴图元 id，交互上可改为"选一条直线作轴"的引导流程；
- **约束可视化**：约束表目前只有命令行 `list`，可在图元面板加约束树与图标标记；
- **尺寸约束与标注联动**：Dimensional 目前锁定图元自身尺寸，可与 `driveDimension`（标注驱动几何）打通，实现"改标注数字即改几何"的双向驱动；
- **求解器能力**：现为"逐条解析求解 + 迭代传播"，未做自由度分析（DOF）与欠约束提示，复杂草图可考虑引入统一数值求解。
