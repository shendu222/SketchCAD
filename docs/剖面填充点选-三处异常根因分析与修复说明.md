# 剖面填充「区域点选」三处异常：根因分析与修复说明

> 工程：`sketch-cad-cpp/`（C++17 / Qt6.10.1 mingw_64 / MinGW 13.1 / CMake + Ninja）
> 核心文件：`src/core/Section.cpp`、`src/core/Section.h`
> 验证用例：`tests/section_pick_anomaly_test.cpp`（新增复现诊断）、`tests/region_pick_test.cpp`、`tests/section_crossing_test.cpp`
> 关联文档：`docs/剖面填充交叉边界细分修复说明.md`、`docs/剖面填充-共享边界保护修复说明.md`
> 标准依据：GB/T 4457.5-2013（剖面符号）、GB/T 17452（剖视图）

---

## 0. 摘要（TL;DR）

用户报告剖面填充「区域点选」存在三处异常，并要求**不得引入新的边界问题**：

| 编号 | 现象 | 根因 | 修复 |
|------|------|------|------|
| **A1** | 已填充区域**重新进入时被重新划分**（重复填充、边界漂移） | 已填充的 `Hatch` 被当作普通边界投入「细分图」，与原始边界编织出面积更大的非法环 | Hatch **不再进细分图**，单源注册为 `loopHatchId` 环；重入直接命中 `AlreadyFilled` |
| **A2** | 不规则图形（菱形）被一条线切分后**仍被当成一个整体** | 面遍历「左手定则」只会走出 CCW 定向的有界面；CW 输入的边界，其真实子区域反而是 CW，被当作「外立面」丢弃 | 求交/剪开前把**闭合边界统一归一化为 CCW**；并跳过「近共线直行续接」避免串区 |
| **A3** | 填充完成后**分割线被错误剪切** | A2 的级联：区域被当整体 → 分割线成为「独占源图元」→ 被消费删除 | A2 修复后分割线被两侧共享 → `exclusiveSrcIds` 判定为非独占 → **原样保留** |

**附带重构**：把面遍历的「候选出边」逻辑抽为显式的 `Cand{ ei, d, straight }` 结构；新增可复用的 `sharesCollinearEdge()` 谓词；对生成环做「连续重复顶点去重」的边界表示归一化。

**验证结论**：`SketchSelfTest` **717 通过 / 0 失败**；`RegionPickTest` **PASS=61/FAIL=0**；`SectionCrossingTest` **PASS=40/FAIL=0**；`SectionPickAnomalyTest` **PASS=16/FAIL=0**（三处异常全部「符合期望行为」）；`SectionTest`/`SectionApplyTest`/`SectionClosureTest`/`SectionClosureEdgeTest`/`SectionRenderVerify` 全部退出码 0。**无回归。**

## 1. 问题陈述

「剖面填充」的交互契约是**「点哪填哪」**：进入区域选择模式后，按鼠标点自动识别**该点所在的封闭区域**并只填充它，相邻区域不受牵连。

三处异常：

- **A1 重入被重新划分**：对某区域填充完成后，再次点击同一区域（或重复进入填充流程），程序没有识别出「此处已填充」，而是重新解析、重新划分边界，产生重复填充或边界漂移。
- **A2 不规则图形拆不开**：一个菱形（闭合 `Polyline`）被一条斜线贯穿切分，分别点击两侧应得到**两个独立区域**，实际却仍被当成**一个整体**。
- **A3 分割线被剪切**：上例中，填充完成后作为分割线的图元被错误删除/裁剪，几何被破坏。

约束：**任何修复都不得引入新的边界问题**（相邻区域误吞并、误删共享边、误切分割线等）。

## 2. 点选流水线总览

区域点选的核心链路（`src/core/Section.cpp`）：

```
选中图元集合 elems
   └─ buildSectionLoopSet(elems, tol)          // 建「闭环集合」
        ├─ buildLoopsSubdivided(非Hatch, tol, subdivide=true)   // 细分图 → 面遍历成环
        └─ Hatch 单源注册为 loopHatchId 环（A1 修复点）
   └─ pickRegionAt(set, 鼠标点 p)               // 命中包含 p 的最内层环
        ├─ 优先命中 loopHatchId 环 → AlreadyFilled（A1 修复点）
        └─ 否则取「体积最小」环 = 最内层
        └─ exclusiveSrcIds = 仅被本环使用、且本环非内孔的边界图元（共享边界保护）
   └─ makeSectionChangeForPick(pick, pool, style)  // 生成 modify::Change[]
        ├─ 选一个独占图元承载 Hatch（原地替换，复用 ID）
        ├─ 其余**独占**边界图元删除；**共享**边界图元一律保留
        └─ 内孔图元删除
   └─ modify::applyChanges(model, changes)     // 落盘
```

`buildLoopsSubdivided` 内部流程：

```
gatherBoundaryPolysForSubdivide(elems)            // 每图元抽出折线边界 RawPoly{pts, closed, srcId}
   → 【A2 修复】闭合边界统一 CCW 归一化
   → transverseHit 两两配对，标记 crossed[]        // 被另一条边界「穿过」才需细分
   → (1) 未 crossed 的闭合图元 → 直接成环          // 共边相邻矩形、独立圆/矩形走这里
   → (2) crossed 图元 + 开放图元 → splitPolysAtIntersections 在交点剪开
   → 顶点容差合并 → 悬挂尾修剪（度<2 删除）
   → 面遍历（左手定则选下一条出边）→ poly 去重归一化
   → 剔除「无界外立面」（远点探针）
```

## 3. 复现诊断：证据先行

在动手改代码之前，新增了 `tests/section_pick_anomaly_test.cpp`，用**纯核心层、真实 `SketchModel`** 复现四个场景，只记录「期望 vs 实际」：

| 场景 | 构造 | 期望 |
|------|------|------|
| 1 | 矩形 (0,0)-(100,50) + 贯穿竖线 (60,-20)→(60,70) | 填左半后**重入**同点 → `AlreadyFilled`；竖线存活；右半仍可独立填充 |
| 2 | 菱形（闭合 Polyline）+ 斜线 (-50,-10)→(50,25) | 解析出 **2 个闭合环**；两半可分别拾取；分割线存活 |
| 3 | 场景 1/2 落盘后 | 分割线**端点吻合原始**（未被剪切） |
| 4 | T 形：矩形 + 竖线下端点落在矩形内/边上 | **只有 1 个边界交点 → 不细分成 2 块**（保持整体） |

关键探针输出（修复前）：

```
场景1 重解析 loopSet: loops=3
  loop[0] verts=4 area=3000.00 srcIds=[1,2]     ← 左半（正确）
  loop[1] verts=4 area=2000.00 srcIds=[1,2]     ← 右半（正确）
  loop[2] verts=5 area=3000.00 srcIds=[3]       ← 非法大环！（Hatch 参与细分所致）
[重入 pick(30,25)] reason=Ok found=1 ...        ← 异常：未识别已填充
```

```
场景2（菱形）：loops=1，顶点 10，area=2400     ← 异常：被当成整体，无法拆两半
```

诊断结论：**A1 的病灶确实在「Hatch 进入细分图」，A2 的病灶在「面遍历只出 CCW 有界面」**，A3 是 A2 的级联。据此展开修复。

## 4. 根因分析

### 4.1 A1：已填充重入被重新划分

`buildSectionLoopSet` 原先把所有图元（含 `Hatch`）一并投入 `buildLoopsSubdivided`。一个已填充的 `Hatch` 携带的是**上一次填充的外轮廓多边形**，它与原始图形边界**同源却已膨胀**；在交点剪开 + 面遍历时，两者被编织出一个**面积大于原图形**的非法合成环（场景 1 中 `loop[2] area=3000` 即此）。

其后果有二：

1. 重入拾取时，该非法环与真实区域环争抢「最内层」，`pickRegionAt` 无法稳定命中「已填充」语义，于是**重新划分、重复填充**；
2. 边界漂移破坏 A2/A3 所依赖的几何基础。

**要点**：Hatch 是「填充结果」，不是「填充输入」。它不应参与区域划分。

### 4.2 A2：面遍历的定向依赖（左手法则只出 CCW 面）

`buildLoopsSubdivided` 的面遍历规则（注释原文）是「**取相对来向的最小正向（逆时针）转角出边**」——即左手定则，沿面内部连续前进。

该规则只有在**边界为逆时针（CCW，有向面积 > 0，内部在左侧）**时，才能正确走出「受限子区域」：

- 对 CCW 输入：受限子区域是 **CCW 有界面**（被提取）；无界外立面是 **CW**（被丢弃）。
- 对 CW 输入（例如用户按逆序给出的闭合 `Polyline`、或自相交退化轮廓）：**真正的内部子区域反而呈现为 CW**，被左手定则当成「外立面」丢弃，结果只剩整体被当成一整块。

菱形正是 CW 输入 → `loops=1`（整体）。**这就是 A2 的根因。**

### 4.3 A3：分割线被剪切 = A2 的级联

`makeSectionChangeForPick` 的契约（见「共享边界保护」文档）是：**只有「独占图元」（仅被本环使用的边界图元）才会被消费（承载 Hatch / 删除）；共享边界一律保留。**

当区域被错误当成整体时，贯穿分割线成了该「整体环」的**独占**边界 → 被判定可消费 → 删除。**A2 一旦修好**，同一分割线会被**左右两个子环共享** → `exclusiveSrcIds` 不含它 → **原样保留**。A3 无需单独修补。

## 5. 修复方案

### 5.1 A1：Hatch 退出细分图，单源注册为「已填充环」

`buildSectionLoopSet` 重写为：先剔除全部 `Hatch`，只把其余图元送入细分图；再把每个 `Hatch` 作为**独立单源闭环**追加，并用 `loopHatchId` 标出其元素 id。

```cpp
SectionLoopSet buildSectionLoopSet(const std::vector<Element>& elems, double tol) {
    SectionLoopSet set;
    // 异常 A1 修复：已填充的 Hatch 不再投入细分图。
    std::vector<Element> rest;
    rest.reserve(elems.size());
    for (const auto& e : elems)
        if (e.type != ElementType::Hatch) rest.push_back(e);

    LoopBuildResult built = buildLoopsSubdivided(rest, tol, /*subdivide=*/true);
    set.stats = built.stats;
    set.loops = std::move(built.loops);
    set.loopSrcIds = std::move(built.loopSrcIds);

    const size_t n = set.loops.size();
    set.loopArea.assign(n, 0.0);
    set.loopHatchId.assign(n, 0);          // 0 = 非 Hatch
    for (size_t i = 0; i < n; ++i)
        set.loopArea[i] = std::fabs(polygonArea2(set.loops[i])) * 0.5;

    // 已填充 Hatch → 独立单源闭环 + loopHatchId 标记
    for (const auto& h : elems) {
        if (h.type != ElementType::Hatch) continue;
        if (h.pts.size() < 3) continue;
        set.loops.push_back(h.pts);                       // 外边界多边形（见 makeHatchElement）
        set.loopSrcIds.push_back({ h.id });
        set.loopArea.push_back(std::fabs(polygonArea2(h.pts)) * 0.5);
        set.loopHatchId.push_back(h.id);
    }
    return set;
}
```

配套在 `pickRegionAt` 中**优先命中 Hatch 环**：

```cpp
int best = -1, bestHatch = -1;
for (size_t i = 0; i < set.loops.size(); ++i) {
    if (!geo::pointInPolygon(p, set.loops[i])) continue;
    if (i < set.loopHatchId.size() && set.loopHatchId[i] != 0) {      // 已填充环
        if (bestHatch < 0 || set.loopArea[i] < set.loopArea[(size_t)bestHatch] - 1e-9)
            bestHatch = (int)i;
        continue;
    }
    if (best < 0 || set.loopArea[i] < set.loopArea[(size_t)best] - 1e-9) best = (int)i;
}
if (bestHatch >= 0) {                 // 重入已填充区域 → 不重复填充
    r.loopIndex = bestHatch;
    r.boundary = set.loops[(size_t)bestHatch];
    r.boundarySrcIds = set.loopSrcIds[(size_t)bestHatch];
    r.reason = RegionPickReason::AlreadyFilled;
    return r;
}
```

**设计取舍**：原先依赖「单源自闭合」的偶然判定来识别已填充环，不可靠；现在用显式的 `loopHatchId` 标记，语义确定。

### 5.2 A2：闭合边界统一 CCW 归一化

在 `gatherBoundaryPolysForSubdivide` 之后、求交剪开之前插入：

```cpp
// 统一闭合边界为逆时针(CCW)定向。面遍历采用「左手定则」(取相对来向最小正向转角)，
// 该规则只在边界为 CCW(有向面积 > 0、内部在左)时才能正确走完受限区域；若输入为 CW，
// 真正的内部区域反而会被当作「外立面」丢弃，结果只剩整体被当成一整块——这正是异常 A2
// 的根因。统一 CCW 后：受限子区域必为 CCW 有界面(被提取)，无界外立面为 CW(被剔除)。
// 开放折线无定向概念，保持不变。定向规范化放在求交/剪开之前，不影响交点判定(线段相交与方向无关)。
for (auto& poly : polys) {
    if (!poly.closed || poly.pts.size() < 3) continue;
    if (polygonArea2(poly.pts) < 0.0) std::reverse(poly.pts.begin(), poly.pts.end());
}
```

`polygonArea2` 为鞋带公式（有向面积两倍），`< 0` 表示 CW → 反转顶点序即可归一化为 CCW。

**为什么放在求交之前**：线段相交判定与方向无关，先归一化不改变交点集合，却让后续所有面遍历都建立在统一的右手系约定上。

### 5.3 A2 增强：面遍历「跳过近共线直行续接」

分隔线横穿一条**直边**时，交点处的「沿该直边直行」这条边与来向**共线（转角 ≈ 0°）**。若直接取「最小正向转角」，会**误把相邻区域串进来**，导致被切形状仍被当整体。修复：在候选出边中检测「近共线直行」，当该顶点**还存在真正的转角边**时**跳过直行续接**，改拐上分隔线。

```cpp
struct Cand { int ei; double d; bool straight; };
std::vector<Cand> cands;
for (int ei : adj[w]) {
    if (edges[ei].used || ei == cur) continue;
    const Vec3 od = vpts[edges[ei].to] - vpts[w];
    const double eAng = std::atan2(od.y, od.x);
    double d = eAng - tAng;
    while (d <= -kPi) d += 2.0 * kPi;
    while (d >   kPi) d -= 2.0 * kPi;
    if (d <= 1e-12) continue;                 // 近似回退（来向反方向）跳过
    const Vec3 idr = vpts[w] - vpts[u];       // 来向（未归一化）
    const double cross = idr.x * od.y - idr.y * od.x;
    const double dot   = idr.x * od.x + idr.y * od.y;
    const double lin = std::sqrt(idr.x*idr.x + idr.y*idr.y);
    const double lod = std::sqrt(od.x*od.x + od.y*od.y);
    const double sinT = std::fabs(cross) / (lin * lod + 1e-12);
    cands.push_back({ ei, d, (sinT < 1e-3 && dot > 0.0) });   // 近共线且同向 = 直行续接
}
bool hasReal = false;
for (const auto& c : cands) if (!c.straight) { hasReal = true; break; }
int best = -1; double bestDelta = 1e18;
for (const auto& c : cands) {
    if (hasReal && c.straight) continue;      // 存在真转角时跳过直行续接
    if (c.d < bestDelta) { bestDelta = c.d; best = c.ei; }
}
if (best < 0) break;                          // 无法闭合 → 开放轮廓，丢弃
```

**边界情形**：若某顶点**仅有**一条直行边、无其它转角（自然直边界未细分），则保留直行（维持旧行为），不误伤普通直线边界。

### 5.4 边界表示归一化：连续重复顶点去重

面遍历按「边」收集顶点，闭环回到起点时**首点会被重复收集一次**（例如 4 个角点被记录成 5 个顶点）。虽然面积正确，但会导致顶点数虚高、出现零长边，进而使后续 `Hatch` 生成 / 点在多边形内判定出现**不稳定的边界问题**。故在成环后做一次去重归一化：

```cpp
std::vector<Vec3> clean;
clean.reserve(poly.size());
for (const auto& v : poly) {
    if (!clean.empty() && clean.back().distTo(v) <= tol) continue;   // 连续重复
    clean.push_back(v);
}
if (clean.size() >= 3 && clean.back().distTo(clean.front()) <= tol) clean.pop_back();  // 首尾重复
if (clean.size() < 3) continue;              // 去重后不足三角形 → 退化
poly = std::move(clean);
const double a2 = polygonArea2(poly);
if (std::fabs(a2) * 0.5 < 1e-6) continue;    // 零面积退化面丢弃
```

效果：场景 2 的半区边界由「5 顶点」规范为「4 顶点」。

### 5.5 回归防护：共边相邻区域不并入细分图

CCW 归一化上线后，暴露出一个**既有隐患**（被归一化放大）：`transverseHit` 把「共边相邻矩形」误判为「被穿过」。

**现象**：左右两个矩形共用一条边 `x=10`（`RegionPickTest` A 段）。预期两区域各自独立；实际——
- 点右矩形内部却命中 `{101,102}`（即**左∪右的并集轮廓**）；
- 填充左侧后左矩形**不再变成 Hatch**，图元总数从 2 变 3。

**根因**：`transverseHit` 统计「非共线交点」，而共边相邻两矩形在共享边的**两个端点 (10,0)、(10,10)** 处各产生一次「端点—端点」接触（两边界在此处方向不共线），凑够 `≥2` → 被判为 `crossed` → 混淆入细分图 → 面遍历把二者并集当成一整块。这与代码自身的既定注释**「共边相邻矩形仍走直接成环」**相矛盾。

**修复**：新增 `sharesCollinearEdge()` 谓词——两条**闭合**边界若共享一段**共线重叠边（seam）**，则**不作** transverse 分区判定，直接走「直接成环」路径。

```cpp
// 两条「闭合」边界是否共享一段共线重叠边(seam)。相邻矩形共用一条边时，两条边界在该边
// 两端各产生一个「端点—端点」接触点；transverseHit 会把这两个纯角点接触算成 2 个非共线
// 交点，从而把两个本应各自独立的相邻区域误判为「被穿过」并投入细分图 → 面遍历把二者的
// 并集当成一整块。与旧语义「共边相邻矩形仍走直接成环」一致：共边相邻 → 不作 transverse 分区判定。
auto sharesCollinearEdge = [&](const RawPoly& a, const RawPoly& b) -> bool {
    if (!a.closed || !b.closed) return false;
    const int na = (int)a.pts.size(), nb = (int)b.pts.size();
    for (int i = 0; i < na; ++i) {
        const Vec3 pa = a.pts[i], pb = a.pts[(i + 1) % na];
        const Vec3 d1 = pb - pa;
        const double L1 = std::sqrt(d1.x * d1.x + d1.y * d1.y);
        if (L1 <= 1e-12) continue;
        for (int j = 0; j < nb; ++j) {
            const Vec3 qa = b.pts[j], qb = b.pts[(j + 1) % nb];
            const Vec3 d2 = qb - qa;
            const double L2 = std::sqrt(d2.x * d2.x + d2.y * d2.y);
            if (L2 <= 1e-12) continue;
            if (std::fabs(d1.x * d2.y - d1.y * d2.x) > 1e-9 * L1 * L2) continue;  // 不平行
            const Vec3 dq = qa - pa;
            if (std::fabs(d1.x * dq.y - d1.y * dq.x) > 1e-6 * L1) continue;       // 不共线
            const double L1sq = d1.x * d1.x + d1.y * d1.y;
            auto proj = [&](const Vec3& p) {
                return ((p.x - pa.x) * d1.x + (p.y - pa.y) * d1.y) / L1sq;
            };
            double lo = std::max(std::min(proj(qa), proj(qb)), 0.0);
            double hi = std::min(std::max(proj(qa), proj(qb)), 1.0);
            if ((hi - lo) * L1 > tol) return true;         // 重叠长度 > 容差 → 共边 seam
        }
    }
    return false;
};

std::vector<char> crossed(polys.size(), 0);
if (subdivide) {
    for (size_t i = 0; i < polys.size(); ++i)
        for (size_t j = i + 1; j < polys.size(); ++j) {
            if (sharesCollinearEdge(polys[i], polys[j])) continue;   // 共边相邻 → 非分区
            if (transverseHit(polys[i], polys[j])) { crossed[i] = 1; crossed[j] = 1; }
        }
}
```

**为何安全**：仅当两条**闭合**边界存在**共线重叠边**时才跳过；分隔线贯穿矩形（线与矩形边**垂直相交**，无共线重叠）、菱形+斜线（无共线重叠）均不受影响，仍正常细分。

## 7. 关键算法小结（可复用知识）

1. **「谁进细分图」的判据**：只有被另一条边界**真正穿过**（`transverseHit ≥ 2` 个非共线内部交点）的图元才需要细分成环；自闭合、未穿过的图元（独立圆/矩形）与**共边相邻**图元一律「直接成环」——这样重合边不会被误合并、共享边不会被误消费。
2. **面遍历的定向约定**：左手定则要求输入边界为 **CCW**；对所有闭合边界做 CCW 归一化，是让「有界面 vs 无界外立面」二分稳定的前提。
3. **近共线直行的陷阱**：交点处「沿直边直行」与来向共线，会串接相邻区域；**存在真转角时优先拐弯**。
4. **Hatch 是输出不是输入**：已填充结果不参与区域划分，用显式标记（`loopHatchId`）承载「已填充」语义。
5. **边界表示要归一化**：闭环顶点去重（连续重复 + 首尾重复）避免零长边与不稳定的点内判定。
6. **共享边保护**：`exclusiveSrcIds`（仅本环使用的非内孔边界）决定哪些图元可被填充消费；共享边界必须保留。
