## 二、菜单结构（与参考图逐项对应）

```
选择(&N)
├── 全部不选            Ctrl+K
├── 全选                Ctrl+A
├── ─────────
├── 选择实体
├── (取消)选择轮廓
├── ─────────
├── 窗口选择
├── 窗口取消
├── ─────────
├── 选择相交
├── 取消相交
├── ─────────
├── (取消)选择图层
├── ─────────
└── 反选                Ctrl+Shift+I
```

- 即时命令（全部不选 / 全选 / 反选）：点击即执行，不占用工具状态。
- 工具型项：与工具条下拉**共用同一个 QAction**，因此菜单与工具条的高亮/互斥天然同步。
- 顶层菜单可直接操作（画布右键被「拖拽平移 / 单击结束绘制」占用，故选择功能不落在画布右键菜单）。

## 三、交互与状态维护

交互链路：`viewport → mousePressEvent → ToolManager::dispatchPress → ITool::onPress → SketchModel`
状态真相：模型侧只有 `selectedId_` + `selectedIds_` 一套，所有选择操作最终收敛到
`setSelection / addToSelection / clearSelection`，视图侧仅 `rebuild()` 时按 `isSelected()` 刷新高亮。

| 菜单项 | 工具 id | 模型侧实现 | 语义 |
|--------|---------|-----------|------|
| 选择实体 | `select_entity` | `selectEntity` | 点击选中 |
| 取消选择实体 | `deselect_entity` | `deselectEntity` | 点击取消 |
| (取消)选择轮廓 | `toggle_contour` | `toggleContour` | 轮廓已全选中→整条取消，否则整条选中 |
| 窗口选择 | `select_window` | `selectWindow(r, additive)` | 拖框入选，Ctrl 加选 |
| 窗口取消 | `deselect_window` | `deselectWindow(r)` | 拖框移除 |
| 选择相交 | `select_intersected` | `selectIntersected` | 选中与种子相交者（并入选区） |
| 取消相交 | `deselect_intersected` | `deselectIntersected` | 移除与种子相交者 |
| (取消)选择图层 | `toggle_layer` | `toggleLayerOf` | 同层已全选中→整层取消，否则整层选中 |
| 全选 / 全部不选 / 反选 | — | `selectAll / clearSelection / invertSelection` | 即时命令 |

## 四、一处需要澄清的事实（避免后人踩坑）

最初判断「画布框选选不中水平线 / 垂直线」，经核查**不成立**：交互层原先用的
`elementSceneBounds()` 取的是 `ElementItem::boundingRect()`（绘制包围盒，含笔宽余量），
零面积问题只存在于核心层 `geo::elementBounds` 的裸 intersects 用法（已在核心层用
1e-6 双侧膨胀修掉）。

因此第 3 项改动的真实收益不是"修 bug"，而是**消除同一语义的两份实现**：
菜单 / 命令行走核心层、画布拖拽走交互层，长期必然分叉。统一后框选判定只有一份真相，
且与 LibreCAD 一致（按几何包围盒判定，而非按绘制笔宽）。
