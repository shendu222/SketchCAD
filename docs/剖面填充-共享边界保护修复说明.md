# 剖面填充·共享边界保护修复说明

> 工程：`sketch-cad-cpp/`（C++17 / Qt6 / MinGW / CMake + Ninja）
> 涉及文件：`src/core/Section.h`、`src/core/Section.cpp`、`src/ui/MainWindow.cpp`、`tests/section_crossing_test.cpp`
> 关联文档：`docs/剖面填充交叉边界细分修复说明.md`（边界交叉细分成环，前置修复）

---

## 1. 缺陷现象

当**剖面填充区域只是整体图形的一部分**时（例如一个矩形被一条贯穿竖线分成左右两半），
对其中一半执行剖面填充，会**把另一半也一并裁掉**：

- 填充左半 → 整个矩形被替换为「只覆盖左半」的剖面区域，竖线消失、右半区域不复存在。
- 期望：只填充目标那一半，另一半的边界与可填充性完全不受影响。

---

## 2. 根因定位

修复前 `makeSectionChangeForPick()`（`src/core/Section.cpp`）的填充契约是
「**1 个 update + N 个 remove**」：

```cpp
const int target = pick.boundarySrcIds.front();   // ① 第一个边界图元原地改成 Hatch
...
for (size_t k = 1; k < pick.boundarySrcIds.size(); ++k) pushRemove(pick.boundarySrcIds[k]); // ② 其余边界删除
for (int id : pick.holeSrcIds) pushRemove(id);                                              // ③ 内孔删除
```

问题在于 **① 与 ② 无差别地消费了「参与成环的全部边界图元」**，而这些图元往往**同时约束着相邻区域**：

| 场景 | 被消费的图元 | 后果 |
|------|--------------|------|
| 矩形(单个 Rectangle 图元) + 贯穿竖线 | 矩形图元被改成「只覆盖左半」的 Hatch；竖线被删除 | 右半区域的上下边/右边/分隔线全部丢失 → 右半被裁掉 |

对照实验（`RegionPickTest` A 段「两个独立矩形」）之所以**未暴露**该缺陷，是因为那里的左右两块是
**两个彼此独立的图元**，各自独占、互不共享；而本缺陷只在**两区域共享同一图元**（整体外框 / 公共边 /
贯穿分隔线）时才出现。

> 补充：`model.addElement()` 会重新分配 ID，故复现判断不能依赖硬编码 ID。

---

## 3. 修复方案（共享边界保护）

**核心判据——"独占图元"**：一个边界源图元只有当它**仅被本环使用**（不与任何其它闭环共享），
**且本环不是内孔**（未被更大的闭环包含）时，才可以被填充消费；否则必须原样保留。

### 3.1 新增判据（`RegionPickResult::exclusiveSrcIds`）

`pickRegionAt()` 在得到命中环后新增第 5 步，计算"独占"边界源图元：

```cpp
auto loopUseCount = [&](int id) {                       // 该 id 出现在多少个闭环的源列表中
    int c = 0;
    for (const auto& v : set.loopSrcIds)
        if (std::find(v.begin(), v.end(), id) != v.end()) ++c;
    return c;
};
bool bestNested = /* 命中环是否被更大的环包含（内孔环） */;
if (!bestNested)
    for (int id : r.boundarySrcIds)
        if (loopUseCount(id) == 1) r.exclusiveSrcIds.push_back(id);
```

### 3.2 只消费独占图元（`makeSectionChangeForPick`）

```cpp
// 承载 Hatch 的图元：优先选一个"独占"图元；无独占图元 → 纯新增（不改任何原图元）
int target = -1;
for (int id : pick.boundarySrcIds) if (isExclusive(id)) { target = id; break; }
...
// 仅"独占"边界图元并入删除；共享边界图元一律保留；内孔按原逻辑处理
for (int id : pick.boundarySrcIds) { if (!isExclusive(id)) continue; pushRemove(id); }
for (int id : pick.holeSrcIds)      pushRemove(id);
```

### 3.3 行为矩阵

| 场景 | 独占图元 | 结果 |
|------|----------|------|
| 单个自闭合图元（圆/矩形） | 有（1 个） | 原地替换为 Hatch（复用 ID，撤销/选中态不跳）—— 保持原行为 |
| 4 条独立直线围成的方框 | 有（4 个） | 1 update + 3 remove —— 保持原行为 |
| 矩形(单图元) + 贯穿竖线 | **无** | **纯新增 Hatch**，矩形与竖线原样保留 → 两半均完好 |
| 独立左矩形 + 独立右矩形 | 有（各自） | 填左仅替换左矩形，右矩形不动 —— 保持原行为 |

### 3.4 UI 选中项修正（`MainWindow.cpp`）

修复后承载 Hatch 的可能是另一个「独占」图元，或为纯新增，故填充后的选中项改为：

```cpp
const std::vector<int> newIds = modify::applyChanges(model_, result.changes, QString());
const int changedId = result.changes.empty() ? -1 : result.changes.front().id;
if (changedId > 0)        model_->setSelection({ changedId });      // 复用原 ID：选中态不跳
else if (!newIds.empty()) model_->setSelection({ newIds.front() }); // 纯新增：选中新 Hatch
```

## 6. 影响面

- 仅调整 `makeSectionChangeForPick` 对**边界源图元**的消费范围；`pickRegionAt` / `applyChanges` 接口与签名不变。
- 单图元区域、多独立图元链式区域（方框/跑道形）、嵌套内孔区域等**既有行为保持不变**（对应测试全绿）。
- 唯一新增行为：当区域内所有边界图元都与相邻区域共享时，退化为「纯新增 Hatch」——这正是修复目标。
