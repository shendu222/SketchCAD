# SketchCAD 与主流二维 CAD 系统差距分析报告（结构化版）

> **对象**：`sketch-cad-cpp`（产品名 SketchCAD，C++17 / Qt 6.10.1 Widgets / MinGW-w64 GCC 13.1 / CMake+Ninja）
> **报告日期**：2026-10-26
> **对标产品**：AutoCAD 2025（行业标杆）、中望 CAD 2025 / 浩辰 CAD（国产主流）、LibreCAD / QCAD（开源二维对照）
> **事实基线**：源码 + 无头自测（`SketchSelfTest` 当前 **3063 项断言 EXIT=0**）、`docs/cad-engineering-gap-analysis-2026-10-10.md`（2026-10-10 决策基线）、`docs/SketchCAD-主流CAD差异分析报告.md`。本报告的互操作/工程化结论以 2026-10-10 源码审查为准；与旧差异报告冲突处以本报告及工程化差距报告为准。
> **定位声明**：SketchCAD 是**面向航空/机械工程的轻量二维制图系统**，非三维 CAD。三维能力不计为“应补齐”项。

---

## 0. 摘要（一句话 + 量化总览）

SketchCAD 已从“演示级画板”进入**可用的轻量二维工程 CAD**：国标出图、块/参照、布局打印、命令行习惯、崩溃恢复、二次开发入口均已具备骨架。与主流系统的差距不再是“有没有”，而是 **互操作保真、产能级深度、正式工程化交付** 三个代际差。

**量化总览（评估性打分，5=对标/领先，1=缺失）**

| 维度 | 评分 | 一句话判断 |
|---|---|---|
| 功能完整性 | 3.0 | 国标+垂直模板领先；块/约束/填充深度不足 |
| 运行性能 | 3.0 | 轻量但无显示列表/GPU 批处理，十万图元有风险 |
| 易用性 · 界面设计 | 3.5 | 四输入一致、已加主题切换；无 Ribbon、可配置性弱 |
| 易用性 · 交互效率 | 3.5 | 14 种捕捉+别名+夹点；缺关联阵列、CLI 覆盖不全 |
| 易用性 · 学习成本 | 4.0 | 习惯对齐 AutoCAD，迁移成本低；帮助/F1 弱 |
| 互操作性 | 2.0 | **DWG 写出仅 R2000**、DXF 仅 R12/R2000，无 ODA 内核 |
| 工程化 / 商业就绪 | 2.0 | 无许可/激活、签名证书未落地、仅 Windows |

> 综合约 **2.8–3.0/5**：在其目标场景（中国机械/航空规则化出图与模板化生成）具备真实优势；作为通用二维 CAD 在互操作与商业闭环上仍有代际差距。

## 1. 对比维度定义

每个维度给出**子度量**与**评分口径**，保证后续差异清单与严重程度可量化、可复评。

### 1.1 功能完整性（Functional Completeness）
覆盖“一个通用二维 CAD 用户完成日常工作所需能力”的程度。
- 子度量：图元类型数、命令/编辑命令数、标注/文字/表格、块与参照、图层管理、填充图案、布局与打印、参数化约束、脚本/二次开发 API、文件格式支持面。
- 评分口径：以 AutoCAD 公开能力为 5.0 基准，按“可完成同类任务的百分比与深度”折算。

### 1.2 运行性能（Runtime Performance）
大规模图纸下的响应与稳定性。
- 子度量：打开耗时、平移/缩放帧率、峰值内存、渲染架构（显示列表/GPU）、空间索引、增量重绘、大图降级与取消。
- 评分口径：以“在 N 万图元下保持交互”的 SLO 达成度衡量（本程序暂无产品化 SLO）。

### 1.3 易用性（Usability）—— 用户明确关注，拆为三项
- **1.3.1 界面设计（UI Design）**：视觉一致性、可读性、主题/高 DPI、可配置性、与平台原生外观融合度。
- **1.3.2 交互效率（Interaction Efficiency）**：快捷键/别名覆盖、对象捕捉与追踪、夹点编辑、命令行与脚本、重复操作与批量能力。
- **1.3.3 学习成本（Learning Cost）**：文档/帮助/F1 上下文、与 AutoCAD 操作习惯的一致性（迁移成本）、认证/示例、出错提示友好度。

### 1.4 互操作性（Interoperability，延伸维度）
与主流工作流交换图纸的保真度——是本项目最关键的短板。
- 子度量：DWG 原生读/写版本、DXF 版本、块/属性/动态块/标注/填充语义保留、SHX/中文、代理对象。

### 1.5 工程化 / 商业就绪（Engineering & Commercial Readiness，延伸维度）
“功能齐”不等于“能进现场”。
- 子度量：许可/激活、代码签名、自动更新、跨平台、PLM 对接、分发合规（GPL 转换器义务）。

## 2. 与主流二维 CAD 的具体差异清单

图例：✅ 支持 · ⚠️ 部分/受限 · ❌ 不支持 · **领先** 强于通用 CAD 默认配置。

### 2.1 功能完整性差异

| 能力项 | SketchCAD | AutoCAD/中望/浩辰 | LibreCAD/QCad | 判定 | 量化差距 |
|---|---|---|---|---|---|
| 图元类型 | ~20 类（Line…Fcf，只增不改） | 100+ 对象类型 | 20+ | 部分 | 类型数约为 AutoCAD 的 15–20% |
| 命令目录 | ~100–127 条精确名 + 前缀族；别名 66 条 | >1000 命令 + 完整别名 | 数百 | 部分 | 命令覆盖约 AutoCAD 的 10–12% |
| 编辑命令 | move/rotate/scale/mirror/offset/trim/extend/fillet/chamfer/join/array×3/stretch/align/lengthen/pedit/matchprop/purge/overkill | 全 + 关联阵列 + OVERKILL 深度 | 基本 | 部分 | 缺关联阵列、路径切线对齐、部分清理深度 |
| 标注/文字 | 12 类 + DimStyle + QDIM + MText/STYLE + FIELD 子集 + Table 公式 | 注释性、SHX、完整 FIELD、QLEADER | 基本 | 部分（GB/ISO 切换领先，SHX/注释性落后） | FIELD 码集远小于 AutoCAD |
| GD&T/粗糙度/剖切 | MLeader、Fcf、GB 粗糙度、剖切符号 | 需配置 | 弱 | **领先**（开箱） | — |
| 块 / Xref | 引用式块、属性、动态参数、在位编辑、Xref 附加/分离、设计中心 | 动态块完整、XBIND、路径管理 | 基本块 | 部分 | 动态块深度、XBIND、路径管理弱 |
| 图层 | ByLayer、冻结/打印/透明度、LAYISO 族、LTSCALE、12 个 GB/T 14665 标准层 | 状态管理器/过滤器/视口覆盖更全 | 够用 | 部分 | 缺 LAS/过滤器树/LAYWALK |

| 布局/打印 | 多布局、视口比例/冻结、CTB 简化、PUBLISH、PDF | 图纸集、STB、戳记、电子传递 | PDF/SVG/HPGL | 部分 | 无图纸集/STB/完整戳记 |
| 参数化约束 | 21 类 + 尺寸驱动 + 模板；自研 LM 求解 | 参数化草图完整（工业求解器） | ❌ | 部分 | 工业求解器（SKT）未接入 |
| 脚本/API | JS/SDK/COM/宏；Python/VBA 可选编译 | LISP/.NET/ARX/COM | C++ 插件 | 部分（接口有、生态无） | 无 AutoLISP 兼容 |

### 2.2 运行性能差异

| 能力项 | SketchCAD | 主流系统 | 判定 |
|---|---|---|---|
| 渲染架构 | Qt 场景图，“一图元一 Item” | 显示列表 + GPU 批处理 | 落后（10–50 万图元量级） |

### 2.3 易用性差异（用户关注重点）

| 子维度 | SketchCAD | 主流系统 | 判定 |
|---|---|---|---|
| 界面设计 | 四输入一致、已加亮/暗主题、高 DPI 声明 | Ribbon、可深度配置、主题成熟 | 部分（无 Ribbon、可配置性弱） |

### 2.4 互操作性差异（最关键短板）

| 格式/语义 | SketchCAD | AutoCAD/中望 | 判定 | 量化差距 |

## 3. 差距严重程度评估

严重度：**严重**（阻塞企业落地）/ **高**（影响互操作或商业闭环）/ **中**（专业能力不足）/ **低**（体验/一致性）。
量化列给出“受影响用户比例 / 可量化损失”的评估口径。

| ID | 维度 | 差距 | 严重度 | 量化影响 |
|---|---|---|---|---|
| G1 | 互操作 | **DWG 写出仅 R2000（AC1015）**，R2004+ 不支持 | 严重 | 影响 100% 需向客户交付新版 DWG 的企业用户；客户强制 R2013/R2018 时直接失败 |
| G2 | 互操作 | DWG 非原生内核（R12 自研子集 + R13–R2018 读经桥） | 严重 | 块/标注/填充/动态块/代理对象语义损失；转换器缺失则通道关闭 |
| G3 | 商业就绪 | 无许可/激活/试用期 | 高 | 无法控装机数、无法售卖、无法区分内部版/客户版 |
| G4 | 商业就绪 | 代码签名证书未落地 | 高 | Windows SmartScreen“未知发布者”，企业白名单过不了 |
| G5 | 商业就绪 | 仅 Windows 交付 + 工具链路径写死 | 中 | 部分高校/Linux 工作站无法部署；CI 脆弱 |
| G6 | 功能 | 无关联阵列 / 路径切线对齐 / JOIN-OVERKILL 深度 | 中 | 重复构件编辑效率显著低于 AutoCAD |
| G7 | 功能 | 参数化约束为自研 LM，工业求解器（SKT）未接入 | 中 | 装配级尺寸联动可靠性未知；宣传“参数化”与能力不一致 |
| G8 | 性能 | 无显示列表/GPU 批处理，十万图元风险 | 中 | 大总图平移缩放可能掉帧/卡顿 |
| G9 | 互操作 | SHX 形字体未默认带、注释性比例部分生效 | 中 | 打开外来 DWG 文字不可见/不可打印 |
| G10 | 功能 | 缺图层状态(LAS)/过滤器树/LAYWALK | 中 | 大装配图显示方案切换低效 |
| G11 | 易用性 | 帮助/F1 上下文、认证/示例缺失 | 低 | 新用户上手成本上升，但习惯已对齐 ACAD 缓解 |
| G12 | 易用性 | 无 Ribbon、界面可配置性弱 | 低 | 重度用户效率受限 |
| G13 | 功能 | 无渐变填充、FIELD 码集小、动态块深度弱 | 中 | 建筑/复杂注释表达受限 |

**严重程度分布**：严重 2 项（G1/G2）、高 2 项（G3/G4）、中 7 项（G5–G10、G13）、低 2 项（G11/G12）。
**结论**：差距集中在**互操作保真（G1/G2）**与**商业闭环（G3/G4）**——这四项不解决，产品无法作为设计院主 CAD 或对外售卖。

## 4. 按优先级排序的改进方向建议

按 **P0 放行闭环 → P1 保真与产能 → P2 生态与体验** 推进。每项给出预期收益、工作量量级（人周，单熟练 C++/Qt）、闭合的差距 ID。

### P0 — 能发给客户且打得开对方的图（最高投入产出比）

|---|---|---|---|---|
| 1 | **DWG 写出升级到 R2013/R2018**（优先 ODA Drawings SDK；否则明确仅 R2000 并 UI 明示） | 解除对外交付硬阻塞 | 4–8(ODA)/1(文案) | G1 |

## 5. 改进的 AI 编程提示词

使用约定（与本仓库既有任务提示词同构，可直接贴进新对话）：
- 验收基线：`build.sh test` EXIT=0；双目标 `-Wall -Wextra` 零警告。
- 铁律：`ElementType` / 存档字段只增不改；撤销走 `Change + applyChanges`；不把 GPL 源码链入主程序（LibreDWG 仅进程外）。
- 改完必须在 `SketchSelfTest` 增断言，并更新对应 `docs/*-design-analysis.md`。

### 提示词 P0-1 — DWG 写出升级到 R2013/R2018（闭合 G1）
```
【目标】让 SketchCAD 能写出客户强制的 R2013/R2018 DWG，解除对外交付硬阻塞。
【范围】优先评估并集成 ODA Drawings SDK（合规授权）做原生写出；若授权不可行，则
       扩展 LibreDWG 桥的 dwgwrite 能力边界并在 UI/导出对话框明确标注“最高 R2000”，
       同时把 DXF 写出扩展到 R2004–R2018（LWPOLYLINE/MLINE/透明度/真彩组码）。
【约束】主程序零链接 GPL 源码；不虚标版本号；R12 自研路径与既有黄金样本回归不得破坏；
       ElementType/存档字段只增不改。
【验收】R2018 DWG 在正版 AutoCAD 可打开且块/标注/填充语义保留；t_formatsGolden 扩展
       断言 ≥15；既有 R12 回归全绿；零警告；EXIT=0。
```

### 提示词 P0-2 — DWG 转换器随包与失败可诊断（闭合 G2）
```
【目标】正式安装包默认具备 DWG R13–R2018 读取与 R2000 写出，转换器缺失时给出可执行指引而非静默失败。
【范围】1) build.sh package 把 dwg2dxf/dwgwrite 拷入 STAGE/tools/dwg/；
        2) 安装脚本同步该目录；第三方声明页写入 GPLv3 与源码获取 URL；
        3) dwgbridge::available()==false 时，打开/另存对话框展示版本串原文 + 「未安装 DWG 转换组件」+ 帮助链接；
        4) 选项页增加「DWG 转换组件路径」覆盖 SKETCHCAD_DWGTOOLS。
【约束】主程序零链接 libdwg；自研 AC1009 路径不动。
```

## 6. 结论与建议起点

1. **先过互操作 + 商业闭环（P0）**：DWG 写出版本、转换器随包、代码签名、最小许可、交叉保真门禁——这五项直接决定“能否对外售卖、能否打开客户的图”，是 ROI 最高的投入。
2. **再补产能深度（P1）**：注释性比例、SHX、关联阵列、图层状态、SKT 求解器、大图稳定性——决定“设计院日常改图是否踩坑”。
3. **最后做生态与体验（P2）**：LISP 子集/迁移指南、图纸集、动态 UCS、跨平台构建、行业模板、F1 帮助——放大既有国标与垂直模板优势、降低学习成本。
4. **坚守优势不破坏**：国标内建（GB/T 14665/4458/4457.5/131/17452/14689/10609.1/14690）与六套参数化模板是差异化壁垒，任何改动须保证其回归不退化（以 `SketchSelfTest` 3063 项断言为护栏）。
