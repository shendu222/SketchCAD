# SketchCAD 与主流二维 CAD 系统差异分析报告

> **对比基准**：本程序（SketchCAD，基于 C++17 / Qt 6.10.1 自研）、**AutoCAD**（商业二维/三维全功能标杆）、**LibreCAD**（开源二维 CAD 代表）。
> **报告目的**：客观评估本程序在功能覆盖度、绘图与编辑、图层与对象管理、坐标系与精度、文件格式兼容性、扩展性与性能六个维度上的**优势、不足与功能缺口**，为后续路线规划提供依据。
> **方法**：以本程序源码为事实基准（`src/core`、`src/ui`、`tests`），AutoCAD / LibreCAD 能力按其公开的、广为人知的产品能力描述。

---

## 摘要

本程序是一款**面向中国国家制图标准（GB）的轻量级二维工程绘图系统**。其最大的差异化优势在于：把 GB/T 图层标识、线组/线宽、尺寸标注、图框标题栏、表面粗糙度、剖切符号、剖面线等**系列国家标准内建为可直接使用的功能**，并附带一批**垂直领域参数化模板**（飞机三面图、法兰盘、轴承座、法兰轮毂、箱体、户型平面图）——这些在 AutoCAD 与 LibreCAD 中均需自行配置或完全缺失。

但作为通用二维 CAD，本程序在**块/外部参照、DWG 原生读写、现代 DXF 版本、布局与图纸空间、打印出图、脚本/二次开发 API、参数化约束、填充图案库**等方面与主流系统存在明显缺口。

一句话定位：**工程标准深度强、垂直模板实用、架构轻量、测试完备；通用性、互操作性与可扩展性是主要短板。**

## 一、本程序核心功能与技术架构概述

### 1.1 技术栈与架构

| 项 | 内容 |
|---|---|
| 语言/标准 | C++17 |
| 框架 | Qt 6.10.1（**仅 Widgets**，未用 QML/网络/数据库模块） |
| 编译器/构建 | MinGW-w64 GCC 13.1.0 / CMake ≥ 3.16 + Ninja |
| 第三方几何库 | **无**（几何算法全部自研） |
| 命名空间 | `SketchCAD`（子域：`modify`/`snap`/`dim`/`cadfmt`/`geo`/`section` 等） |

**分层**：

```
┌─────────────────────────────────────────────┐
│ ui/         MainWindow · GraphicsView · 面板  │  表现层
├─────────────────────────────────────────────┤
│ core/       SketchModel（中央模型）            │  模型层
│             Element / Layer / ElementFactory  │
│             CommandInterpreter / Modify       │
│             Section / ConstraintSolver        │
│             CadFormats(JSON/DXF/STEP)         │
├─────────────────────────────────────────────┤
│ 工具层      ToolRegistry（108 项）/ tools/     │
└─────────────────────────────────────────────┘
```

- **模型唯一真相源**：`SketchModel` 集中管理图元集合、图层表、选择集、撤销栈、绘图比例；
- **视图与交互**：`GraphicsView`（`QGraphicsView` 派生）承担渲染、捕捉、拾取、拖拽编辑；
- **命令通路**：工具栏 / 菜单 / 命令行 / 属性面板**四条输入路径收敛到同一模型 API**，保证行为一致。

### 1.2 核心能力盘点

| 维度 | 本程序实现 |
|---|---|
| 图元类型 | **12 类**：Line、Circle、Arc、Rectangle、Polygon、Spline、Ellipse、Polyline（含弧段）、Text、Dimension、Hatch（剖面）、Constraint |
| 绘图工具 | **108 项**（含直线 17 种子模式、圆 10、弧 10、样条 6+编辑 6、椭圆 6、折线 1+编辑 9、标注 14 等） |
| 编辑操作 | move/copy/rotate/scale/mirror(点/线)/offset/trim/延伸/fillet/chamfer(=fillet R0)/explode/align/stretch/divide/break/lengthen/revert/阵列(矩形/极轴，UI 对话框) |
| 标注 | **12 种** DimensionType；**GB/T 4458 与 ISO 129 双标准**可切换 |
| 符号/标准 | 表面粗糙度(GB/T 131)、剖切符号(GB/T 17452)、投影法符号、图框(GB/T 14689)、标题栏(GB/T 10609.1)、比例(GB/T 14690) |
| 图层 | 12 个 GB/T 14665 标准层 + 活动层 + 快照式解耦 |

| 测试 | `tests/` 下 **39 个测试源文件**；综合自测 **727 项断言通过** |

## 二、逐维度对比

### 2.1 功能覆盖度

| 功能域 | 本程序 | AutoCAD | LibreCAD |
|---|---|---|---|
| 二维绘图 | ✅ 丰富（构造几何强） | ✅ 全 | ✅ 中 |
| 三维建模 | ❌ 无 | ✅ 实体/曲面/网格 | ❌ 无 |
| 块/图块 | ❌ 无 | ✅ 块、动态块、属性块 | ✅ 基本块 |
| 外部参照 XREF | ❌ 无 | ✅ 全 | ❌ 无 |
| 标注 | ✅ 12 种，GB/ISO | ✅ 全 + 注释性 | ✅ 基本 |
| 填充/图案 | ⚠️ 仅剖面线 | ✅ 图案/渐变/实体 | ⚠️ 基本 Hatch |
| 文字 | ⚠️ 单行 Text | ✅ TEXT/MTEXT/字段 | ✅ 单/多行（弱） |
| 表格 | ❌ 无 | ✅ Table | ❌ 无 |
| 布局/图纸空间 | ❌ 无 | ✅ 多布局+视口 | ⚠️ 打印布局弱 |
| 打印出图 | ❌ 无 | ✅ 全（PDF/PLT/CTB-STB） | ✅ PDF/SVG/HPGL |
| 脚本/二次开发 | ❌ 无 | ✅ LISP/.NET/ObjectARX/JS | ⚠️ C++ 插件 |
| 参数化约束 | ⚠️ 有限（少数几何约束） | ✅ 全参数化 | ❌ 无 |

**结论**：本程序覆盖"二维工程制图 + 国标出图要素"这一子集且做得较深，但**未覆盖块/参照/布局/打印/三维/自动化**这些通用 CAD 的支柱能力。

### 2.2 绘图与编辑能力

**绘图**：本程序工具数量众多，尤其在**经典几何构造**上不逊色甚至更细——如点到直线垂足、两圆公切线、角平分线、正交/相对角、Snake 折线等成体系的子模式；椭圆提供 6 种画法、样条 6 种。不足之处是**缺少块与动态块**这一"以复用换效率"的核心手段，复杂重复构件的绘制效率会显著低于 AutoCAD。

**编辑**：常用编辑齐备（移动/复制/旋转/缩放/镜像/偏移/修剪/延伸/圆角/倒角/分解/对齐/拉伸/阵列/等分/打断/加长/反向）。相较主流系统的差距在于：

- **无夹点（Grip）全套编辑**：仅有端点联动拖拽，缺少"选中后直接拖拽夹点改中点/象限点/长度"的一体化编辑；
- **阵列非关联**：矩形/极轴阵列是一次性生成，非 AutoCAD 的可编辑关联阵列；
- **无 JOIN/OVERKILL 等批量清理**；
- **CLI 覆盖不完整**：如 `extend`、`array` 无命令行别名（仅 UI 提供），脚本化编辑受限。

### 2.3 图层与对象管理

| 能力 | 本程序 | AutoCAD | LibreCAD |
|---|---|---|---|
| 图层属性（色/线型/线宽） | ✅ | ✅ | ✅ |
| 标准层模板 | ✅ **12 层（GB/T 14665 表6）** | ⚠️ 需自建 | ⚠️ 需自建 |
| 活动图层 + 实时显示 | ✅（HUD 徽标 + ●当前） | ✅ | ✅ |
| 属性继承（BYLAYER） | ⚠️ **快照式解耦**（非引用式） | ✅ 引用式 | ✅ 引用式 |
| 冻结/解冻（含剪枝） | ❌ 无 | ✅ | ✅ |
| 图层锁定 | ✅（定义层） | ✅ | ✅ |
| 打印/非打印开关 | ❌ 无 | ✅ | ✅ |
| 视口级冻结/覆盖 | ❌ 无 | ✅ | ❌ |
| 图层状态 / 过滤器 / 分组 | ❌ 无 | ✅ | ⚠️ 过滤弱 |
| 对象级覆盖/透明度 | ❌ 无 | ✅ | ⚠️ |
| 块/参照作为"对象管理" | ❌ 无 | ✅ | ✅ 块 |

**要点**：本程序的图层语义是**"快照式解耦"**——新建图元拷贝图层属性，改图层定义**不回溯**既有图元。这与 AutoCAD/LibreCAD 的**"BYLAYER 引用式"**（改层即全局生效）是**设计哲学差异**，而非简单缺陷：前者保证"逐图元独立、改层不误伤"，后者保证"统一风格、一处改处处变"。本程序缺少"随层/独立"的属性级开关，用户无法二选一，是可改进点。

### 2.4 坐标系与精度控制

| 能力 | 本程序 | AutoCAD | LibreCAD |
|---|---|---|---|
| 世界坐标 | ✅（Vec3，支持 XY/YZ/XZ 平面切换） | ✅ WCS | ✅ |
| 用户坐标 UCS/动态 UCS | ❌ 无 | ✅ | ⚠️ 部分 |
| 正交/极轴追踪 | ⚠️ 有线子模式（line_h/v/angle） | ✅ Ortho/Polar/OTRACK | ✅ 正交/极轴 |
| 对象捕捉 | ✅ 端点/圆心/交点/切点/中点 | ✅ 全（含象限/垂足/插入点等） | ✅ 部分 |
| 栅格/捕捉 | ✅ | ✅ | ✅ |
| 绘图比例 | ✅（GB/T 14690，1:n） | ✅ 布局比例/注释性 | ⚠️ |
| 精度控制 | 拾取容差 8px、闭合容差 0.5mm、约束容差 0.5 | 单位/精度/角度制式可配 | 单位可配 |
| 注释性缩放 | ❌ 无 | ✅ | ❌ |

**要点**：本程序坐标与捕捉满足二维工程制图的基本需要，且**内建绘图比例与 GB 比例记法**；但缺少 **UCS 自定义**与**极性追踪**，且精度/单位未做成用户可配项。

### 2.5 文件格式兼容性

| 格式 | 本程序 | AutoCAD | LibreCAD |
|---|---|---|---|
| 原生 | JSON(.sketch) | DWG | — |
| DWG | ❌ 非原生（写为 DXF 兼容） | ✅ 原生（全版本） | ⚠️ 只读（libdxfrw，版本有限） |
| DXF | ⚠️ **R12 / AC1009** 读写 | ✅ 全版本（R12~2018+） | ✅ R12~2018（libdxfrw） |
| STEP | ⚠️ **只写**（AP214） | ✅ 导入/导出 | ❌ |
| 其他 | — | DWF/PDF/DGN/SAT… | PDF/SVG/HPGL/PLT |
| 编码 | 中文写 **GBK**/ANSI_936，纯 ASCII 写 ANSI_1252 | 全 Unicode | 依赖库 |
| 校验 | ✅ `validate_dxf.py` / `validate_step.py` | — | — |

**要点**：这是**最关键的互操作短板**。

1. **DWG 无原生读写**（需 ODA 或 LibreDWG SDK），当前写出的 DWG 实为 DXF 内容，主流 CAD 交换会"降级"；
2. **DXF 仅 R12**：无法写出 LWPOLYLINE、无现代实体与 2000+ 特性（透明度、真彩聚线等），仅**读入**时支持 LWPOLYLINE/MTEXT；
3. **STEP 只写不出**：作为三维交换格式意义有限（本程序为二维）。

值得肯定的是：DXF 遵守 R12"三铁律"（AC1009、组码无换行、POLYLINE/VERTEX/SEQEND 结构），中文走 GBK 且能往返无损，并有独立校验脚本——**写出质量在 R12 范围内是可靠的**。

### 2.6 扩展性与性能

| 能力 | 本程序 | AutoCAD | LibreCAD |
|---|---|---|---|
| 二次开发 API | ❌ 无（仅内置命令行） | ✅ LISP/.NET/ObjectARX/JS | ⚠️ C++ 插件 |
| 插件/动态加载 | ❌ | ✅ | ✅ |
| 脚本/批处理 | ⚠️ 仅命令行单条 | ✅ 全 | ⚠️ |
| 渲染/命中 | QGraphicsView，命中 O(N) 逆序遍历 | 优化显示列表 + 索引 | 场景图 |
| 空间索引/视口裁剪 | ❌ 无（无 R 树/网格索引） | ✅ | ⚠️ |
| 大图纸剪枝（冻结） | ❌ 无冻结语义 | ✅ | ✅ |
| 依赖体积 | ✅ 极轻（纯 Qt Widgets） | 重 | 中 |

**要点**：本程序**轻量、无第三方几何库、易部署**是优势；但**无空间索引、无图层冻结剪枝、命中检测 O(N)**，在数万图元以上规模的交互流畅度会落后于主流系统。扩展性方面**没有任何插件/脚本接口**，无法被自动化或在外部生态中被集成。

## 三、优势总结

1. **GB 国家标准深度内建（最大差异化）**
   图层标识（GB/T 14665 表6）、线组/线宽（表1）、尺寸标注（GB/T 4458）、图框（GB/T 14689）、标题栏（GB/T 10609.1）、表面粗糙度（GB/T 131）、剖切符号（GB/T 17452）、剖面线（GB/T 4457.5）、比例（GB/T 14690）**开箱即用**。AutoCAD 需自行配置标准模板，LibreCAD 基本不提供。

2. **垂直领域参数化模板**
   飞机三面图、法兰盘、轴承座、法兰轮毂、箱体、户型平面图——**输入参数即出图**，AutoCAD/LibreCAD 均无此能力。这是面向特定工程场景的"降维"优势。

3. **剖面填充引擎有工程深度**
   基于半边（half-edge）边界追踪的闭环识别 + 内/外立面剔除 + 共享边界保护，属较扎实的算法实现（多数轻量 CAD 仅有简单 Hatch）。

4. **架构轻量、零重型依赖**
   仅 Qt Widgets、无第三方几何库、CMake+Ninja、单文件即可跑，**部署与嵌入成本低**。

5. **测试覆盖度高**
   39 个测试源文件、综合自测 **727 项断言**通过，另有 DXF/STEP 独立校验脚本——**工程可控性与回归保护优于多数同类开源项目**。

6. **四条输入路径行为一致**
   工具栏/菜单/命令行/属性面板收敛到同一模型 API（如绘制样式统一走模型默认样式），避免"工具条选红色、命令行画黑色"类不一致。

7. **图层语义清晰**
   "快照式解耦 + 活动层 HUD"让"新建归属当前层、已有图元不回溯"的语义简单可预期，适合"逐图元独立"的作图习惯。

## 四、不足与功能缺口

### 4.1 严重缺口（影响互操作 / 专业落地）

| 编号 | 缺口 | 影响 |
|---|---|---|
| G1 | **无块/图块库与外部参照（XREF）** | 无法复用标准件与拼装图纸，协同与大型装配受限 |
| G2 | **DWG 无原生读写** | 与主流工作流互通需经 DXF 中转，且 DWG 输出为伪 DWG |
| G3 | **DXF 仅 R12** | 无 LWPOLYLINE 写出与现代特性，交换到新 CAD 可能降级/丢信息 |
| G4 | **无布局/图纸空间与视口** | 无法"一图多视图 + 多比例"出图 |
| G5 | **无打印/出图链路（PDF、CTB/STB、PLT）** | 图纸无法直接落地成纸质/PDF 交付物 |
| G6 | **无脚本/二次开发 API** | 无法自动化、无法被外部生态集成、无法批量处理 |
| G7 | **仅二维** | 无法做三维校验/装配（对本程序定位可接受，但对标 AutoCAD 属缺口） |

### 4.2 中等缺口（专业能力不足）

| 编号 | 缺口 | 说明 |
|---|---|---|
| M1 | 仅剖面线填充，**无图案/渐变库** | 建筑、机械剖面表达受限 |
| M2 | 无文字样式 / **MTEXT 富文本** / 字段 | 复杂注释与技术说明排版受限 |
| M3 | 无**表格** | 明细栏、参数表需手绘 |
| M4 | 参数化约束**有限**（少数几何约束） | 无法驱动式改参重生成 |
| M5 | 无**冻结/视口冻结**、图层状态、过滤器、分组 | 大图纸与多视口管理弱 |
| M6 | 无**透明度**、无**线型比例 LTSCALE**、无**注释性缩放** | 显示表现力与出图一致性不足 |
| M7 | 阵列**非关联**、无 JOIN/OVERKILL | 编辑效率与图纸清理能力弱 |
| M8 | 无**真正 BOM 明细表**（仅按类型分组的树） | 装配统计弱 |
| M9 | 无 UCS 自定义、无极性/对象追踪 | 复杂定位依赖辅助线 |
| M10 | STEP **只写** | 三维互操作单向 |

### 4.3 轻微缺口（体验 / 一致性）

- CLI 覆盖不完整（`extend`/`array` 无命令别名）；
- 快捷键存在冲突（如 `Ctrl+K`）；
- 坐标轴常显、无开关；
- 无坐标系图标 / UCS 图标显示；
- 无撤销历史面板（仅逐次 Ctrl+Z）；
- 单位与精度未做成用户可配项。

## 五、改进建议（路线图）

### 短期（补互操作与出图短板，投入产出比最高）
1. **DXF 升级到 2000+ 版本**：写出 LWPOLYLINE、真彩、透明度组码，保留 R12 作为兼容选项；
2. **块系统**：块定义/插入/属性块 + 图块库；
3. **打印/出图**：接入 PDF 输出与线宽/颜色映射（CTB/STB 或简化映射），补齐"出图闭环"；
4. **CLI 补全**：为 `extend`/`array` 等补齐命令别名，支持简易批处理脚本。

### 中期（逼近主流二维 CAD 能力）
5. **XREF / 布局与图纸空间视口**；
6. **填充图案库**（GB 常用剖面图案集合）+ 渐变；
7. **文字样式 / MTEXT / 表格**；
8. **图层冻结 + 图层状态 + 过滤器/分组**；
9. **属性级"随层/独立"开关**（在现有快照式之上补 BYLAYER 选项，兼顾两类习惯）。

### 长期（架构与生态）
10. **二维参数化约束求解器**（几何+尺寸约束、驱动重生成）；
11. **脚本/插件 API**（Python/JS 或 C++ 插件 ABI）；
12. **性能**：空间索引（R 树/网格）+ 视口裁剪 + 增量重绘，支撑十万级图元；
13. **DWG 原生**（集成 ODA 或 LibreDWG，权衡授权）。

## 六、结论

| 维度 | 相对 AutoCAD | 相对 LibreCAD |
|---|---|---|
| 功能覆盖度 | **明显不足**（缺块/参照/布局/打印/三维/自动化） | **各有短长**（本程序国标+模板强，LibreCAD 块/DXF 强） |
| 绘图与编辑 | 工具数量接近，**缺块与夹点/关联阵列** | **相当或略优**（构造几何更细） |
| 图层与对象管理 | **弱**（无冻结/状态/过滤器/视口） | **相当**（均缺视口级特性） |
| 坐标系与精度 | **弱**（无 UCS/追踪，精度不可配） | **相当** |
| 文件格式兼容 | **显著落后**（DWG 非原生、DXF 仅 R12） | **落后**（LibreCAD DXF 版本更全） |
| 扩展性 | **缺失**（无 API） | **落后**（LibreCAD 有 C++ 插件） |
| 性能 | 轻量但**无索引/剪枝** | 相当 |
| **国标制图** | **领先**（内建 GB 系列） | **领先** |
| **垂直模板** | **独有** | **独有** |
| **测试完备度** | 领先于同类开源 | 领先 |

**总体判断**：本程序是一款**定位清晰、工程扎实的"国标二维制图 + 垂直模板"专用系统**——在其目标场景（中国机械/建筑制图的规则化出图与模板化生成）中具备真实优势；但作为通用二维 CAD，它在**块/参照、DWG 互操作、布局出图、自动化扩展**四个方向上与主流系统存在代际差距。后续若按"先补互操作与出图闭环、再补对象复用与管理、最后补参数化与生态"的次序演进，可在保持轻量与国标优势的同时，显著缩小与 AutoCAD/LibreCAD 的差距。
