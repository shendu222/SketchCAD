# 撤销栈差量化（出向变更集 + 周期检查点）设计分析

> 状态：已实现并通过自测（`--undo` 专项 **通过 1037 / 失败 0**，双目标 `-Wall -Wextra` 零警告，EXIT=0）
> 范围：`src/core/UndoDelta.{h,cpp}`（新增）、`src/core/SketchModel.{h,cpp}`（撤销栈重构）、
> `src/core/Element.{h,cpp}`（新增 `operator==`）、`AppSettings`/`OptionsDialog`/`MainWindow`（特性开关）、
> `tests/SketchSelfTest.cpp`（`t_undoDelta`，30+ 断言 + `--undo` 快速通道）

---

## 1. 问题定义

原撤销栈为**全量 Memento 快照**：每一步编辑把整张图（`elems_` + 全部随图属性）完整拷贝入栈。

- **内存**：5 万图元场景单步快照 ≈ 10~20 MB，默认 100 步栈深 → GB 级驻留；
- **拷贝**：每步 push 都要复制整张图，编辑越大图纸越卡。

目标：单步撤销内存 **≤1 MB**、撤销耗时 **≤16 ms**，行为与全量模式**逐字节一致**，且可用特性开关随时回落对照。

## 2. 方案总览（最终形态：出向差量 + 惰性封印）

```
undoStack_:  [CP(E0)+Δ(E0→E1)] [Δ(E1→E2)] ... [Δ(E49→E50)] [CP(E50)+Δ...] ...
              检查点(全量锚)     出向差量（只存该步操作的变更图元）   每 50 步落一个全量锚点

undo(): 弹出栈顶条目 → 逆向应用其出向差量（就地改 elems_）→ 条目原样进 redo
redo(): 从 redo 取回条目 → 正向应用其出向差量 → 条目原样压回 undo 栈
```

- **条目不变式**：undo 栈条目 `k` 代表状态 `E_k`（第 k+1 次操作前），并持有
  **出向差量** `Δ(E_k → E_{k+1})`——即「第 k+1 次操作」的变更集本身。
  撤销第 n 步 = 弹出条目 `n-1` 并逆向应用其出向差量；重做 = 正向应用后原样压回。
  检查点属性/快照随条目往返双栈自动保留，redo 无需重算 `%50`、无需重建差量。
- **惰性封印（lazy seal）**：push 发生在操作**之前**（捕获"改前"态），此刻出向差量尚不存在。
  push 只捕获 label + `auxBefore` + 基态 `pendingBase_`（一次 elems 深拷贝，与旧实现
  每次 push 的 `currentMemento()` 同价）；差量延迟到**下一次 push / undo** 时封印
  （`sealPendingStep`：`diff(pendingBase_, 当前)`），该差量在数学上恰好等于上一步操作的变更集。
- **O(变更数) 撤销/重做**：旧实现（入向差量）每步撤销需 `reconstructStep`（5 万元素向量
  detach 拷贝 ≈ 12ms）+ 全量 `makeDelta`（5 万次 `operator==` ≈ 20ms）+ 旧缓冲析构 ≈ 8ms
  → 39ms/步；新实现就地正/逆向应用单个变更集 → **0.48ms/步**（见 §6）。
- **差量内容**（`DeltaRecord`）：
  - 元素级 `ElementDelta{Op: Added/Removed/Modified, id, index, beforeJson, afterJson}`——
    序列化复用 `elementToJson/elementFromJson`，零新增格式（**约束：Element/SketchModel 既有序列化一字未动**）；
  - 随图属性（单位/界限/捕捉/追踪/布局/过滤器/样式表等）整段按值快照（`AuxState`），
    不做差量——占比极小，整段快照换来确定性。
- **定位策略（id 复用安全）**：删除/修改按 `id` 定位、插入按 `index` 定位
  （Added 存结果态序位、Removed 存源态序位），两个方向各自与自己的结果态对齐。
- `reconstructStep(idx)`（最近检查点 + 出向差量链回放）保留为工具函数，undo/redo 热路径不依赖它。

## 3. 关键设计决策

| 决策 | 选择 | 理由 |
|---|---|---|
| 差量方向 | **出向**（条目持有"离开自身状态"的变更集） | 撤销/重做降为 O(变更数)；入向差量每步撤销都要整图重建+全量 diff（实测 39ms） |
| 差量生成时机 | 惰性封印（下次 push/undo 时一次 diff） | push 在操作前、差量在操作后才存在；每次封印只 diff 一次，push 总成本不高于旧实现 |
| 检查点间隔 | 50 步 | 全量锚点（`snap = E_k`）按规格保留；出向差量链本身自足（逐条逆向即可无限回退），检查点降级为回放工具/安全锚 |
| 批量删除 | ≤8 条逐条 erase，>8 条「id 集合标记 + 原地单趟压缩」 | 逐条 erase 是 O(N²)：5 万条 Added 逆向回放实测 64s（见 §4 坑⑥） |
| 修改检测 | `Element::operator==` 成员比较 | JSON 编码只用于**记录**变更 payload，不用于**检测**（见 §4 坑①） |
| 无操作步 | 封印空差量 → push 原样早退（基态留给下步）；undo 遇空条目丢弃不消耗撤销步 | 与旧 `sameState` 去重逐字节对应（含"不清 redo""不 trim"两个细节） |
| aux 状态 | 整段按值快照 | 占比小、类型异构，差量化收益趋零、风险不对称 |
| 特性开关 | `AppSettings general/undoDelta`（默认开） | OptionsDialog 复选框 + `applySettingLive` 热切换；切换时清空双栈并复位封印状态 |
| 裁剪 | 双栈同限，保留队首检查点锚 | 出向链任意后缀自成体系（从当前态逐条逆向即可），裁剪正确性天然成立 |

## 4. 实现中踩到/避开的坑（血泪）

### ① 修改检测不能逐图元 JSON 序列化
初版 `diffElements` 对每个图元各做 `elementToJson().toJson()` 判"是否变了"——5 万图元每步
push 触发 10 万次 JSON 编码，测试卡死数分钟。修复：新增 `Element::operator==`（全字段成员比较），
仅对真正变化的图元序列化存 payload。
**纪律**：`operator==` 字段清单必须与 `elementToJson` 同源同步（两处已注释互指）。

### ② 栈不变式（本任务推导核心）
push 在操作**之前**捕获"改前"态 ⇒ n 步操作后旧栈条目 0..n-1 代表 E_0..E_{n-1}，**当前态 E_n 不在栈上**。
入向差量据此推出：undo 目标 = `reconstructStep(栈顶索引)`（误写 `栈顶-1` 会单步退两步）；
redo 不能把正向差量直接压回（栈顶将代表当前态，紧随的 undo 退化为空操作）。
**出向差量把这两个别扭一并消解**：每个条目自带"离开自己"的变更集，undo/redo 只是同一差量的
反/正两个方向应用，压回条目即恢复不变式，无需任何重建或重算。

### ③ 封印的时序等价性（无操作步四个角落）
`sealPendingStep` 返回空差量 ⟺ 上一步是无操作。逐一与旧 `sameState` 去重对齐：
- **push 时封印为空** → 原样早退：不建条目、不 trim、**不清 redo**（旧 dedup-return 在 clear 之前）；
  栈顶条目保持未封印、基态不变——下一步真实操作的变更集仍封进同一条目；
- **undo 时封印为空** → 丢弃该条目、不消耗撤销步、继续向下找最近的真实变更条目；
- **全撤为空** → 与空栈同路径 warn；
- **重做侧**：空条目不进 redo，故 redo 永远重放真实变更。
推演过"普通序列中夹 no-op / 撤销紧随 no-op / redo 后 no-op / 全空栈"四个角落，与旧行为逐一对齐。

### ④ 私有嵌套类型的访问边界
成员函数类外定义的**返回类型**不在类作用域查找 → 必须写 `SketchModel::Memento`；
匿名命名空间自由函数不能摸私有 `Memento`/`UndoStep` → 收敛为静态私有成员。

### ⑤ id 复用的定位策略
删除/修改按 id、插入按 index（Added 存结果态序位、Removed 存源态序位），
先 id 删改、后按 index 升序插入（降序+qBound 钳位在多元素重叠区间会错位）。
同 id 位置不同（乱序/同 id 删除后异位复用）必须拆 Removed+Added，坍缩成 Modified 会丢序。
`t_undoDelta` C 组双向 round-trip 专门回归。

### ⑥ 批量删除的 O(N²)（出向差量新引入、实测 64s）
出向差量使「整批新增」（批量载入一步 = 5 万条 Added）成为栈内真实条目；全撤到底时逆向应用
它 = 5 万次 `vector::erase`，每次 O(N) 尾段移动 → **64 秒**。修复：删除超阈值（8 条）改走
「id 集合标记 + 原地单趟压缩」，O(N) 且相对顺序不变（有序性保持，后续二分依旧有效）。
修复后该步 ≤12ms，整体平均 0.48ms。批量插入为升序逐条 `insert`，尾部追加场景摊还 O(1)，
中间批量插入保持逐条（未成为实测瓶颈，已留注释）。

### ⑦ 基准失真：载入步不能拆成几十个撤销步
首版 F 组把 5 万图元拆成 50 个 `beginEdit` 批量步，撤销末段要回放 117 万次 `elementFromJson`
（≈2.3s）——基准测的是自己的失真。改为**单步整体载入**（一次 beginEdit + 一次 Quiet 批量加），
等同真实"打开图纸"语义；超大差量随后被栈深裁剪自然淘汰，稳态栈内只剩小幅编辑差量。

### ⑧ 沙箱环境四坑（测试基建）
前台进程被快速 SIGTERM（长命令必须后台 + 文件落盘）；stderr 捕获损坏（FAIL 行丢失，日志一律
`> file 2>&1` 合并）；后台构建不继承前台 cwd（一律绝对路径）；QProcess 管道耗尽使全量自测的
golden/dwg 样本用例挂起 → 为 SketchSelfTest 增加 `--undo` 快速通道（只跑撤销相关 + 自检注册表），
秒级完成验收回路。

## 5. 与既有约束的对照

- **Element/SketchModel 序列化不动**：`elementToJson/elementFromJson` 零改动，只增 `operator==`；
- **撤销语义一致**：undo/redo 的字段写回与信号广播（`restoreAuxInPlace`）与 `restoreFromMemento`
  逐项一致（先算差异标志再写值、条件信号只在真变了时发、始终清空选择）；元素部分经
  `applyElementDeltas` 就地应用，C 组 round-trip + A 组逐层对照保证与全量模式全等；
- **Modify 层零挂钩**：`applyChanges` 经 `beginEdit`+Quiet 天然汇入 `pushMemento`，
  差量在封印点统一生成，既有 Change 翻译层语义不变；UndoGuard 抑制区的变更并入下一个
  封印条目（与旧 reconstruct-diff 的合并行为一致）；
- **联动同一步**：块/标注/填充联动在一次 `beginEdit` 内收集 → 单条 `DeltaRecord` → 单步撤销
  （D 组断言 `undoStackSize()==1`）。

## 7. 自测覆盖（t_undoDelta，30+ 断言）

- **A 差量 vs 全量**：同一随机 500 步序列（增/删/改/静默批量/aux）双模式并行，
  编辑后、撤销逐层、重做逐层三段全程 `modelsEquivalent`（id+JSON 字节+aux），步数严格相等；
- **B 检查点回放**：120 步跨第 50 步检查点边界，撤销/重做 70 步两模式一致；
- **C 差量引擎单元**：同位 id 复用（Modified）、删除后新建（Removed+Added）、乱序 reorder
  （慢路径保序）、删+改+增混合，双向 round-trip 全部逐字节对照；
- **D 复合步/联动**：一次 beginEdit 多操作合并单步（`undoStackSize()==1`），单步撤/重做整组还原；
- **E 模式切换**：`setUndoDeltaEnabled` 清空撤销/重做历史（含封印状态复位）；
- **F 基准**：5 万图元单步整体载入 + 200 步编辑，`maxDeltaEntryBytes() ≤ 1MB`、
  `< 全量快照/5`、平均撤销耗时 ≤16ms、栈深收敛（≤上限且 ≥50 步）；
- **G 基本语义**：单步增 → 撤销 → 重做。
另：`SketchSelfTest --undo` 快速通道（撤销专项 + 注册表自检），秒级验收回路。

## 8. 已知边界与后续

- 每次封印（即每次编辑）仍是 O(N) 成员比较 + 一次 elems 深拷贝（基态捕获）；5 万图元实测
  单步编辑 ~30ms 内，无感。若图元规模再上台阶，可挂脏标记（mutation hook）把封印降为 O(变更数)；
- 批量**中间位置**插入保持升序逐条 `insert`（O(N)/条）：尾部批量（批量载入/redo 整批新增）
  已摊还 O(1)，中间批量未成为实测瓶颈，如需要可改「分组区间拼接」；
- 检查点快照（每 50 步一张全量）在出向差量架构下不再被 undo/redo 消费，仅作为
  `reconstructStep` 回放工具与安全锚保留；如需进一步压缩内存，可把检查点改为可选（关掉后
  栈内存再省 ~2×全量快照），行为不变；
- 重做栈条目随撤销原样往返，深度天然受撤销次数约束；`trimRedoStackToLimit` 逻辑保留为兜底；
- 全量自测（无参）在本沙箱受 QProcess 管道耗尽影响会卡在 golden/dwg 样本用例（既有环境问题，
  非本次引入）；`--undo` 快速通道 EXIT=0 为本次验收口径，正式环境建议复跑 `build.sh test`。
