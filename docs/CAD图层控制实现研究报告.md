# CAD 图层控制实现研究报告

> **摘要**：图层（Layer）是 CAD 数据模型中最基础、也最容易被低估的组织与属性管理机制。本文从工程实现角度系统论述图层控制：首先剖析其基本原理与核心机制（归属、继承、可见性、锁定、打印、状态），继而给出关键算法及其设计思路（属性解析、继承策略、批量索引、冻结剪枝、撤销事务等），随后梳理主要实现方法与技术路线（存储、分层架构、渲染集成、事件同步、互操作），最后归结图层控制应具备的功能特性，并结合一个快照式解耦的工程实现案例加以印证。
>
> **关键词**：CAD；图层；BYLAYER；属性解析；可见性；撤销事务；DXF；GB/T 14665

---

## 一、引言

在 CAD 系统中，图元（entity）并非孤立存在，而是被组织在若干"图层"之中。图层最早是作为一种**图形属性分组容器**出现的：把颜色、线型、线宽等显示属性，以及可见性、锁定、打印等控制开关，从"每个图元各存一份"上收为"按类别集中管理"。

这一设计的价值随着图纸规模增长而急剧放大。一张机械装配图或建筑平面图可能包含数万乃至数十万图元；若没有图层，任何"隐藏标注""只打印轮廓""统一改颜色"的需求都会退化为全图纸遍历与逐图元修改。图层把这类操作从 **O(N)** 降为 **O(1) 改定义 + O(k) 受影响图元的局部刷新**，这正是其工程意义所在。

本文以"原理 → 算法 → 实现 → 功能"为主线展开。为增加可信度，文中以一个真实的自研 CAD 系统（后文称为 **SketchCAD**）的图层子系统作为工程案例，其采用"快照式解耦"策略，与 AutoCAD 的"BYLAYER 引用式"形成有意义的对照。

## 二、图层控制的基本原理与核心机制

### 2.1 图层的本质：属性分组容器

从数据结构看，图层是一组**命名的属性集合**：

```
Layer {
    name        : 唯一标识（字符串，图纸内不可重复）
    color       : 默认颜色（可为 ACI 索引色或真彩色）
    lineType    : 默认线型（实线/虚线/点划线…）
    lineWeight  : 默认线宽
    visible     : 显示/隐藏（整层）
    frozen      : 冻结/解冻（整层，且不参与重生成）
    locked      : 锁定/解锁（禁止编辑，但可见、可捕捉）
    plottable   : 是否参与打印
    lineWidth   : 打印线宽（可与显示线宽分离）
}
```

图元通过一个**归属字段**（通常就是图层名）与图层建立联系。于是"图元属性"的最终值取决于两个来源：图元自身的显式值与所属图层的默认值。二者如何组合，就引出下一节的解析模型。

### 2.2 CAD 数据模型中的图层表与图元归属

成熟 CAD 采用**符号表（Symbol Table）**统一管理命名对象，图层表（Layer Table）是其中一张。图元并不内嵌完整图层副本，而是**引用**图层（在 DXF 中以图层名字符串表达，在内存中通常是指针或索引）。

```
图纸文档
 ├── 符号表集合
 │    ├── 图层表  ── [ "0", "轮廓", "标注", "剖面线", … ]
 │    ├── 线型表
 │    ├── 文字样式表 …
 └── 图元集合
      ├── Line   { layer: "轮廓", color: BYLAYER, … }
      ├── Circle { layer: "轮廓", color: 0xFF0000(显式红), … }
      └── Text   { layer: "标注", color: BYLAYER, … }
```

**归属是单向的**：图元知道自己在哪层，图层不必记录自己包含哪些图元（反向索引可作为性能优化另行维护，见 §3.4）。

### 2.3 属性解析模型：BYLAYER 与 BYOBJECT

这是图层控制的理论核心。对一个属性 $p \in \{\text{color}, \text{linetype}, \text{lineweight}\}$，图元可以处于两种状态：

- **BYLAYER（随层）**：属性的取值"延迟"到解析时从图层读取，图元本身不存值；
- **BYOBJECT / 显式（独立）**：图元存有自己的取值，与图层无关。

解析函数可形式化为：

$$
p_{\text{eff}}(e) =
\begin{cases}
e.p, & \text{若 } e.p \neq \text{BYLAYER} \ (\text{显式值}) \\[4pt]
L(e.\text{layer}).p, & \text{若 } e.p = \text{BYLAYER} \ (\text{取图层值})
\end{cases}
$$

其中 $L(\cdot)$ 为按名查图层表。该模型的关键性质：

1. **延迟解析**：改图层属性无需遍历图元即可"立刻"影响所有 BYLAYER 图元——因为它们本就没存值；
2. **单值来源（Single Source of Truth）**：颜色/线型的唯一真值在图层表，避免数据漂移；
3. **粒度可控**：可做到"颜色随层，但线宽独立"这类按属性混合。

AutoCAD/DXF 对此有明确约定：颜色 BYLAYER = `256`、BYBLOCK = `0`；线型为 `"ByLayer"` / `"ByBlock"`；线宽 BYLAYER = `-1`、BYBLOCK = `-2`、DEFAULT = `-3`。

> **与"快照式"的对照**：也存在另一种实现——图元创建时把图层属性**拷贝**为自身值（BYOBJECT 快照），此后与图层解耦。它牺牲了"改层即时生效"，换来了"改层绝不回溯影响既有图元"与"单图元完全独立"。两种策略的算法对比见 §3.2，工程案例见 §4.8。

### 2.4 六大核心机制

| 机制 | 含义 | 关键实现点 |
|---|---|---|
| **归属** | 图元 → 图层（单值引用） | 归属字段唯一、改名/删层时的一致性维护 |
| **继承** | 新建图元默认采用当前层属性 | 创建路径收敛到单一工厂；"当前活动层"状态 |
| **可见性** | 整层显示控制 | off/on（仅不绘制）与 freeze/thaw（不绘制且不重生成）语义不同 |
| **锁定** | 禁止编辑但保留显示与捕捉 | 命中检测/编辑入口统一门控 |
| **打印** | 控制出图与打印线宽/颜色映射 | plot/no-plot、CTB/STB 打印样式表 |
| **状态** | 保存/恢复一整套图层配置 | 图层状态（Layer State）序列化 |

其中**可见性的两种语义**常被混淆，值得展开：

- **关闭/打开（Off/On）**：图层被关闭时不绘制，但**仍参与图形重生成（regen）、仍计入范围（extents）与裁剪**。适合"临时让某层不显示"。
- **冻结/解冻（Freeze/Thaw）**：图层被冻结时**既不绘制也不参与重生成**，从显示列表与包围盒计算中剔除。适合"长期不看的层"，可显著提升大图纸性能。

此外还有**视口级冻结（VP Freeze）**：仅在图纸空间的某个视口中冻结图层，实现"同一模型、不同视图不同显示"。

### 2.5 空间层次：模型空间、图纸空间与视口覆盖

现代 CAD 具有两级空间：

- **模型空间（Model Space）**：设计对象的真实几何；
- **图纸空间（Paper Space）/ 布局**：用于排版出图，通过**视口（Viewport）**映射模型。

由此产生"图层属性优先级链"：模型空间层的定义是**基线**，视口可对其施加**覆盖（VP Override）**，解析时优先级为

$$
\text{VP Override} \;\succ\; \text{模型层定义} \;\succ\; \text{默认值}
$$

这把"可见性/颜色/线型的控制维度"从"图层"扩展为"图层 × 视口"，是图层控制复杂度的一个重要来源。

### 2.6 与 DXF/DWG 标准的对应

图层控制必须能与行业格式互操作。以 DXF 为例：

- 图层定义存于 `LAYER` 表，每个表项是一个 `LAYER` 记录；
- 图元归属由**组码 `8`**（图层名）表达；
- 图层颜色组码 `62`（ACI；**负值表示图层关闭**）、真彩色 `420`；
- 线型组码 `6`、线宽组码 `370`；
- 图层标志组码 `70`：bit0 冻结、bit2 视口默认冻结、bit4 锁定；
- 可打印性组码 `290`。

因此"图层控制"在实现上必须至少覆盖：表结构的读写、组码的语义映射、以及 BYLAYER 解析在导出时的**固化（flatten）**（因为 DXF 某些实体需写出解析后的实际颜色）。

## 三、关键算法与设计思路

### 3.1 属性解析算法（延迟解析）

**设计目标**：改一次图层定义，所有 BYLAYER 图元立即生效；且不必遍历图元。

```cpp
// 解析单个属性的有效值（延迟解析）
Color effectiveColor(const Entity& e, const LayerTable& lt) {
    if (e.color != BYLAYER) return e.color;      // 显式覆盖优先
    const Layer* L = lt.find(e.layer);           // 按名 O(1)
    return L ? L->color : DEFAULT_COLOR;         // 缺失兜底
}

double effectiveLineWeight(const Entity& e, const LayerTable& lt) {
    if (e.lineWeight != BYLAYER) return e.lineWeight;
    const Layer* L = lt.find(e.layer);
    return L ? L->lineWidth : 0.25;
}
```

**思路要点**：
- **查找用哈希表**（`unordered_map` / `QHash`），使 $L(\cdot)$ 为期望 $O(1)$；
- **解析发生在消费侧**（渲染、导出、查询），而非每次写模型时；
- **兜底策略**明确（图层缺失时回退默认值），避免空指针与脏数据。

### 3.2 两种继承策略：引用式 vs 快照式

这是图层控制实现中最重要的架构分叉。两者的区别在于"新建图元时如何对待图层属性"。

**策略 A：引用式（BYLAYER，AutoCAD 模型）**

```cpp
Entity create(...) {
    Entity e;
    e.layer = currentLayer;    // 只记归属
    e.color = BYLAYER;         // 值不落地，延迟解析
    e.lineType = BYLAYER;
    e.lineWeight = BYLAYER;
    return e;
}
// 改图层属性：仅改图层表，无需触碰任何图元
void setLayerColor(Layer& L, Color c) { L.color = c; /* 完毕 */ }
```

**策略 B：快照式（BYOBJECT，解耦模型）**

```cpp
Entity create(...) {
    Entity e;
    e.layer = currentLayer;
    if (currentLayer != "0") {
        const Layer* L = findLayer(currentLayer);
        if (L) {                       // 一次性值拷贝（快照）
            e.color     = L->color;
            e.lineType  = L->lineStyle;
            e.lineWeight= L->lineWidth;
            e.byObject  = true;        // 标记为"独立"
        }
    }
    return e;
}
// 改图层属性：仅改图层表，既有图元因已快照而"纹丝不动"
void setLayerColor(Layer& L, Color c) { L.color = c; /* 已有图元不受影响 */ }
```

**对比分析**：

| 维度 | 引用式 BYLAYER | 快照式 BYOBJECT |
|---|---|---|
| 改层即时生效 | ✅ 是 | ❌ 否（只影响此后新建） |
| 既有图元稳定性 | 低（会随之变化） | 高（解耦，不变） |
| 单图元完全独立 | 需显式设非 BYLAYER | 天然独立 |
| 存储开销 | 小（只存标志） | 略大（存值副本） |
| 数据一致性风险 | 低（单一真值） | 中（值可能漂移，需保证创建时正确快照） |
| 典型场景 | 需要"统一风格随层联动" | 需要"改层不回溯、逐图元可控" |

> **设计判据**：若系统的核心诉求是"图层即风格，一处改处处变"，选引用式；若是"图元一经创建即定格，图层只作新图元的取值来源"，选快照式。二者并非互斥，可组合（见 §3.3）。

### 3.3 混合式：per-property BYLAYER 标志

自由度最高的是混合模型：**每个属性各带一个 `BYLAYER` 标志位**，解析时逐属性判定。

```cpp
struct AttrRef { bool byLayer; Value local; };

Value resolve(const AttrRef& a, const Layer& L, Value dflt) {
    return a.byLayer ? L.value : (a.local ? a.local : dflt);
}
```

这样可表达"颜色随层、线宽独立""线型随层、颜色独立"等任意组合，代价是每个属性多一位标志与一次分支判断。UI 上表现为属性面板里每个属性的"随层/独立"开关。

### 3.4 批量操作与反向索引

图层可见性切换、批量赋色等操作需要"本层全部图元"的高效枚举。若每次全量扫描图元集合，规模 $N$ 时批量操作退化到 $O(N)$。**反向索引**（图层 → 图元索引列表）可将其降为 $O(k + c)$，$k$ 为本层图元数、$c$ 为索引维护成本。

```cpp
class LayerIndex {
    unordered_map<string, vector<int>> layerToElems; // 层名 → 图元 id 列表
public:
    void rebuild(const vector<Entity>& es) {
        layerToElems.clear();
        for (int i = 0; i < (int)es.size(); ++i)
            layerToElems[es[i].layer].push_back(i);
    }
    const vector<int>& of(const string& l) { static vector<int> e; auto it=layerToElems.find(l); return it==layerToElems.end()?e:it->second; }
};
```

**维护时机**：图元增删、重归属（move to layer）时增量更新；批量操作前若担心脏数据可重建。**遍历时的关键不变量**：任何批量图层操作只应触碰 `e.layer == 目标层` 的图元，其他层"互不干扰"。

### 3.5 冻结与可见性剪枝算法

可见性控制不只是"跳过绘制"，更需要**剪枝**：

```
渲染/重生成管线（含剪枝）：
  1. 收集候选图层集合 S = 可见 ∧ 未冻结 的图层
  2. for each entity e:
        if e.layer ∉ S: continue          # 剪枝：不进入后续几何处理
        if e.layer.frozen: skip bbox extents  # 冻结层不计入范围
        resolveStyle(e); buildDisplayList(e)
```

- **off 层**：仅在第 2 步跳过绘制，但**仍计入 extents / 命中测试**（若实现如此约定）；
- **freeze 层**：从第 1 步即排除，连**包围盒与重生成**都省去——大图纸下这是数量级的性能差异。

### 3.6 图层查找与过滤算法

- **唯一键查找**：图层名 → 图层对象，哈希表 $O(1)$；重名在创建时拒绝。
- **通配符/过滤器**：`*`、`?`、`[ ]` 等模式匹配（AutoCAD 风格的图层过滤器），可预编译为正则或自定义匹配器。
- **组合过滤**：属性谓词（颜色=红 ∧ 已关闭）与名称模式可组合为过滤器树，用于图层管理器批量选择。

### 3.7 撤销/重做：命令模式与快照

图层操作必须可撤销，通常两种实现：

```text
命令模式（Command）：
  LayerCommand { Layer 前像; Layer 后像; execute(); undo(); }
  适合"定义变更"类操作，内存占用小、精确。

快照/Memento：
  pushMemento("修改图层样式")  → 保存受影响对象集合的完整状态
  适合"批量改图元 + 改层定义"混合事务，实现简单、回退彻底。
```

工程上常采用"**事务（Transaction）**"封装：进入事务压一份 memento，操作完成后提交，撤销时整体回退。粒度可调（单层操作 = 一次事务）。

### 3.8 重归属、合并与删除的迁移算法

当图元改层、图层被删除或合并时，需保证归属一致：

```text
moveToLayer(ids, target, adoptStyle):
    for id in ids:
        e = find(id)
        e.layer = target
        if adoptStyle: applyLayerStyle(e, L(target))   # 可选：采纳目标层样式
    # 只改指定 id，其他图元不变

removeLayer(name):
    if name == "0": reject                          # 默认层不可删
    for e in elements: if e.layer == name: e.layer = "0"   # 回落默认层，保留各自属性
    eraseLayerDef(name)
    if currentLayer == name: currentLayer = "0"     # 活动层回落

renameLayer(old, new):
    if old == "0": reject
    layerDef(old).name = new
    for e in elements: if e.layer == old: e.layer = new     # 归属迁移
    if currentLayer == old: currentLayer = new              # 活动层同步
```

**设计要点**：删除图层时图元"**回落默认层并保留各自属性**"是安全且符合直觉的选择；切勿连带删除图元。

### 3.9 视口覆盖的优先级解析（图纸空间）

在存在视口覆盖时，解析函数需带上"当前视口"上下文：

```cpp
Style resolveInViewport(const Entity& e, const Layer& L, const Viewport* vp) {
    Style s = baseResolve(e, L);                       // 模型层基线
    if (vp) s = vp->overrideFor(e.layer, s);           // 视口覆盖优先
    return s;
}
```

这使同一图元在不同视口中呈现不同颜色/线型/可见性，是图纸空间图层控制的必备能力。

## 四、主要实现方法与技术路线

### 4.1 数据存储与持久化

| 层次 | 方案 | 说明 |
|---|---|---|
| 内存 | `vector<Layer>` + 图元 `layer` 字段；查找用哈希表 | 顺序存储利于面板枚举，哈希利于解析 |
| 文件（原生） | 自定义 JSON/二进制 | 需带格式版本号，向前兼容 |
| 文件（互操作） | DXF `LAYER` 表 / DWG | 组码语义映射；导出时可能需固化 BYLAYER |
| 数据库 | SQLite/RDBMS | 图层表 + 图元表，适合协同/版本管理 |

### 4.2 架构分层（Model–View–Controller）

```
    ┌────────────────────────────────────────────┐
    │  View  图层面板 / 属性面板 / 视口渲染         │
    └───────────────▲───────────────┬────────────┘
        信号(变更通知)│               │命令(用户操作)
    ┌───────────────┴───────────────▼────────────┐
    │  Controller  命令/事务/交互逻辑（守卫锁定等） │
    └───────────────▲───────────────┬────────────┘
                    │               │
    ┌───────────────┴───────────────▼────────────┐
    │  Model  图层表 + 图元集合 + 属性解析 + 索引   │
    └────────────────────────────────────────────┘
```

- **Model 负责规则**：属性解析、批量操作不变量、活动层状态、索引维护；
- **View 只读消费**：面板按模型枚举，视口按解析函数绘制；
- **Controller 收敛入口**：所有图层操作经命令层，便于撤销与权限（锁定）校验。

### 4.3 渲染管线集成

```
帧/重生成：
  ① 图层剪枝（可见 ∧ 未冻结）
  ② 对每个可见图元：解析样式（延迟解析）
  ③ 构建/复用显示列表（线宽换算、线型图案）
  ④ 绘制（含绘制顺序 draw order）
事件：
  layerChanged → 失效相关缓存 → 触发重绘（可增量）
```

**性能优化点**：把"图层 → 可见性/样式"的解析结果缓存为**按图层批处理的绘制状态**（同层图元共享一个画笔），减少状态切换。

### 4.4 事件驱动同步（观察者 / 信号槽）

图层变更需要同步面板显示与视口重绘。典型做法是**观察者模式**：模型发信号，面板与视图各自响应。

```cpp
// 模型侧
void setCurrentLayer(const QString& n) {
    if (!hasLayer(n)) return;          // 守卫
    if (currentLayer_ == n) return;    // 短路，避免无谓重绘
    currentLayer_ = n;
    emit currentLayerChanged(n);       // 通知
}
// 视图侧
connect(model, &Model::currentLayerChanged, view, [view]{ view->viewport()->update(); });
// 面板侧
connect(model, &Model::currentLayerChanged, panel, [panel]{ panel->refresh(); });
```

**设计要点**：信号 + 短路判断，既保证"实时刷新"，又避免"刷新回路"与无谓重绘。

### 4.5 事务与撤销栈

所有会改模型状态的图层操作都进入事务：`beginEdit(名字) → 改动 → 提交`。撤销时整体回退。这样"改图层样式/批量赋色/移入图层"等都成为可 `Ctrl+Z` 的原子操作。

### 4.6 索引与缓存策略

- **反向索引**（§3.4）：加速批量操作；
- **解析缓存**：图层定义未变时复用解析结果，用版本号/脏标记失效；
- **显示列表缓存**：几何不变时复用 tessellation，避免每帧重建。

### 4.7 标准与互操作

- **国家标准**：如 GB/T 14665-2012 表6 给出"图线的分层标识"（粗实线、细实线、虚线、点画线、尺寸线、剖面符号、文本等 12 类标准层及建议线型），可作为标准图层模板预置，便于按标准标识分层出图；
- **DXF 互操作**：组码映射（§2.6）、BYLAYER 固化（导出时写实际值）、中文编码（`$DWGCODEPAGE`）。

### 4.8 工程案例：SketchCAD 的快照式解耦方案

SketchCAD 采用**快照式（BYOBJECT）**策略，其要点可作为"解耦型"实现的范例：

**（1）单一创建入口保证继承一致**

所有交互绘制、命令行绘图、智能标注都经同一工厂：

```cpp
Entity ElementFactory::create(ElementType t, const QString& name, const Model* m) {
    Entity e; e.type = t; e.name = name;
    if (m) {
        m->applyDefaultStyle(e);   // 全局默认色/线型；线宽随线型自动
        m->applyActiveLayer(e);    // 归属活动层 + 快照其属性
    }
    return e;
}
void Model::applyActiveLayer(Entity& e) const {
    const Layer* L = (currentLayer_ == "0") ? nullptr : findLayer(currentLayer_);
    if (!L) { e.layer = "0"; return; }      // 兜底
    e.layer = currentLayer_;
    e.color = L->color;  e.lineType = L->lineStyle;  e.lineWeight = L->lineWidth;
    e.lineWeightByLayer = false;            // 继承来的值视为固定
}
```

**（2）默认层"0"特例**：活动层为默认层时不覆盖默认样式，保留"工具栏默认色 + 线宽自动追随线型"的既定手感。

**（3）解耦集中在唯一变更入口**：图层属性变更**只改图层定义**，不触碰任何既有图元——

```cpp
void Model::setLayerStyle(const QString& name, Color* c, double* w, LineType* ls) {
    Layer* L = findLayer(name);
    if (!L) return;
    beginEdit("修改图层样式 " + name);
    if (c) L->color = *c;  if (w) L->lineWidth = *w;  if (ls) L->lineStyle = *ls;
    emit layersChanged(); emit modelChanged();
    // 无任何遍历图元的推送 —— 既有图元属性保持不变
}
```

此后新建图元经 `applyActiveLayer` 自动获得新属性，**天然满足"仅新建图元应用新属性"**。

**（4）显式同步作为"逃生舱"**：另设 `applyLayerStyleToElements(name)`，供用户主动把图层当前样式**一次性套用**到本层全部图元（面板"应用样式"按钮 / `layer apply <名>`），与自动解耦互不冲突。

**（5）活动层与实时可视化**：视口右上角以覆盖层绘制"当前图层"徽标（图层色块 + 名称），采用**视口像素坐标**绘制，**不随缩放/平移漂移**，且不计入图形包围盒（不参与 fit/zoom）；切层即由信号触发重绘。

这一案例说明：解耦型实现的关键在于**把"不推送"这一约束收敛到唯一的变更函数**，并让创建路径的快照逻辑自然承接"新建继承新属性"。

### 4.9 技术选型权衡表

| 决策点 | 选项 | 建议 |
|---|---|---|
| 继承语义 | 引用式 / 快照式 / 混合式 | 依核心诉求定；需"逐图元独立 + 改层不回溯"选快照式 |
| 查找结构 | 线性 / 哈希 | 图层数 > 数十即上哈希 |
| 批量枚举 | 全扫描 / 反向索引 | 大图纸上反向索引（或空间索引） |
| 撤销实现 | 命令 / memento | 混合事务用 memento 更稳 |
| 可见性语义 | 单档 / off+freeze 双档 | 追求性能须区分 freeze |
| 视口覆盖 | 支持 / 不支持 | 需要多视图出图须支持 |

## 五、图层控制应具备的功能特性

### 5.1 基础管理
- 新建、删除、重命名图层；默认层（通常为 `"0"`）**不可删除/改名**；
- 图层唯一命名与合法性校验（去空白、非空、查重）；
- 图层列表枚举与排序（按名/按属性）。

### 5.2 属性与继承
- 每层持有颜色/线型/线宽默认值；
- **属性继承**：新建图元默认采用当前（活动）层属性；
- **属性覆盖**：单个图元可显式覆盖为独立值，且**不被图层变更回溯修改**（解耦）；
- *（增强）* 按属性粒度的"随层/独立"切换（BYLAYER/BYOBJECT）。

### 5.3 可见性与显示控制
- 整层显示/隐藏（on/off）；
- *（增强）* 冻结/解冻（freeze/thaw，含重生成剪枝）；
- *（增强）* 视口级冻结/覆盖（VP Freeze/Override）；
- 隔离（Isolate）：只显示选中图元所在层；隐藏其余（Hide Others）；
- 图层漫游（Layer Walk）：逐层预览。

### 5.4 编辑与选择控制
- 锁定/解锁：锁定层可见、可捕捉，但**禁止编辑**；
- 锁定应在**所有编辑入口统一门控**（拖拽、删除、属性修改、命令行）；
- 选择过滤：仅可选择可见/未锁定层的图元。

### 5.5 打印与输出控制
- 每层可打印/不可打印（plot/no-plot）；
- 打印线宽与显示线宽可分离；
- 打印样式映射（颜色相关 CTB / 命名 STB）；
- 导出时 BYLAYER 属性的固化与组码正确写出。

### 5.6 状态与配置管理
- 图层状态（Layer State）：保存/恢复一整套"图层 × 开关 × 属性"配置；
- 图层模板/标准层预置（如 GB/T 14665 表6 的 12 类标准层）；
- 状态可导入/导出、随图纸存盘。

### 5.7 组织与检索
- 图层过滤器（名称通配/属性谓词/组合树）；
- 分组与搜索；
- 批量选择、批量改属性、批量移入图层；
- 合并图层、清理未使用图层（PURGE）。

### 5.8 一致性与可维护性（工程特性）
- **归属一致性**：改名/删层/合并时图元归属正确迁移或回落；
- **活动层一致性**：删层/改名时活动层同步回落或改名；切换不存在的层被拒绝；
- **撤销/重做**：图层操作可原子撤销；
- **变更通知**：图层变更实时驱动 UI 与重绘，避免脏显示；
- **可扩展**：支持自定义图层属性元数据（如阶段、注释、状态）。

### 功能特性清单（汇总）

| 类别 | 特性 | 优先级 |
|---|---|---|
| 基础 | 新建/删除/改名/枚举 | 必备 |
| 属性 | 颜色/线型/线宽默认值、继承、覆盖 | 必备 |
| 活动层 | 当前绘图层切换与实时显示 | 必备 |
| 可见性 | on/off、隔离、隐藏其余 | 必备 |
| 可见性 | freeze/thaw、VP 冻结、图层漫游 | 进阶 |
| 编辑 | 锁定、选择过滤 | 必备 |
| 打印 | 可打印性、打印线宽、CTB/STB | 进阶 |
| 状态 | 图层状态保存/恢复、标准层模板 | 进阶 |
| 组织 | 过滤器、分组、合并、PURGE | 进阶 |
| 工程 | 一致性维护、撤销、变更通知、扩展性 | 必备 |

## 六、结论与展望

图层控制是 CAD 系统的骨架之一，其实现质量直接决定大图纸下的可用性与性能。本文的结论可归纳为三点：

1. **理论核心是"属性解析模型"**——BYLAYER 的延迟解析把"统一风格"的代价降到最低，而快照式解耦则把"逐图元独立性"做到极致；两条路线各有适用场景，混合模型提供了最大自由度。
2. **算法关键在于"局部性与索引"**——批量操作只触碰本层图元，配合反向索引与冻结剪枝，把复杂度从 $O(N)$ 压到 $O(k)$。
3. **工程关键是"收敛入口与一致性维护"**——把继承逻辑收敛到唯一创建入口、把变更逻辑收敛到唯一变更函数（并在此处落实"解耦"或"推送"语义），同时在改名/删层/合并处维护归属与活动层一致性，并保证可撤销与实时通知。

**展望**：随着 BIM/协同设计的普及，图层控制正从"单图纸内的显示开关"演化为"跨专业、跨视图、跨版本的信息组织维度"。未来值得深入的方向包括：图层与视口/阶段/专业的多维交叉控制、基于图层语义的自动化出图与合规检查、以及图层模型在协同环境下的冲突消解与增量同步。
