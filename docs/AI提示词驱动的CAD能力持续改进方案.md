# AI 提示词驱动的 CAD 能力持续改进方案（V2）

> 适用范围：SketchCAD（`sketch-cad-cpp/`）**全部代码由 AI 生成**的开发模式
> 与 V1 的关系：V1（`二维CAD差距分析与AI编程实施方案.md`）的 §1 **差距清单是本方案的任务来源**，本方案替代其 §2「按开发阶段划分」的组织方式
> 差距项编号（如 1.4.1）均指 V1 §1 中的条目

---

## 0. 为什么要从"阶段划分"重构为"提示词驱动"

| 维度 | V1 阶段划分 | V2 提示词驱动 |
|---|---|---|
| 组织轴 | 时间（P0/P1/P2/P3，月为单位） | 目标类型（新增功能 / 缺陷修复 / 性能优化 / 稳定性提升） |
| 核心资产 | 里程碑与交付物 | **提示词库 + 验证闭环**（可复用、可版本化、可度量） |
| 瓶颈 | 人力排期 | **提示词质量** 与 **反馈收敛速度** |
| 进度度量 | 完成百分比 | 步骤吞吐 + 一次通过率 + 平均收敛轮次 |
| 适合场景 | 人写代码 | 全部代码 AI 生成 |

**核心判断**：AI 生成代码时，"实现过程"不再是需要人来规划的部分；人真正要交付的是——**把目标、约束、边界、验收说清楚**。因此每一步的产出物不是"代码怎么写的说明"，而是**一组可复用、可回填、可验证的提示词**。

## 1. 提示词体系架构（四层 + 复用机制）

### 1.1 四层结构

| 层 | 名称 | 定位 | 变更频率 | 存放 |
|---|---|---|---|---|
| **L0** | 基础系统提示词（Base） | 全局恒常：项目身份、技术栈、代码风格、硬约束、禁改清单 | 极低频（季度） | `prompts/base/system.md` |
| **L1** | 模块提示词（Module） | 按子系统锁定上下文：职责边界、核心文件、既有 API、该模块特有约定 | 低频（模块重构时） | `prompts/modules/{geometry,formats,render,model,dim,section,block,xref,layer,commands,ui,perf}.md` |
| **L2** | 任务类型提示词（Task） | 新增功能 / 缺陷修复 / 性能优化 / 稳定性加固 / 回归校验 的通用骨架 | 中频（方法论改进时） | `prompts/tasks/{feature,bugfix,perf,stability,verify}.md` |
| **L3** | 反馈回填提示词（Feedback） | 把编译错误、失败断言、性能数据、评审意见结构化回填 | 每次迭代 | `prompts/feedback/{compile,test,perf,review}.md` |

### 1.2 组合公式

```
本次提示词 = L0 基础系统提示词
           + L1 模块提示词({{MODULE}})
           + L2 任务提示词({{TASK_TYPE}})
           + 上下文包 {{CTX}}（头文件 / 同类实现样例 / 同类测试样例 / 相关差距项）
           + 本步六要素 {{GOAL, CONSTRAINTS, IO_SPEC, ACCEPT, FORBID}}
           + [可选] L3 反馈包 {{FEEDBACK}}
```

### 1.3 复用机制

1. **变量化模板**：所有可变部分用 `{{双花括号}}` 占位，运行前填充，便于 diff 与版本对比。
2. **上下文包（Context Pack）固定化**：每个模块预定义"必注入文件清单"，避免每次临时挑文件导致上下文漂移。
   - 例：`formats` 模块必注入 `CadFormats.h`、`Element.h`、`Block.h`、`tests/dxf_import_test.cpp`。
3. **提示词入库与版本化**：每个提示词文件带 YAML 元信息头（见 §6.2），变更需评审。
4. **交叉复用**：同一 L2 任务骨架 + 不同 L1 模块 = 新步骤（如"新增功能骨架"套到 `commands` 模块即生成 EXTEND 命令步骤）。
5. **失效标记**：绑定的测试失败或代码重构后，对应提示词标记 `stale`，必须复核后才能再用。

## 2. 提示词六要素规范（每类提示词必含）

| # | 要素 | 必含内容 | 本项目具体化（写进 L0，不重复口述） | 典型反例 |
|---|---|---|---|---|
| 1 | **目标描述** | 一句话目标 + **非目标（Out of Scope）** | "新增 DIMENSION 实体导入"；非目标："不改动渲染、不改标注样式体系" | 只写"优化导入"，AI 顺手改了渲染 |
| 2 | **项目上下文与已有代码约束** | 模块职责、核心文件、既有 API 清单、项目级铁律 | 见下方"项目铁律清单" | 让 AI 自己猜目录结构 |
| 3 | **技术栈与代码风格** | C++17/Qt6、命名、注释语言、依赖方向、错误处理风格、事务风格 | 见下方"风格清单" | 出现 `printf`/裸 `new`/混用 `std::cout` |
| 4 | **输入输出规范** | 函数签名、JSON/存档字段、命令语法、日志文案、返回码 | `bool xxx(..., QString* err)`；失败 `log(msg,"warn")` 并返回 `false`/`-1` | 返回值语义不一致 |
| 5 | **验收标准** | 断言数量与类型、测试 target、CMake 注册、黄金样本、性能阈值、全量回归 | 新模块 ≥ 8 断言且含退化用例；38 个 exe 全 exit 0 | 只说"要正确" |
| 6 | **禁止改动范围** | 枚举顺序、存档语义、公共 ABI、既有断言、国标参数表、构建配置、第三方依赖 | 见下方"禁改清单" | 为让测试通过而修改断言 |

**项目铁律清单（写进 L0）**
- 枚举**只增不改**（`ElementType` / `DimensionType` / `SectionMaterial` 以整数存盘）；新增字段须保证旧档字节级兼容（新键条件写入）。
- 一次操作**只 `pushMemento` 一次**；`Change` 契约：`applyChanges` 只认 `replacement.id` 为 update。
- `nextId_` 从 1 开始，**id=0 永不存**；未知 id 的 `updateElementQuiet` 静默失败。
- 几何计算**只能调用既有 `Geometry.h` / `Modify.h` / `Section.cpp` 原语**，禁止自造几何算法。
- 定义内 `entities`（块/动态块）**不可局部增删改**（索引引用），清理以整份 `BlockDef` 为单位。
- 新增图元类型需同步 8 处（Element 枚举 / sizeDesc / 字段 / Factory / JSON 双向 / View 绘制 / distanceToElement / CMake）。
- 新增菜单项须同步 `ModifyMenuTest` 期望并带图标。

**风格清单（写进 L0）**
- C++17 + Qt 6.10.1；前缀下划线成员命名（`model_`）、`QStringLiteral`、中文注释、头文件依赖单向（core 不依赖 ui）。
- 错误一律：模型层校验 → `log(...,"warn")` → 返回 `-1`/`false`；不在 UI 层做业务校验。
- 单一数据源：常量集中在对应头文件（如 `DimStyle.h`），禁止散落魔数；容差统一走 `geo::almostEqual`。
- 测试：每模块一个 CMake target；UI 相关 target 必须显式加 `src/ui/MainWindow.cpp`（`${UI_SOURCES}` 不含它）。

**禁改清单（写进 L0）**
- 枚举顺序、JSON 存档字段语义、`Element` 结构布局、公共头文件签名。
- 既有测试断言（**不得为让测试通过而弱化/删除断言**）。
- 国标参数表（线宽组、19 种剖面材料、粗糙度 H1/H2、字高、剖切符号）。
- CMake 全局配置、第三方依赖（新增依赖须人工批准 + 许可白名单：MIT/BSD/Apache 可用，GPL/LGPL 需特批）。

## 3. 改进步骤库

> 步骤编号规则：`F`=新增功能、`B`=缺陷修复、`P`=性能优化、`S`=稳定性提升。
> 每个步骤统一五段输出：**改进目标 / 提示词设定要点 / 提示词框架示例 / 验证方式 / 完成标准**。
> 详写 8 个样板步骤（覆盖四类），其余 backlog 通过 §3.9 映射表套用同一模板。

### 3.1 【F1】新增功能：DXF 导入实体扩展（块 / 标注 / 填充）

**改进目标**
- 来源差距：1.4.1 / 1.4.2 / 1.4.3 / 1.4.4 / 1.4.5
- 目标：在 `fromDxf` 中新增 `INSERT`（含 `ATTRIB`/`SEQEND`）、`DIMENSION`、`HATCH`、`ELLIPSE`、`SPLINE`、`SOLID`、`POINT` 解析，并读取 `BLOCKS` 段与 `LTYPE` 表。
- 量化：真实客户图纸导入保真率 ≥ 95%（类型加权），块/标注/填充三类 ≥ 90%。

**提示词设定要点**
- L1 注入 `formats` + `block` 两个模块提示词（本次跨模块）。
- 明确**拆分轮次**：第 1 轮只做 `ELLIPSE`+`SOLID`+`POINT`（纯几何、可自洽验证）；第 2 轮 `INSERT`+`BLOCKS`（依赖块模型）；第 3 轮 `DIMENSION`+`HATCH`（最复杂）。**禁止一轮提交全部**。
- 强调"未知实体跳过并计数"，禁止因单实体解析失败中断整个导入。
- 明确非目标：不改动现有 7 类实体的解析行为（回归基线）。
- 数学部分（椭圆参数化、NURBS、HATCH 岛检测）**要求 AI 给出公式来源并标注"需人工复核"**，不得自行拍定参数化约定。

**提示词框架示例**
```
[L0 基础系统提示词]
[L1 模块提示词：formats + block]
[L2 任务提示词：feature]

=== 本步六要素 ===
GOAL: 在 cadfmt::fromDxf 中新增 {{ENTITY_LIST}} 的解析，并对未知实体跳过计数。
OUT_OF_SCOPE: 不改现有 LINE/CIRCLE/ARC/POLYLINE/TEXT/MTEXT 的解析行为；
              不改 DXF 导出；不改渲染；不引入第三方库。
CONTEXT: 核心文件 src/core/CadFormats.cpp(1019-1080 为现有实体分派处)、
         src/core/Element.h、src/core/Block.h；
         同类样例：现有 POLYLINE(VERTEX/SEQEND) 的成对解析写法。
IO_SPEC: 解析结果写入既有 std::vector<Element>& out；
         块定义写入新增的 out 参数或既有 BlockDef 收集路径（由你提出方案，我确认后再实现）；
         错误：*err 写入中文原因；单实体失败不中断，累计到 DxfImportStats。
ACCEPT: 1) 每类实体 ≥ 6 个断言，含退化用例（半径 0、空块、闭合/开放填充边界）；
        2) tests/ 新增或扩展现有 target 并在 CMake 显式注册；
        3) tests/golden 样本 round-trip 几何差 ≤ 1e-6；
        4) 既有的 38 个测试 exe 全部 exit 0。
FORBID: 改动 ElementType/DimensionType 枚举顺序；改动既有测试断言；
        改动现有 7 类实体的解析分支；新增第三方依赖。
ESCALATE: 涉及椭圆参数化、NURBS 节点/权重、HATCH 岛检测时，
          输出候选公式与依据并停止实现，等待人工确认。
=== 反馈包 ===
{{FEEDBACK}}
```

**验证方式**
- 自测用例生成提示词（框架）：
```
基于本轮新增的 {{ENTITY_LIST}}，生成三类测试：
(a) 黄金差分：构造最小 DXF 文本 → 导入 → 断言图元字段（坐标/半径/角度/块名/变换矩阵）；
(b) 属性不变量：随机生成 200 组参数，断言"导入→导出→再导入"字段一致（容差 1e-6）；
(c) 退化与模糊：空块定义、无 SEQEND 的 INSERT、重复句柄、损坏组码（不得崩溃，须 *err 报错）。
禁止"恒真断言"：每条断言必须能被一次源码破坏触发失败，并在注释中写明破坏方式。
```
- 性能基准校验提示词（框架）：
```
为 fromDxf 生成基准：样本 = 1万/10万图元 DXF（含块与标注）。
采集：解析耗时、峰值内存、图元/秒三项；输出 CSV 与 Markdown 表格。
阈值：解析耗时较本轮基线回归 > 5% 即判定失败；内存增长 > 10% 需说明理由。
```

**完成标准（DoD）**
- [ ] 目标实体全部解析通过，黄金样本保真率达标
- [ ] 新测试 target 注册且全绿；38 个既有 exe 全 exit 0
- [ ] 数学部分经人工复核签字（G1 门禁）
- [ ] 未知实体跳过计数写入日志，不静默吞掉
- [ ] 提示词与上下文包回写 `prompts/`，标注验证通过的代码版本

### 3.2 【F2】新增功能：打印与布局最小闭环

**改进目标**
- 来源差距：1.3.12 / 1.3.13 / 1.3.14（**产品闭环断点**）
- 目标：`PlotEngine` 提供页面设置（纸张/方向/边距/比例/居中）、模型空间打印、线宽-颜色映射（CTB 简化版）、打印预览、PDF 输出。

**提示词设定要点**
- L1 注入 `ui` + `render` 模块；明确**新模块**须给出目录与文件划分方案供确认（不要直接开工）。
- 强制"PDF 优先"：`QPdfWriter` 为第一输出目标，实体打印机走 `QPrinter` 且必须可注入假设备进行离屏测试。
- 线宽映射表**必须由人工提供**（GB/T 14665 组别 → 设备线宽），提示词中作为常量表输入，禁止 AI 自创。
- 强调单位换算链：图纸 mm → 逻辑像素 → 设备单位，要求显式写出换算函数并单独测试。
- 非目标：布局/视口（VPORTS）本轮不做（拆到下一个步骤）。

**提示词框架示例**
```
[L0][L1: ui + render][L2: feature]
GOAL: 实现 PlotEngine 最小闭环：页面设置对话框 + 打印预览 + PDF 输出 + 实体打印。
OUT_OF_SCOPE: 不做布局/图纸空间/视口；不做打印样式表编辑器（本轮用内置映射表）。
CONTEXT: src/ui/MainWindow.cpp 的菜单与 writeDrawing 结构；src/core/SheetSpec.h（图框）；
         线宽映射表（人工提供，见 CONSTANTS）。
IO_SPEC: PlotSettings{paper, orientation, marginMM, scale, center, lineWidthTable} 可序列化进存档；
         bool plotToPdf(path, settings, err) / bool plotToPrinter(printerName, settings, err)；
         预览用既有渲染路径复用，不得另写一套绘制代码。
ACCEPT: 1) 单位换算函数单独 ≥ 10 断言（含 1:1/1:2/1:50/2:1）；
        2) 离屏 PDF 可生成并与基准 PDF（人工提供样张）逐页文本/几何比对；
        3) A4/A3 × 彩色/黑白 四种组合有样张测试；
        4) 打印失败路径返回 false + log warn（不弹崩溃）。
FORBID: 改动 SheetSpec 语义；改动既有渲染代码；新增第三方依赖；改动国标线宽组常量。
ESCALATE: 涉及设备驱动差异、真实打印机行为时停止实现并报告。
```

**验证方式**
- 自测用例生成提示词：页面设置序列化 round-trip、比例换算矩阵表驱动（参数化 12 组）、边距越界钳制、空图纸打印应失败并 log。
- 性能基准校验提示词：`1000 图元 / 10000 图元` 生成 PDF 的耗时与文件体积；阈值：10 秒内完成，体积回归 > 20% 需说明。
- **必过人工门禁 G7**：样张人工比对签字。

**完成标准**
- [ ] A4/A3 彩色/黑白四种组合输出样张，人工比对通过
- [ ] PDF 与打印同源（同一绘制路径），可用假设备离屏验证
- [ ] 单位换算与映射表测试全绿
- [ ] 页面设置可随存档存取且旧档兼容

### 3.3 【F3】新增功能：命令补全（样板化命令族）

**改进目标**
- 来源差距：1.1.2 / 1.1.3 / 1.1.4 / 1.1.5 / 1.1.7 / 1.1.8 / 1.1.12 / 1.1.13 / 1.1.9
- 目标：新增 EXTEND / JOIN / CHAMFER / PEDIT / BOUNDARY / HATCHEDIT / MATCHPROP / PURGE / AUDIT / DIST / AREA / COPYCLIP 族，并把 `array`、剖面填充从"仅 UI"补成命令行。
- 量化：命令数 66 → ≥ 110。

**提示词设定要点**
- **这是最能体现复用的步骤**：提示词 = L0 + L1(commands) + L2(feature) + **一个"完整命令样板"上下文包**（`OffsetCommand` 的命令类 + `registerExact` + 菜单项 + 测试 target 四件套）。
- 明确"照抄结构、只换语义"，禁止 AI 自行设计命令注册方式或参数解析风格。
- 每命令单独一轮（禁止一次提交 12 个命令），每轮 ≤ 300 行。
- 几何语义部分要求 AI 先输出"算法步骤与退化情形清单"，确认后再实现（G1 门禁前置）。

**提示词框架示例**
```
[L0][L1: commands][L2: feature]
CONTEXT(必注入): src/core/Commands.cpp 中 OffsetCommand 的完整实现；
                 registerExact 注册处(2091-2216)；MainWindow 菜单 mk() 写法；
                 tests/ 中对应命令测试样例。
GOAL: 参照上述样板实现命令 {{CMD_NAME}}，语义：{{SEMANTICS_DESCRIPTION}}。
OUT_OF_SCOPE: 不改命令注册表机制；不改命令解析框架；不改既有命令行为。
IO_SPEC: 命令语法 {{SYNTAX}}；参数解析复用 CommandContext::tryParsePoint；
         失败：m->log("用法: ...", "warn") 并返回 false；
         成功：beginEdit + 变更 + 一次 pushMemento，返回 true。
ACCEPT: 1) ≥ 8 断言，含 3 类退化用例（零长/重合/自交/空选择）；
        2) tests 新增 target 并在 CMake 注册；
        3) 命令行与菜单两条入口行为一致（若有菜单项）。
FORBID: 自造几何算法（只能用 Modify.h/Geometry.h/Trim.h 既有 API）；
        改既有命令；改既有断言。
PRE_STEP: 先用 100 字以内给出"算法步骤 + 退化情形清单"，我确认后再写代码。
```

**验证方式**
- 自测用例生成提示词：对每命令生成"参数矩阵表驱动测试"（合法/缺参/越界/退化）+ "与既有同类命令一致性测试"（如 EXTEND 与 TRIM 的边界选择语义对称）。
- 性能基准校验提示词：命令在 1 万图元图纸上的执行耗时（EXTEND/JOIN/BOUNDARY 最易 O(N²)），阈值 ≤ 50 ms，并断言复杂度不是 O(N²)（用 1万/4万 两档耗时比 < 6 验证）。

**完成标准**
- [ ] 每命令独立 PR、独立测试、独立 DoD
- [ ] 命令数与覆盖度达目标（≥110 条 / 常用 150 条覆盖 ≥70%）
- [ ] `array` 与剖面填充具备命令行入口（可脚本化）
- [ ] 38 exe 全绿

## 4. 迭代式提示词：把报错、测试与性能数据回填以收敛

### 4.1 反馈包分类与结构

| 反馈包 | 内容 | 结构化要求 |
|---|---|---|
| **编译/链接包** | 错误行、文件:行号、完整错误文本 | 只保留**首个错误链**（后续多为连锁），附相关代码 ±10 行 |
| **测试失败包** | 失败用例名、期望值、实际值、断言位置 | 逐条列出，禁止贴整段日志；标注"是否为新引入失败" |
| **性能数据包** | 指标、基线值、当前值、回归幅度、样本规模 | 表格化 + 指出超阈值的具体项 |
| **评审意见包** | 人工门禁意见（G1~G8） | 逐条编号，明确"必须改/建议改/仅说明" |

### 4.2 收敛循环

```
执行 → 采集（编译/测试/性能）→ 结构化成反馈包 → 回填到下一轮提示词 → 复跑
     ↑                                                                    │
     └──────────── 未达标且轮次 < N（默认 N=4）─────────────────────────┘
                     轮次 ≥ N 仍未达标 → 降级为「最小复现 + 人工介入」
```

### 4.3 回填提示词模板

```
[L0][L1: {{MODULE}}][L2: {{TASK_TYPE}}]
=== 上一轮结果 ===
轮次: {{N}} / 上限 4
已完成: {{DONE_ITEMS}}
=== 反馈包：{{TYPE}} ===
{{STRUCTURED_FEEDBACK}}
=== 本轮要求 ===
1. 只针对以上 {{K}} 条问题修复，不得扩大改动范围；
2. 不得修改断言来让测试通过（如需改断言，说明为什么原断言错误）；
3. 输出格式：先给"每条问题 → 根因 → 改动点（文件:行号）"，再给完整 diff；
4. 若某条无法在现有约束内解决，明确回复"需要人工决策：{{问题}}"，不要自行放宽约束。
```

### 4.4 反模式（必须避免）

| 反模式 | 后果 | 正确做法 |
|---|---|---|
| 整段日志原样粘贴 | 上下文膨胀、关键信息被淹没 | 结构化裁剪，只留首个错误链与失败断言 |
| 一轮混合多个目标 | 失败无法归因 | 一个 PR = 一个目标 |
| 无轮次上限 | 无限试错、成本失控 | 默认 4 轮，超限转人工 |
| 允许 AI 自行改断言 | 测试失去意义（"假绿"） | 明确禁止；改断言需人工批准 |
| 只给"还是不对" | AI 无法定位 | 必须给出期望值 vs 实际值 |

### 6.1 目录结构

### 6.3 度量与调优（用数据反过来改提示词）

| 指标 | 口径 | 用途 |
|---|---|---|
| 一次通过率 | 首轮即编译通过 + 测试全绿的比例 | < 50% 说明 L0/L1 上下文不足 |
| 平均收敛轮次 | 达到 DoD 的轮次 | > 3 说明验收标准不明确 |
| 返工率 | 合并后 7 天内被发现缺陷的比例 | 高则补"禁止改动范围"与边界清单 |
| 引入缺陷率 | 每千行 AI 代码触发的回归数 | 高则强制 PRE_STEP（先给方案再写代码） |

### 6.4 与 V1 人工门禁的衔接

提示词中的 `ESCALATE` 段对应 V1 的 G1~G8：几何算法(G1)、数值精度(G2)、许可合规(G3)、ABI/存档(G4)、性能基线(G5)、撤销事务(G6)、出图样张(G7)、脚本安全(G8)。**提示词只负责"触发停止并上报"，判定权在人工。**

## 7. 主要风险与应对（针对提示词驱动模式的新增风险）

| # | 风险 | 表现 | 应对 |
|---|---|---|---|
| R1 | **提示词漂移** | 同一任务不同轮次上下文不一致，结果发散 | 上下文包固定化 + 提示词版本化 + 元信息头校验 |
| R2 | **上下文膨胀** | 注入过多文件，关键约束被淹没 | 每个模块限定"必注入清单"（≤ 5 个文件）；日志类信息一律裁剪 |
| R3 | **AI 自造几何算法** | 绕过 `Geometry.h` 写出"看起来对"的数学 | L0 硬性禁止 + G1 门禁 + 变异测试 |
| R4 | **测试假绿** | AI 改断言/写恒真断言 | 明令禁止 + 变异测试 + diff 人工抽检 |
| R5 | **阈值博弈** | 为过性能门槛而降低样本质量或缓存结果 | 基准脚本固定种子与样本构造代码，脚本本身由人工审批 |
| R6 | **无限迭代** | 回填轮次失控 | 默认上限 4 轮，超限转人工 |
| R7 | **合规污染** | AI 复现 GPL/商业 SDK 代码 | L0 写明许可白名单；依赖变更须人工批准；相似度扫描 |
| R8 | **提示词 stale** | 代码重构后提示词失效却仍在使用 | 绑定提交号，测试失败即标记 stale 并强制复核 |

## 附录 A：提交前提示词自检清单（12 项）
