# SketchCAD 图元关系型数据库存储方案

> 适用对象：需要把 SketchCAD 绘制图元（绘图元素）持久化到关系型数据库（SQLite / MySQL，亦可平滑扩展至 PostgreSQL）的场景。
> 设计目标：在不破坏现有 `Element` 内存数据模型的前提下，给出一套**可移植、可索引、可批量读写**的存储方案，并直接复用既有的 `elementToJson()` / `elementFromJson()` 序列化对，保证导入导出与 DB 存储同源。

---

## 1. 总体架构

采用**分层 + 适配器**结构，DB 引擎差异收敛在最薄的一层：

```
┌──────────────────────────────────────────────────────────┐
│  应用 / SketchModel（内存模型，现有 C++ 代码）             │
├──────────────────────────────────────────────────────────┤
│  SketchModelBridge       模型 ↔ DB 增量同步（增删改回调）  │
│  ElementRepository       图元 CRUD / 查询                  │
│  LayerRepository         图层 CRUD                        │
│  BlockRepository         块定义 / 块引用                  │
│  DrawingRepository       工程 / 文档                      │
│  SchemaMigrator          版本化建表与升级                 │
│  GeometryCodec           控制点 ↔ 行 / WKB / JSON 编解码  │
│  SpatialQuery            包围盒 / 区域检索                │
├──────────────────────────────────────────────────────────┤
│  IDbAdapter（方言适配）   占位符/自增/时间/JSON/UPSERT/DDL │
├──────────────────────────────────────────────────────────┤
│  Qt SQL（QSqlDatabase）   QSQLITE / QMYSQL 驱动           │
└──────────────────────────────────────────────────────────┘
```

**为何基于 Qt SQL**：SketchCAD 本身为 Qt 6 工程，`QSqlDatabase` 已原生抽象 SQLite（`QSQLITE`）与 MySQL（`QMYSQL`），占位符统一为 `?`（或 `:name` 命名占位符），事务、外键、预处理语句一应俱全。本方案以 Qt SQL 为默认承载，方言差异仅在 `IDbAdapter` 中处理，因此大部分逻辑与具体引擎无关。

**核心思想 —— 规范化列 + JSON 兜底双写**：

- **规范化列**：把 `Element` 中与检索/过滤相关的字段（`type`/`layer`/`color`/`line_style`/`bbox`/`by_layer`/`visible` …）落为独立列并建立索引，支撑「按图层、按类型、按包围盒、按名称」的高性能查询。
- **`payload_json` 列**：每行额外存一份 `elementToJson(e).toJson()` 的完整 JSON BLOB/TEXT。它是**无损兜底**，保证新字段、嵌套向量（`holes`/`colWidths`/`fcfDatums`/属性表…）零丢失，并在跨版本迁移时可直接反序列化，避免"改一处漏一处"。
- 读取时优先由规范化列重建轻量对象；需要完整字段时再用 `payload_json` 还原。二者由 `ElementSerializer` 保证一致。

## 2. 图元数据模型抽象

### 2.1 统一图元模型

现有 `struct Element`（见 `src/core/Element.h`）已是"宽表式"统一结构：一个 `type: ElementType` 决定语义，其余字段按类型复用。`ElementType` 为**只增不改**的枚举（当前 0..19，Text..Fcf），数据库用 `INTEGER` 存储其整数序号即可复用同一语义。

抽象维度分为五类：

| 维度       | 含义                                                 | 抽象方式                                                                                                                               |
| -------- | -------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| **几何形状** | 直线/圆/弧/椭圆/折线/样条/点/边界/块引用…                          | 主表 `type` 区分；控制点统一进 `element_points` 表；`radius`/`start_angle`/`end_angle`/`radius_y`/`rotation`/`closed`/`spline_sub_type` 进主表或扩展表 |
| **坐标**   | 世界坐标右手系（X 右、Y 上）                                   | `element_points(x, y, z, seq)`；所有图元几何以"点多段"形式归一到点序列，圆/弧由 `pts[0]` 圆心 + `radius` 表达                                                 |
| **样式**   | 颜色 / 线型 / 线宽 / ByLayer / ByBlock                   | 主表 `color_rgb` + `line_style` + `line_width` + `line_width_auto` + `by_layer` + `by_block`；`by_layer=true` 时样式在渲染期动态解析所属图层         |
| **层级**   | 图层 / 块成员 / 编组 / z 序                                | `layer_id` 外键、`owner_block_id` 外键（块定义内成员）、`group_name`、`zorder`（替换保留字 `order`）                                                     |
| **语义附属** | 标注/约束引用、FIELD 域、MText/Table/Fcf/MLeader/Hatch 专用字段 | 类型化扩展表（`dimension_elems`/`mtext_elems`/`table_cells`/`fcf_datums`…）或通用 `element_attrs` EAV 表兜底                                     |

### 2.2 几何抽象（归一点序列）

所有图元的几何统一抽象为**点序列 + 参数**，避免为每种图元建独立几何表：

- **直线/折线/多边形/样条/边界/构造线**：`pts[]` 进 `element_points`；折线是否闭合由 `closed` 字段（而非类型）决定；样条子类型 `spline_sub_type`、折线圆弧段标记 `arc_flags`（第 i 段是否圆弧）进 `element_attrs`。
- **圆/圆弧**：`pts[0]`=圆心，`radius`=半径，弧用 `start_angle`/`end_angle`。
- **椭圆**：圆心 + `radius`（长半轴）+ `radius_y`（短半轴）+ `rotation`（长轴角）。
- **矩形/多边形**：本质为闭合点序列，无需专门几何列。
- **块引用（BlockRef）**：**不复制几何**，仅存 `block_name` + 插入变换（`pts[0]` 插入点、`rotation`、`scale_x`、`scale_y`）+ 属性值/动态参数；渲染期按 `BlockDef` 展开。块定义本身 = 一组 `owner_block_id` 指向某 block 的 `elements` 行。
- **Hatch/Boundary 孔洞**：外环进 `element_points`，内孔（`holes`）进 `hatch_holes` 表（`element_id, hole_seq, point_seq, x, y`）。

### 2.3 样式与图层（ByLayer / ByBlock）

沿用现有"引用式 + 标志位"范式：

- 图层存于 `layers` 表（含图层默认 `color`/`line_style`/`line_width`/可见性/锁定/冻结/打印/绘制序）。图元 `by_layer=true` 时渲染期取所属图层值。
- `by_block=true`（DXF 62=0）时块内图元在展开期继承 INSERT 样式。
- 显式色（`by_layer=false` 且非 by_block）落入 `color_rgb`；`by_layer/by_block` 标志位单独成列。

### 2.4 块（Block）

"引用式"而非"内嵌式"：

- `blocks`：块定义元信息（`name` 唯一、`base_x`/`base_y` 基点、描述）。
- 块内图元 = 普通 `elements` 行，仅 `owner_block_id` 指向该 block（其余字段与自由图元完全一致）。
- 块引用 = 一条 `type=BlockRef` 的 `elements` 行，引用 `block_name` + 变换 + 属性。改 block 定义 → 所有引用天然同步。

### 2.5 字段与域（FIELD / PROP）

`%<PROP:名称>%`、`%<变量>%` 等在 MText/Table 单元格中求值：

- 图纸级变量/特性存 `drawing_props`（`key`, `value`）或 `variables` 表，供域引擎替换。
- 域宿主（含域的 MText/Table）在 `elements` 中以 `type` 标识，内容列存原始文本（`%<...>%` 占位），求值结果（快照）由渲染/导出期产生，DB 仅存"源"。

## 3. 数据库表结构设计

> 类型说明：`BIGINT` 作主键/外键；`TEXT` 存字符串与 JSON 兜底；`REAL` 存坐标/尺寸；`INTEGER` 存枚举/标志/时间戳（unix epoch 秒）。引擎特异处见第 4 节。保留字 `order`→`zorder`、`key`→`attr_key`、`group`→`group_name` 已规避。所有外键开启 `ON DELETE CASCADE`（或应用层显式级联）。

### 3.1 drawings（工程/文档）

| 字段           | 类型           | 约束               | 说明                              |
| ------------ | ------------ | ---------------- | ------------------------------- |
| id           | BIGINT       | PK               | 文档 id（应用层分配，见 4.2）              |
| name         | VARCHAR(255) | NOT NULL, UNIQUE | 文档名                             |
| version      | VARCHAR(32)  |                  | 软件/格式版本，如 `1.1.0`               |
| units        | SMALLINT     |                  | 0=mm,1=inch…                    |
| payload_json | TEXT         |                  | 文档级配置（视图/DimStyle/TextStyle 表等） |
| created_at   | INTEGER      | NOT NULL         | unix epoch                      |
| updated_at   | INTEGER      | NOT NULL         | unix epoch                      |

### 3.2 layers（图层）

| 字段         | 类型           | 约束                                | 说明                    |
| ---------- | ------------ | --------------------------------- | --------------------- |
| id         | BIGINT       | PK                                |                       |
| drawing_id | BIGINT       | FK→drawings(id) ON DELETE CASCADE |                       |
| name       | VARCHAR(255) | NOT NULL                          | 图层名（如 `0`/`中心线`/`标注`） |
| color_rgb  | INTEGER      |                                   | 默认色 0xRRGGBB，可空=继承    |
| line_style | SMALLINT     |                                   | `LineStyle` 枚举        |
| line_width | REAL         |                                   | 默认线宽(px)              |
| is_visible | INTEGER(0/1) |                                   | 可见                    |
| is_locked  | INTEGER(0/1) |                                   | 锁定                    |
| is_frozen  | INTEGER(0/1) |                                   | 冻结（不重绘）               |
| plot       | INTEGER(0/1) |                                   | 是否打印                  |
| zorder     | INTEGER      |                                   | 绘制序（替代保留字 order）      |

> `UNIQUE(drawing_id, name)` 防止同名图层。

### 3.3 blocks（块定义元信息）

| 字段          | 类型           | 约束                            | 说明      |
| ----------- | ------------ | ----------------------------- | ------- |
| id          | BIGINT       | PK                            |         |
| drawing_id  | BIGINT       | FK→drawings ON DELETE CASCADE |         |
| name        | VARCHAR(255) | NOT NULL                      | 块名（唯一键） |
| base_x      | REAL         |                               | 基点 X    |
| base_y      | REAL         |                               | 基点 Y    |
| description | TEXT         |                               | 描述      |

### 3.4 elements（图元主表 —— 核心）

| 字段                                                | 类型           | 约束                              | 说明                                     |
| ------------------------------------------------- | ------------ | ------------------------------- | -------------------------------------- |
| id                                                | BIGINT       | PK                              | 图元 id                                  |
| drawing_id                                        | BIGINT       | FK→drawings ON DELETE CASCADE   | 所属文档                                   |
| layer_id                                          | BIGINT       | FK→layers(id)                   | 所属图层（可空）                               |
| owner_block_id                                    | BIGINT       | FK→blocks(id) ON DELETE CASCADE | 若属某块定义则非空，否则 NULL                      |
| type                                              | SMALLINT     | NOT NULL                        | `ElementType` 整数序号（只增不改）               |
| handle                                            | VARCHAR(64)  |                                 | DXF 句柄（兼容导入导出）                         |
| name                                              | VARCHAR(255) |                                 | 图元名                                    |
| group_name                                        | VARCHAR(255) |                                 | 编组名（同名称组）                              |
| by_layer                                          | INTEGER(0/1) | NOT NULL DEFAULT 1              | 样式随层                                   |
| by_block                                          | INTEGER(0/1) | NOT NULL DEFAULT 0              | 样式随块                                   |
| color_rgb                                         | INTEGER      |                                 | 显式色 0xRRGGBB；by_layer/by_block 时为 NULL |
| line_style                                        | SMALLINT     |                                 | `LineStyle` 枚举                         |
| line_width                                        | REAL         |                                 | 手动线宽(px)                               |
| line_width_auto                                   | INTEGER(0/1) |                                 | 线宽随线型派生                                |
| text                                              | TEXT         |                                 | 标注/文字内容（含 `%<域>%` 占位）                  |
| radius                                            | REAL         |                                 | 圆/弧半径、椭圆长半轴、Text 字高复用                  |
| radius_y                                          | REAL         |                                 | 椭圆短半轴                                  |
| start_angle                                       | REAL         |                                 | 弧起止角(度)                                |
| end_angle                                         | REAL         |                                 | 弧止角(度)                                 |
| rotation                                          | REAL         |                                 | 椭圆长轴角/剖面线角/插入旋转/表旋转                    |
| closed                                            | INTEGER(0/1) |                                 | 点序列是否闭合                                |
| spline_sub_type                                   | SMALLINT     |                                 | 样条子类型                                  |
| visible                                           | INTEGER(0/1) | NOT NULL DEFAULT 1              | 可见                                     |
| zorder                                            | INTEGER      | NOT NULL DEFAULT 0              | 同层绘制序                                  |
| payload_json                                      | TEXT         |                                 | **完整 `elementToJson` 兜底**（无损）          |
| geom_format                                       | SMALLINT     |                                 | 0=points 表,1=WKB blob（可选冗余）            |
| bbox_min_x / bbox_min_y / bbox_max_x / bbox_max_y | REAL         |                                 | 包围盒（建空间索引）                             |
| created_at / updated_at                           | INTEGER      | NOT NULL                        | unix epoch                             |

**索引**：

```sql
CREATE INDEX ix_elements_drawing      ON elements(drawing_id);
CREATE INDEX ix_elements_layer        ON elements(layer_id);
CREATE INDEX ix_elements_type         ON elements(type);
CREATE INDEX ix_elements_owner_block ON elements(owner_block_id);
CREATE INDEX ix_elements_bbox        ON elements(bbox_min_x, bbox_min_y, bbox_max_x, bbox_max_y);
CREATE INDEX ix_elements_group       ON elements(group_name);
CREATE UNIQUE INDEX ux_elements_handle ON elements(drawing_id, handle);  -- handle 可空时改用部分索引
```

> `bbox_*` 四列是空间检索的关键：SQLite 无原生空间索引，用四列组合 B-tree 索引做"包围盒相交"过滤已足够工程绘图规模；MySQL 可额外用原生 `GEOMETRY` 列 + `SPATIAL INDEX`（见 4.6）。

### 3.5 element_points（控制点，归一几何）

| 字段         | 类型      | 约束                                | 说明          |
| ---------- | ------- | --------------------------------- | ----------- |
| id         | BIGINT  | PK                                |             |
| element_id | BIGINT  | FK→elements(id) ON DELETE CASCADE |             |
| seq        | INTEGER | NOT NULL                          | 点序（0-based） |
| x / y / z  | REAL    | NOT NULL                          | 世界坐标        |

```sql
CREATE INDEX ix_pts_element ON element_points(element_id, seq);
```

> 圆/弧只存 `pts[0]`（圆心），其余由主表 `radius`/`start_angle`/`end_angle` 推导，避免冗余点。

### 3.6 element_attrs（EAV 兜底，存类型专属标量/小向量）

用于那些"列不固定、但值得结构化存储"的字段（`arc_flags`、`col_widths`、`dim_text_height`、`tol_upper/lower`、`fit_code`、`style_name`、`dim_style_name`、`mtext_width`、`line_spacing`、`width_factor`、`text_align`、`section_exempt/section_material`、`hatch_*` 等），避免主表横向膨胀：

| 字段         | 类型          | 约束                            | 说明                             |
| ---------- | ----------- | ----------------------------- | ------------------------------ |
| id         | BIGINT      | PK                            |                                |
| element_id | BIGINT      | FK→elements ON DELETE CASCADE |                                |
| attr_key   | VARCHAR(64) | NOT NULL                      | 属性名（如 `arc_flags`,`tol_upper`） |
| seq        | INTEGER     |                               | 向量元素序（标量=-1）                   |
| val_int    | BIGINT      |                               | 整型值                            |
| val_real   | REAL        |                               | 浮点值                            |
| val_str    | TEXT        |                               | 字符串值                           |

```sql
CREATE INDEX ix_attrs_element ON element_attrs(element_id, attr_key);
```

### 3.7 类型化扩展表（关系型更强、查询更优者）

对最核心的几类图元建立窄表，提升可读性与查询性能：

**table_cells**（明细表/标题栏单元格）

| 字段         | 类型        | 说明                |
| ---------- | --------- | ----------------- |
| id         | BIGINT    | PK                |
| element_id | BIGINT FK | 母表                |
| row        | INTEGER   | 行号                |
| col        | INTEGER   | 列号                |
| content    | TEXT      | 单元格文本（可含 `%<域>%`） |

**fcf_datums**（形位公差基准字母）

| 字段         | 类型          | 说明           |
| ---------- | ----------- | ------------ |
| id         | BIGINT      | PK           |
| element_id | BIGINT FK   |              |
| seq        | INTEGER     | 基准序          |
| letter     | VARCHAR(8)  | 基准字母（A/B/C…） |
| symbol     | SMALLINT    | 几何特征符号枚举     |
| modifier   | VARCHAR(8)  | 修饰符（M/L/S/P） |
| tolerance  | VARCHAR(64) | 公差值文本        |

**block_attr_values / block_dyn_values**（块引用属性与动态参数）

```sql
block_attr_values(element_id FK, tag VARCHAR, value TEXT)
block_dyn_values (element_id FK, name VARCHAR, value REAL, state VARCHAR)
```

**hatch_holes**（剖面内孔）

```sql
hatch_holes(element_id FK, hole_seq INTEGER, point_seq INTEGER, x REAL, y REAL)
```

**element_refs**（约束/标注引用的图元，对应 `refA`/`refB`）

```sql
element_refs(element_id FK, role VARCHAR(8), ref_id BIGINT)  -- role: 'a'/'b'
```

> 其余类型专属字段（MText 的 `width_factor`、MLeader 的 `mleader_landing`、Dimension 的 `dim_value/dtype/standard` 等）可继续落入 `element_attrs` 或各自窄表；**`payload_json` 始终保留全量**，二者不会有不一致风险。

### 3.8 drawing_props / variables（域数据源 / 图纸特性）

| 字段         | 类型           | 说明            |
| ---------- | ------------ | ------------- |
| id         | BIGINT       | PK            |
| drawing_id | BIGINT FK    |               |
| key        | VARCHAR(128) | 变量/特性名        |
| value      | TEXT         | 值（JSON 可存结构化） |

`%<PROP:名称>%` 与 `%<变量>%` 在求值时查此表。

## 4. SQLite 与 MySQL 兼容性及差异处理

方案原则是**用两库共同支持的最小子集**，仅在 `IDbAdapter` 内做方言适配。下表给出差异与处理策略：

| 维度          | SQLite                                  | MySQL                                     | 处理策略                                                               |
| ----------- | --------------------------------------- | ----------------------------------------- | ------------------------------------------------------------------ |
| **驱动**      | `QSQLITE`                               | `QMYSQL`                                  | 由 `DbConfig.engine` 选择；工厂返回对应 `IDbAdapter`                         |
| **自增主键**    | `INTEGER PRIMARY KEY AUTOINCREMENT`     | `BIGINT UNSIGNED NOT NULL AUTO_INCREMENT` | 推荐**应用层分配 ID**（雪花/ULID/`QRandomGenerator`），彻底消除方言差异；仍支持 DB 自增      |
| **占位符**     | `?`                                     | `?`（Connector/C++ 亦支持）                    | 统一用 `?`/`QSqlQuery::addBindValue`；命名占位用 `:name` 两库通用               |
| **布尔**      | 无，用 `INTEGER` 0/1                       | `BOOLEAN`= `TINYINT(1)`                   | DDL 用 `INTEGER(0/1)`（SQLite）/`TINYINT(1)`（MySQL），语义一致，适配器生成对应类型字符串 |
| **时间**      | 无原生类型                                   | `DATETIME`/`TIMESTAMP`                    | 统一存 **`INTEGER` unix epoch 秒**（两库原生支持、排序/索引一致）；MySQL 亦可显式 CAST     |
| **JSON**    | JSON1 扩展（TEXT 存储，函数可选）                  | `JSON` 类型 + `->>` 函数                      | `payload_json` 统一存 **TEXT**（合法 JSON 串）；查询不依赖引擎 JSON 函数，应用层解析       |
| **字符串长度**   | 忽略 `VARCHAR(n)`                         | 需要 `VARCHAR(n)`                           | DDL 显式写 `VARCHAR(255)`（两库均可）；长文本用 `TEXT`                           |
| **保留字**     | —                                       | `order`/`key`/`group` 为保留/易冲突             | 已全部改名（`zorder`/`attr_key`/`group_name`）                            |
| **外键强制**    | 需 `PRAGMA foreign_keys=ON`              | InnoDB 默认强制                               | 打开连接即执行 `PRAGMA foreign_keys=ON`（SQLite）；应用层统一开启级联                 |
| **UPSERT**  | `INSERT ... ON CONFLICT(col) DO UPDATE` | `INSERT ... ON DUPLICATE KEY UPDATE`      | `IDbAdapter::upsert()` 按引擎生成                                       |
| **分页/窗口**   | 3.25+ 支持窗口函数                            | 8.0+ 支持                                   | 兼容写法：用 `LIMIT ? OFFSET ?` 分页；避免依赖窗口函数                              |
| **大小写敏感**   | 字节比较（ASCII 大小写敏感）                       | 默认 CI（不敏感）                                | 名称比较统一在应用层处理；需精确匹配时加 `BINARY`/二进制 collation                        |
| **并发写入**    | 单写者；`WAL` 提升并发读                         | 多写者，行级锁                                   | SQLite 启用 **WAL 模式**并短事务；MySQL 用默认事务隔离；写冲突重试                       |
| **字符集**     | UTF-8（默认）                               | `utf8mb4`                                 | 两库均设 UTF-8/utf8mb4，完整 CJK 与 `•`/`⌀`/`①` 等符号                        |
| **空间索引**    | 无原生；用 `bbox_*` B-tree                   | `GEOMETRY` + `SPATIAL INDEX`              | 通用方案用 `bbox_*` 四列（两库通用）；MySQL 可额外加 `SPATIAL` 加速（视为优化，不破坏兼容）        |
| **BLOB 上限** | 约 1 GB（页限制）                             | 64 KB 行默认/`LONGTEXT` 无限制                  | `payload_json` 文本化后远小于阈值；命中限制时按 `element_id` 分片                    |

### 4.1 应用层分配 ID（推荐）

```cpp
// 避免 AUTO_INCREMENT 方言差异；可用雪花算法或 UUIDv7
qint64 DbIdGen::next(DbScope scope);
```

若无主键冲突需求，也可让两库各自自增，但需在迁移/合并时做 ID 重映射——不推荐。

## 5. 图元 CRUD 存储与读取流程

所有写操作包在 `TransactionScope`（RAII 事务）内，保证"主表 + 点 + 属性 + 扩展表"原子性。

### 5.1 创建（Create）

```
begin transaction
  1. 若无 drawing，插入 drawings 并返回 id
  2. 解析 layer：按 (drawing_id, name) 取得/插入 layer_id
  3. 计算 bbox（由 pts + radius 求极小/大包围盒）
  4. INSERT elements（含 payload_json = elementToJson(e).toJson()）
     返回 element_id
  5. 批量 INSERT element_points（seq,x,y,z）
  6. INSERT element_attrs（各标量/向量）
  7. 如有窄表数据（table_cells/fcf_datums/block_attr_values/hatch_holes/element_refs）→ 批量插入
  8. updated_at = now()
commit
→ 返回 element_id
```

> 批量导入（DXF/DWG 海量图元）：**单事务 + `QSqlQuery::execBatch()` 批量绑定**，`prepare` 一次后 `addBindValue` 多行，避免逐条提交；必要时每 N 千行 `commit`+`begin` 分段，控制事务大小。

### 5.2 查询（Read / Query）

- **按 id**：`SELECT ... FROM elements WHERE id=?`，再 `SELECT` 关联 points/attrs/窄表，由 `ElementSerializer::fromRow` 重建 `Element`。

- **按图层**：`WHERE layer_id=?`（或 JOIN layers 按 name），按 `zorder` 排序。

- **按类型**：`WHERE type=?`；多类型用 `type IN (?,?,?)`。

- **按包围盒（空间）**：
  
  ```sql
  SELECT id FROM elements
  WHERE bbox_max_x >= :qx0 AND bbox_min_x <= :qx1
    AND bbox_max_y >= :qy0 AND bbox_min_y <= :qy1
    AND drawing_id = :did;
  ```

- **按名称/编组**：`WHERE name LIKE ?`、`WHERE group_name=?`。

- **整图加载**：`DrawingRepository::load(drawing_id)` → 一次性取出 elements + points + attrs + 窄表，重建 `SketchModel`。建议 `JOIN` + 应用层按 `element_id` 聚合，避免 N+1。

- **全文/域**：`drawing_props` 按 `key` 查；MText/Table 内容中的 `%<域>%` 由 `FieldEngine` 在内存求值，DB 只存源文本。

### 5.3 更新（Update）

```
begin
  1. 取旧 payload 比对（是否需要重算 bbox）
  2. UPDATE elements（公共列 + payload_json 重新序列化）
  3. 若几何变：DELETE element_points WHERE element_id=? 后重新 INSERT；重算 bbox 并 UPDATE
  4. 若属性变：先 DELETE element_attrs WHERE element_id=? 再重插（或按 attr_key UPSERT）
  5. 窄表同理重建
  6. updated_at = now()
  7. 若本图元是 FIELD 域宿主（MText/Table 含 %<…>%）或被引用的变量改值 → 触发 FieldEngine 重算依赖项
commit
```

> "全字段相等比较"已存在于 `Element::operator==`（O(字段数) 成员比较），更新前用它快速判断是否需要落库，省去无变化写回。

### 5.4 删除（Delete）

```
begin
  1. 若 element 是块定义（blocks 中存在，且本 element 为 owner 的某个成员）→ 先处理引用
  2. DELETE FROM elements WHERE id=?  → 外键级联删除 points/attrs/窄表
  3. 若是 BlockRef 且被其它图元引用 → 应用层决定替换/置空
  4. 若是约束/标注且被 element_refs 引用 → 清理引用行
commit
```

> SQLite 需 `PRAGMA foreign_keys=ON` 才能级联；`IDbAdapter::open()` 内统一开启。

### 5.5 批量导入（DXF/DWG → DB）

复用现有 `CadFormats` 导入路径，把"生成 `Element` 列表"与"落库"解耦：

```
CadFormats::fromDxf() ──► QVector<Element>
                         │
                         ▼
ElementRepository::bulkInsert(vec, drawingId)  // 单事务 + execBatch
```

导入即建 `drawing` + `layers`（按图元出现的图层自动建）+ `blocks`（按 INSERT）+ `elements` 全量。导出反向：`payload_json` 或规范化列 → `Element` → `elementToJson` → DXF/DWG 写出，与现有序列化完全同源。

## 7. 性能与一致性考量

- **索引**：`drawing_id`/`layer_id`/`type`/`owner_block_id`/`bbox_*`/`group_name` 必建；超大图可加 `(drawing_id, zorder)` 复合索引支撑整图按序渲染。
- **包围盒检索**：`bbox_*` 四列 B-tree 组合索引即可满足工程图（万~十万级图元）的框选/缩放裁剪；MySQL 可叠加 `SPATIAL`。
- **批量写入**：`execBatch` + 分段事务，导入万级图元亚秒级。
- **WAL（SQLite）**：`PRAGMA journal_mode=WAL` 让读写并发，避免 UI 卡顿。
- **写冲突**：短事务 + 必要时乐观重试；MySQL 用行锁。
- **一致性**：`payload_json` 与规范化列由 `ElementSerializer` 同一次写入保证一致；读取优先规范列（快），完整对象回退 JSON（全）；迁移时以 JSON 为权威源补列。
- **软删除可选**：`elements` 加 `deleted_at` 列做时间旅行/审计，查询统一 `WHERE deleted_at IS NULL`。

## 8. 落地建议（与现有代码衔接）

1. **先接 `payload_json` 单列表跑通**：最小改动即可让任意 `Element` 无损入库/出库，验证管线；再逐步补全规范化列与索引。
2. **复用 `elementToJson` / `elementFromJson`**：不重写字段映射，DB 仅是另一个"序列化目标"，与 DXF/DWG/`.sketch` 同源，降低漂移风险。
3. **在 `SketchModel` 增加变更回调**：以 `SketchModelBridge` 为唯一落库点，支撑自动保存与"崩溃不丢稿"。
4. **补齐 `layers`/`blocks`/`drawing_props`**：它们是样式/块/域语义的真正单一数据源，应优先建模。
5. **`SchemaMigrator` 随 `ElementType` 扩展**：枚举"只增不改"，新增类型即新增一列/窄表，旧库 `ALTER` 兼容。
6. **测试**：用现有 `SketchSelfTest` 同类思路，新增"序列化往返"用例——`Element → DB → Element` 与 `Element → JSON → Element` 结果应逐字段相等。

---

*本方案直接复用 SketchCAD 既有 `Element` 统一数据模型与 `elementToJson/elementFromJson` 序列化对，确保关系库存储与 DXF/DWG/`.sketch` 导出完全同源、零信息丢失。*
